# MSDS 톨루엔 세트 — 환각 탐지 성능 측정 결과

측정: 2026-09-08 · `evaluate.py` · 52문항 (환각 30 / 정답 22)
대상 모델: `한국어환각탐지기/model` (RobertaForTokenClassification, 110M)

## 핵심 수치

`context` 는 jsonl 에 들어 있는 항목별 조각을 그대로 사용 (README 7절의 채점 조건).

| 단위 | AUROC | macro F1 @0.35 | macro F1 (최적) |
|---|---:|---:|---:|
| **문항** (이 답변에 환각이 있는가) | **0.814** | 0.649 | 0.805 (thr 0.01) |
| **토큰** (어느 구간이 환각인가) | **0.793** | 0.610 | 0.706 (thr 0.00) |

- 문항 점수는 답변 토큰 확률의 **최댓값**을 썼다.
- 토큰 라벨은 `hall_spans` 를 문자 구간으로 펼쳐 토큰에 매핑했다.

## 임계값 0.35 는 이 도메인에 맞지 않는다

| | 환각 문항 | 정답 문항 |
|---|---:|---:|
| 점수 중앙값 | 0.190 | 0.002 |

**분리는 되는데 절대값이 낮다.** AUROC 0.814 는 순위를 잘 매긴다는 뜻이고,
0.35 라는 자리에서 자르면 대부분을 놓친다는 뜻이 F1 0.649 다.
임계값만 0.01 로 낮춰도 macro F1 이 **0.649 → 0.805** 로 오른다.

이유는 README 6절이 예고한 그대로다. 학습 데이터(RAGTruth 번역본)는
뉴스 요약·QA 도메인의 기계번역 한국어이고, MSDS 는 원어민 격식체 기술 문서다.
모델이 전반적으로 확신을 덜 갖는다.

## 환각 유형별 (@0.35)

| 유형 | 건수 | 탐지율 |
|---|---:|---:|
| 과일반화 | 4 | 75.0% |
| 지어내기 | 13 | 46.2% |
| 숫자변조 | 10 | 40.0% |
| 의무예외 | 3 | 33.3% |
| **정답 (오탐률)** | 22 | **9.1%** |

**README 예측과 어긋난 지점이 있다.** README 6절은 *"숫자변조는 번역을 거쳐도
숫자가 살아남으므로 잘 잡히고, 과일반화·의무예외는 많이 놓칠 것"* 으로 봤는데,
실제로는 **과일반화가 가장 잘 잡히고 숫자변조가 낮다.** 발표에서 다룰 만한 지점이다.

다만 과일반화 4건, 의무예외 3건은 표본이 너무 적어 비율의 신뢰구간이 넓다.
1건 차이로 25%p 가 움직이므로 단정하면 안 된다.

## 챗봇 경로(select_context)를 거치면

챗봇(`api.py`)은 긴 PDF 를 감당하려고 질문과 겹치는 구간만 추려 넣는다.
이 세트의 `context` 는 이미 항목별로 짧게 잘려 있어(77~1,258자) 추리기가 크게 필요 없다.

| 단위 | 원본 context | 추린 context |
|---|---:|---:|
| 문항 AUROC | 0.814 | 0.789 |
| 토큰 AUROC | 0.793 | 0.811 |

**차이가 크지 않다.** 이미 짧은 조각에는 추리기가 득도 실도 별로 없다는 뜻이다.
추리기가 필요한 건 이 세트가 아니라 **수천 토큰짜리 PDF 원문**을 넣을 때다
(그 경우 추리기 없이는 탐지율이 0 이 된다).

## 측정 방식에 대한 단서

- **문항 단위 점수로 최댓값을 쓴 것**은 선택이다. 평균이나 상위 k개 평균을 쓰면
  숫자가 달라진다. "한 군데라도 의심되면 그 답변은 의심스럽다"는 관점을 택했다.
- **README 7절의 채점법(스팬 겹침 기준)과는 다른 지표다.** 겹침 기준은
  AUROC 를 낼 수 없어(연속 점수가 없다) 여기서는 토큰 단위로 대체했다.
  두 방식의 숫자를 직접 비교하면 안 된다.
- 표본 52건은 작다. AUROC 0.814 의 신뢰구간은 대략 ±0.06 수준으로 봐야 한다.
