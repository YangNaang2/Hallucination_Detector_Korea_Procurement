#
# 형식:  유형 | 질문
# 빈 줄과 # 로 시작하는 줄은 무시됩니다.
#
# ────────────────────────────────────────────────────────────────
# 유형 다섯 가지. 목적이 서로 다르니 골고루 섞어야 합니다.
#
#   있음   문서에 답이 그대로 있다.
#          → 형광펜이 거의 안 칠해져야 정상. **오탐을 잡는 대조군**이라
#            반드시 6~10개는 넣습니다. 이게 없으면 "다 빨갛게 칠하는
#            모델"과 구별이 안 됩니다.
#
#   수치   구체적인 숫자를 묻는다. 인화점·끓는점·노출기준·pH·비중 등.
#          → 문서에 없는 값이면 모델이 지어내기 가장 쉬운 자리입니다.
#
#   인접   문서가 다루는 항목 "옆"을 묻는다.
#          → 예: 눈 접촉 응급조치만 적힌 문서에 피부 접촉을 묻는다.
#            비슷한 항목이 있어서 모델이 끌려갑니다.
#
#   교차   A 제품 문서만 있는데 B 제품을 묻는다.  ★ MSDS 에서 가장 강력
#          → 제품 문서 여러 개가 서로 비슷해서, 검색이 엉뚱한 제품을
#            가져오거나 모델이 두 제품을 섞습니다. 실제 현장에서
#            가장 위험한 실패 유형이기도 합니다.
#
#   결합   두 항목을 합치거나 계산해야 답이 나온다.
#          → 예: "이 작업 조건에서 노출기준을 넘나요?"
#            문서 조각은 있지만 결론은 없는 자리.
#
# ────────────────────────────────────────────────────────────────
# 쓰는 요령
#   · 제품 이름을 문서에 적힌 그대로 씁니다. 검색이 그 이름으로 걸립니다.
#   · 한 질문에 하나만 묻습니다. 두 개를 물으면 라벨링이 어려워집니다.
#   · 답이 두세 문장 나올 만한 질문이 좋습니다. 한 단어로 끝나면
#     라벨링할 문장이 없습니다.
#   · 40~60개를 목표로 합니다. 문항당 답변 2~4문장이면 100~200문장이
#     나오고, 손라벨링 표본으로 충분합니다.
#
# ★ 실제 안전 판단에 쓰지 마세요. 이 세트는 모델 평가용입니다.
# ────────────────────────────────────────────────────────────────
