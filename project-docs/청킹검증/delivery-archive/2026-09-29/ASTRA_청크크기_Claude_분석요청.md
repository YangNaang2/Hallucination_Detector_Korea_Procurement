# Claude 분석 요청

이 패키지는 ASTRA RAG의 Parent–Embedding Window 청크 크기 비교 실험이다.

다음 순서로 읽어라.

1. `PREREGISTRATION.md`: 결과 확인 전에 고정한 비교군과 지표
2. `README.md`: 수행자가 작성한 해석
3. `summary.csv`: 설정별 집계
4. `validation.json`: 분모·누락·paired 비교·신뢰구간
5. `results.json`: 292문항의 설정별 원시 검색 결과
6. `chunk_ablation.py`: 실험 구현

다음을 독립적으로 검토해라.

- Parent 1,800자를 유지한다는 결론이 수치로 타당한가?
- Window 384토큰을 균형 후보로 선택한 근거가 타당한가?
- 재현율 우선이면 256토큰을 선택해야 하는가?
- Hit@1·Hit@3·Hit@6·MRR·근거 문자 coverage·문맥량·Window 수 사이의 trade-off를 설명해라.
- 현재 460토큰 대비 개선 폭이 표본 변동보다 충분히 큰가?
- 3문항 제외가 결과를 유리하게 만들 가능성이 있는가?
- 평가 코드의 gold hit, offset overlap, RRF, dense window 집계에 구현 오류나 편향이 있는가?
- `test` split도 과거 개발에 노출됐다는 제한을 반영해 발표 가능한 주장과 금지할 주장을 구분해라.
- 이번 결과가 검색 성능이며 답변 정확도·RAG 성능·환각 탐지 성능이 아니라는 점을 유지해라.

최종 답변은 다음 형식으로 작성해라.

1. 한 문단 결론
2. 수치 재계산 결과
3. 설계·평가 코드상 문제점
4. 현재 설정 유지 / 384 채택 / 256 채택 중 추천
5. 발표에서 사용할 수 있는 문장
6. 추가로 필요한 최소 후속 실험

수치를 새로 만들거나 누락된 정보를 추정하지 마라. 원시 자료와 README가 충돌하면 원시 자료를 우선하고 충돌을 명시해라.
