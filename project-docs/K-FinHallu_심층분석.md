# K-FinHallu 심층분석

> arXiv 2605.29523 (2026.05.28) · Eunbyeol Cho, Yunseung Lee, Mirae Kim, Jeewon Yang, Youngjun Kwak, Edward Choi
> KAIST AI and Financial Tech Lab · 카카오뱅크
> 팀 공유용. `K-FinHallu_비교.md`(세션 27, "우리와 무엇이 다른가")의 심화판 — 여기서는 논문 자체를 뜯어본다.

---

## 0. 결론 요약

K-FinHallu는 **한국 금융 다중턴 RAG 대화에서 환각을 턴 단위로 탐지·분류하는 첫 벤치마크**다. 환각을 5가지 유형으로 체계화하고, LLM으로 환각을 주입한 뒤 사람이 검수해 808건(테스트)·2,624건(학습)을 만들었다. 실험 결과 **모든 프론트ier 모델이 "정당한 답변 거부(True Refusal)"를 가장 못한다**는 것과, **8B 모델도 근거 있는 사고 과정(rationale)을 학습시키면 GPT-5를 넘어선다**는 것을 보였다. 우리 프로젝트와는 라벨 단위(턴 vs 구간)와 방법(생성형 LLM vs 인코더)이 근본적으로 다르며, 이 문서는 그 논문을 표면적 비교를 넘어 방법론 세부까지 뜯어본 것이다.

---

## 1. 문제의식 — 왜 이 벤치마크를 만들었나

기존 환각 벤치마크(HaluEval, RAGTruth, DiaHalu, FaithDial 등)는 영어·단일턴·일반 도메인 중심이다. 한국 금융은 세 가지가 다르다.

1. **한국 고유 제도** — 전세(Jeonse) 같은 국내 금융 제도는 해외 벤치마크에 없다.
2. **교착어 형태론과 한자어 다의성** — "저당권"과 "전세권"처럼 한 글자 차이로 의미가 갈리는 한자어 금융 용어가 많다.
3. **다중턴** — 실제 상담은 한 번의 질문·답변이 아니라 여러 턴에 걸친 대화다. 이전 턴과의 모순(Inconsistency)은 단일턴 벤치마크로는 애초에 측정할 수 없다.

## 2. 환각 taxonomy — 5범주 9유형

**"답변 가능한 상황"과 "답변 불가능한 상황"을 먼저 나누고**, 그 위에 환각 유형을 얹은 것이 이 taxonomy의 핵심 설계다.

### 답변 가능한 상황 (문서에 근거가 있음)

| 대분류 | 소분류 | 정의 |
|---|---|---|
| **Contradictory**(모순) | Financial Term Misunderstanding | 비슷하지만 다른 금융 용어로 치환 (예: "신용대출" ↔ "담보대출") |
| | Modifier Change | "~에 한해", "최소", "이내" 같은 한정어를 뒤집음 |
| | Number Error | 금리·기한·한도 등 숫자를 그럴듯한 값으로 왜곡 |
| | Inconsistency | 이전 턴의 발언과 모순되는 응답 생성 |
| **Unverifiable**(근거 없음) | Fabricated Detail | 존재하지 않는 절차·예외를 "5단어 이내로" 짧게 삽입 |
| | Subjective Opinion | 근거 없는 주관적 평가를 사실처럼 끼워 넣음 |
| **Irrelevance**(동문서답) | Condition Not Satisfied | 질문의 조건(연령·기간·자격)을 무시 |
| | Off-topic Drift | 같은 주제의 다른 측면으로 대답이 샘 |
| | Question Misunderstanding | 조사·의문사를 잘못 해석 |
| **False Refusal**(부당 거부) | — | 근거가 충분한데도 답변을 거부 |

### 답변 불가능한 상황 (문서에 근거가 없음)

| 대분류 | 정의 |
|---|---|
| **False Acceptance**(부당 수락) | 근거 문서에 정보가 없는데도 답을 만들어냄 |
| True Refusal (정답 행동) | 근거가 없음을 올바르게 인정하고 거부 — **이것은 환각이 아니라 정답**이다 |

**설계의 정교함** — 대부분의 환각 연구는 "거부하면 안전하다"고 단순화하지만, 이 taxonomy는 **거부에도 옳은 거부(True Refusal)와 틀린 거부(False Refusal)가 있다**는 것을 명시적으로 구분한다. 이게 논문의 가장 중요한 실험 결과(4절)로 이어진다.

## 3. 데이터 구축 — 환각을 어떻게 주입했나

### 원본 자료
AI-Hub의 "한국 금융·법률 문서 기계독해" 데이터셋에서 금융 카테고리만 추렸다. **테스트셋과 학습셋의 출처 기관을 아예 분리**했다 — 테스트는 금융감독원(약 72%)·한국소비자원(약 28%), 학습은 한국은행·금융위원회·한국금융연구원·고용노동부. **문서 자체가 겹치지 않게 만들어 데이터 누수를 원천 차단**한 것이다.

- 테스트 원본: 문서 272개, 질의 2,064개
- 학습 원본: 문서 2,732개, 질의 42,364개

### 주입 파이프라인
1. **턴 위치 선정** — LLM이 각 환각 유형에 어울리는 턴을 고른다 (예: Contradictory는 숫자가 많은 턴을 노린다)
2. **주입 모델** — 테스트셋은 **GPT-4o와 Gemini-2.5-Flash 둘 다** 사용해 같은 정상 대화에 환각을 넣어 소스 다양성을 확보. 학습셋은 GPT-4o만 사용
3. **주입 방식** — Contradictory/Unverifiable/Irrelevance는 근거(rationale) 템플릿과 함께 생성 프롬프팅. False Refusal은 응답을 고정 거부 문구로 치환(근거 문서는 그대로 둠). False Acceptance는 근거 문서를 어려운 오답 후보로 치환(원래 응답은 그대로 둠)
4. **품질 관리** — 학습셋은 LLM 심판이 "유형이 맞는가"·"자연스러운가"를 1~3점으로 채점해 2점 미만은 폐기 (**85.2%만 채택**). **테스트셋은 자동 필터링 없이 사람이 전수 검수**했다
5. **제약** — **대화 하나당 환각을 정확히 1개만** 넣는다. 턴 단위로 정확히 진단하기 위한 설계다

### 사람 검수 인력
**대학원생 2명(NLP 전공) + 금융 도메인 전문가 2명**, 3인 교차 평가에 Gwet's AC1 합의도 지표를 썼다.

> **우리 프로젝트와의 접점** — 세션 24에서 우리가 학사요람을 고른 이유가 "팀에 도메인 전문가가 없어서"였다. K-FinHallu는 정확히 그 자리에 **금융 전문가 2명을 실제로 투입**했다. 우리가 왜 도메인을 신중하게 골랐는지를 이 논문이 거꾸로 증명해준다.

### 최종 규모
**테스트 808건**(정상 404 + 환각 404), **학습 2,624건**(환각 1,312건을 정상과 짝지음).

## 4. 실험 결과 — 실제 수치

### (1) 이진 분류 — "이 응답, 환각인가 아닌가"

| 모델 | 정확도 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|
| Gemini-2.5-Flash | 0.864 | 0.883 | 0.839 | **0.860** |
| Gemini-2.5-Pro | 0.859 | 0.912 | 0.795 | 0.849 |
| GPT-5 | 0.833 | 0.877 | 0.775 | 0.823 |
| Llama-3.3-70B | 0.722 | 0.672 | 0.864 | 0.756 |
| Qwen3-32B | 0.775 | 0.905 | 0.614 | 0.732 |
| GPT-4o | 0.715 | 0.691 | 0.780 | 0.733 |

**최고 성능이 Gemini-2.5-Flash(F1 0.860)라는 점이 눈에 띈다** — 가장 크거나 가장 비싼 모델이 아니다.

### (2) 4분류 (정상/환각/거부) — 클래스별 정확도

| 모델 | 정상 | 환각 | 거부 | 전체 |
|---|---|---|---|---|
| **Qwen3-8B SFT-R(파인튜닝)** | 0.972 | 0.864 | 0.750 | **0.896** |
| GPT-5 | 0.969 | 0.810 | 0.625 | 0.855 |
| Gemini-2.5-Flash | 0.946 | 0.795 | 0.673 | 0.845 |
| Qwen3-32B | 0.969 | 0.551 | 0.625 | 0.743 |

**8B 파인튜닝 모델이 GPT-5를 이겼다.** 크기가 4~30배 차이 나는데도 그렇다. 비결은 5절.

### (3) 정답 거부의 세분화 — 진짜 거부 vs 부당 거부

| 모델 | 정상 | 환각 | **부당 거부** | **정당 거부** |
|---|---|---|---|---|
| Qwen3-8B SFT-R | 0.972 | 0.864 | 0.654 | 0.846 |

**모든 모델을 통틀어 가장 못하는 축이 여기다.** 정당 거부(True Refusal)조차 최고 성능이 0.85 안팎이고, 부당 거부(False Refusal) 구분은 이보다 더 낮다. 논문은 이를 **"모든 모델에서 가장 약한 축"**이라고 명시한다.

### (4) 5범주 세분류 — macro-F1

| 모델 | macro-F1 |
|---|---|
| Gemini-2.5-Pro | 0.725 |
| GPT-5 | 0.717 |
| Qwen3-32B | 0.492 |

턴이 "환각인지 아닌지"는 어느 정도 잡아도, **"어떤 유형의 환각인지"까지 맞히는 건 프론티어 모델도 크게 떨어진다.**

## 5. 8B가 GPT-5를 이긴 비결 — Rationale Supervision

이 논문에서 기술적으로 가장 흥미로운 부분이다.

**방법** — Qwen3의 네이티브 `<think>` 블록 안에 **2단계 추론을 명시적으로 학습**시켰다.
1. 먼저 "이 질문에 답할 단서가 문서에 있는가"(답변 가능성)를 판단
2. 그다음 "응답이 그 단서에 충실한가"(사실 충실성)를 판단

즉 "환각이냐 아니냐"를 한 번에 묻지 않고, **판단을 두 단계로 쪼개 각 단계의 근거를 언어화하도록 강제**했다.

**학습 설정**
- 데이터 : 학습 2,624건을 9:1로 분할
- LoRA rank 8 · alpha 32 · dropout 0.05
- 학습률 1e-4, 코사인 스케줄, 3 epoch
- 유효 배치 32 (GPU 8장 × per-device 2 × 누적 2)
- A6000(48GB) 8장으로 **약 4시간**

**결과** — 0.896(전체 정확도)로 GPT-5의 0.855를 넘었다. **작은 모델이라도 "생각의 절차"를 명시적으로 가르치면 훨씬 큰 프롬프팅 모델을 이길 수 있다**는 것을 보여준 사례다.

> **우리 프로젝트에 주는 시사점** — 우리는 인코더(토큰 분류)라 `<think>` 같은 생성형 추론을 쓸 수 없다. 다만 **"작은 모델 + 좋은 학습 신호가 큰 프롬프팅 모델을 이긴다"는 명제 자체는 우리 프로젝트의 전제(TinyLettuce 사례)와 정확히 같은 방향**이다. D 파트가 베이스라인을 짤 때, "거대 LLM 프롬프팅"과 "소형 모델 + 양질의 학습 신호" 두 축으로 비교하는 것이 이 논문과 같은 구도가 된다.

## 6. 저자가 스스로 밝힌 한계

- 파생상품·투자은행 같은 **전문 세부 영역은 대표성이 부족**할 수 있다
- **대화 하나에 환각을 정확히 1개만** 넣는 설계라, 실제 대화에서 여러 환각이 겹치는 상황은 다루지 못한다
- 대화 자체가 **LLM이 시뮬레이션한 것**이라 생성 모델 특유의 흔적이 데이터에 섞였을 수 있다 (다만 5가지 환각 유형 모두 실제 프론티어 모델 출력에서도 자연히 관찰되었다고 밝힘)
- **한국 금융 규제 언어에 특화**되어 있어 다른 국가·언어로의 전이는 검증되지 않았다
- **다국어 전이 가능성과 복수 환각 동시 발생 시나리오**를 향후 과제로 남김

## 7. 우리 프로젝트와 다시 연결하기

`K-FinHallu_비교.md`(세션 27)에서 이미 정리한 차이(턴 단위 vs 구간 단위, 8B LLM vs 소형 인코더)는 이 심층분석으로 더 명확해진다.

| 이 논문이 잘하는 것 | 우리가 하려는 것 |
|---|---|
| **거부 행동의 정오**(정당 거부 vs 부당 거부)까지 구분 — 우리 taxonomy엔 없는 축 | 구간 단위 위치 지목 — 이 논문엔 없는 축 |
| 도메인 전문가 2명을 투입한 전수 검수 | 팀이 스스로 검증 가능한 도메인(학사요람) 선택 |
| LLM 프롬프팅 + 소형 파인튜닝 비교 구도 | 소형 인코더 3종 비교 + 번역 전이 격차 측정 |

**가져다 쓸 수 있는 것**
1. **베이스라인 성능표** — D 파트가 "거대 LLM은 이 정도 한다"는 기준선을 인용할 때 이 표를 그대로 쓸 수 있다
2. **"정당 거부" 개념** — 우리 모델의 3분류(지지/반박/정보부족)에서 "정보부족"이 이 논문의 True Refusal과 대응한다. 이 논문이 "모든 모델이 여기서 가장 약하다"고 밝힌 것은, 우리도 이 축에서 성능이 낮게 나올 가능성을 미리 각오해야 한다는 뜻이다
3. **데이터 누수 방지 방법** — 학습·평가 문서의 발행 기관을 아예 분리한 방식은, 우리 평가③(학사요람) 제작 시에도 "학습에 쓴 학사요람과 평가에 쓴 학사요람을 다른 학교/연도로 분리"하는 식으로 응용할 수 있다
