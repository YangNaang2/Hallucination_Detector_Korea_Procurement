# 프로젝트 진행 현황 공유 (2026-09-11)

> 이 문서는 팀원 각자가 쓰는 AI 에이전트(Claude, ChatGPT, Codex, Gemini 등)에게 프로젝트 맥락을 한 번에 알려주기 위해 작성했다.
> 에이전트에게 이 파일을 통째로 읽히고 "이 프로젝트 상황을 이해했으면 그 전제로 도와줘"라고 하면 된다.
> 아래 내용은 2026-09-11 저녁 기준이며(데이터 작업 반영), 이후 결정은 이 문서를 갱신해서 반영한다.

## 1. 프로젝트 한 줄 정의

**입찰 참여 기업의 직원이 나라장터 공개 공고와 자기 회사 내부 자료를 함께 검토할 때, AI 답변의 근거와 환각(문서에 없는 말) 의심 구간을 표시해 주는 서비스.**

- 팀: B1조 6인
- 최종 발표: **2026년 10월 2일**
- 주 사용자: 입찰·제안·사업 담당자 (발주기관이 아님)
- 설명용 가상 기업: **한빛IT** (실제 회사 아님)

## 2. 전체 계획 (큰 그림)

프로젝트는 두 단계로 진행되어 왔다.

### 1단계 (완료): 한국어 환각 탐지 모델 만들기

한국어에는 "답변의 어느 구절이 문서에 근거 없는지"를 표시한 공개 학습 자료가 없다.
그래서 영어 RAGTruth 데이터의 환각 구간에 태그를 붙여 한국어로 번역하고, 그걸로 토큰 분류 모델을 학습시켰다.

판정 기준은 **"이 말이 사실인가"가 아니라 "이 문서에 있는가"** 다. 사실이어도 문서에 없으면 환각으로 표시한다.

### 2단계 (진행 중): 나라장터 입찰 지원 서비스에 적용하기

1단계 모델을 실제 쓸 곳으로 **나라장터 입찰 공고 검토**를 정했다. 이전에는 MSDS(화학물질 안전자료)를 적용 도메인으로 썼는데, 지금 메인 서사는 나라장터로 바뀌었다.

서비스 동작 흐름:

```
사용자 질문
  → 사용자 권한에 맞는 문서만 검색 (원본 BGE-M3 임베딩)
  → LLM(Gemma 등)이 답변 생성
  → 우리가 학습시킨 탐지 모델이 답변 토큰별 환각 의심 구간 표시
  → 사용자가 원문과 대조
```

## 3. 핵심 개념: 문서 보안 등급 L1 / L2 / L3

| 등급 | 의미 | 예시 |
|---|---|---|
| L1 | 공개 공고 자료 | 입찰공고, 제안요청서(RFP), 과업지시서, 규격서, 정정공고 |
| L2 | 입찰 기업 내부 자료 | 과거 실적, 보유 인증, 투입 가능 인력의 경력·자격, 장비 |
| L3 | 입찰 기업 민감 자료 | 원가, 내부 단가, 협력사 견적, 투찰 예정가, 수주 전략 |

- 한빛IT 직원은 한빛IT 자료만 본다. 다른 기업 직원은 자기 기업 자료만 본다. 공개 공고(L1)는 모두가 본다.
- 보안은 **회사 경계(tenant) + 사용자별 문서 권한**을 함께 확인한다. 단순 등급 숫자 비교로 다른 회사 자료가 열리면 안 된다.
- **주의:** 예전 3D 가상세계 UI에 공간 단계 이름으로 L1/L2/L3가 섞여 있다. 그것은 보안 등급과 무관하다. 앞으로 공간 쪽 이름은 바꿀 예정이다.
- L2/L3 자료는 당분간 **합성(가상) 기업 자료**다. 실제 기업 내부 정보처럼 표시하지 않는다.
- 최종 구조는 **가상 기업 3~5곳이 여러 공고를 검토**하는 형태다. 공고마다 기업을 새로 만들지 않는다.

## 4. 지금까지 한 것

### 4-1. 환각 탐지 모델 (1단계, 완료)

- 영어 RAGTruth 환각 구간에 `<HAL>` 태그를 붙여 Gemma-3-12b-it로 번역, 태그 위치에서 한국어 글자 위치를 다시 계산.
- 자동 검사 통과 17,537건 (학습 14,863 / 평가 2,674).
- 인코더 3종 학습 결과 (기록상 수치):

| 인코더 | 문맥 길이 | macro F1 | AUROC |
|---|---|---|---|
| klue/roberta-base | 512 | 0.6980 | 0.837 |
| xlm-roberta-base | 512 | 0.6527 | 0.847 |
| **BAAI/bge-m3** | 8192 | **0.7385** | **0.8834** |

- 확인된 한계: **숫자 변조를 잘 못 잡는다.** 문서에 "6개월 / 12개월"이 둘 다 있을 때 답변이 둘을 바꿔 써도 놓친다. 모델 크기와 무관하게 같은 비율로 실패하므로 학습 자료의 한계로 본다.
- MSDS 평가 세트(톨루엔, 52문항)와 소형 생성 모델 6종 답변 312개 라벨링은 팀원이 만든 평가 자산이다.

### 4-2. 나라장터 데이터 처리 파이프라인 (2단계, 코드 작성 완료 · 실데이터 미적용)

위치: `procurement-pipeline/` (Python 3.10+, 외부 패키지 없음)

| 파일 | 역할 |
|---|---|
| prepare.py | 수집 목록(manifest) 검사, SQLite 집계, 분야 추천, 대표 공고 선정, 근거 청킹 |
| generate.py | LLM 요청 파일 생성. `--execute`를 붙여야만 실제 전송 |
| security_schema.py | 가상 기업 L2/L3 자료 합성 프롬프트와 검증 |
| test_pipeline.py | 로컬 테스트 3개 (2026-09-11 통과 확인) |

- 입력은 공고 ID+버전별 manifest. PDF/HWP 파싱과 OCR은 이 코드 범위 밖이다. 파서 결과(page/section/text JSONL)가 먼저 있어야 한다.
- 실제 LLM 호출은 **아직 한 번도 하지 않았다.**

### 4-3. ASTRA 데모 UI (목업 완성 · 실연결 안 됨)

위치: `demo-ui/spatial-poc/` (`실행.bat` 또는 `python run_demo.py`, 포트 8765)

- Reality 모드: MapLibre + 무료 지도. 8개 지역 공고는 가상. Mapbox 키 불필요.
- Virtual 모드: Three.js 3D, 가상 문서 PDF와 그래프.
- 로그인, 관리자, 역할 필터, Q&A는 **전부 시연용 목업**이다. 실제 보안이나 LLM 성능이 아니다.
- `live-design/` 폴더에 실제 RAG 서버 연결 설계(REST + 스트리밍, FastAPI/pgvector 제안)가 있지만 서버와 UI에 붙지 않았다.

### 4-4. 실제 나라장터 데이터 (2026-09-11 갱신)

- 4·5·6월 공고 137,745건(최신 차수 124,522건) 수집·파싱·변환 완료. 세 담당자 워크스테이션에 SHA-256 해시 구조로 저장.
- 4·6월은 첫 실행 때 파서 미설치로 파싱 실패 4~6만 건이 캐시에 남아 있었고, 기존 원본으로 재파싱해 92~95% 복구했다.
- 수집 범위는 조달청 나라장터 API 제공 범위(공기업 자체조달·민간·긴급공고 제외). 용역 누락 8% 수준으로 허용.
- 어댑터(`procurement-pipeline/adapt_g2b.py`)가 수집기 출력을 파이프라인 입력으로 바꾸고, 첨부 285,252개 중 246,797개(87%)가 사용 가능.
- 완전 공고(공고문 + 제안요청서/과업지시서): 용역 28,852건(57%), 물품 14,145건(43%), 공사 8,082건(21%). 메인 업무구분은 용역.
- 용역 세부 후보: 학술연구서비스 6,129 / 행사 기획 및 대행 2,352 / SW 및 시스템 개발 984 + 운영 및 유지관리 681. 비교표는 `project-docs/데이터현황/3개월_통합현황.md`.

## 6. 앞으로 할 일 (순서대로)

1. ~~실제 데이터 샘플 확보~~ 완료.
2. ~~변환 어댑터 작성~~ 완료.
3. **메인 분야 결정.** 세 달 통합 표를 보고 용역 세부 분야를 정한다. 정해지면 세 담당자가 `prepare.py --sector`로 최종 표본 30~50건을 뽑고, 그 공고의 원본·텍스트만 메인 워크스테이션으로 모은다.
4. **합성 스키마 재설계.** 가상 기업 마스터(company_id, 자료 버전) + 회사 공통 자료(실적·인력·인증·단가) + 공고별 자료(인력 배치안·원가표·투찰 전략) 구조로 바꾼다.
5. **소규모 시나리오 실행.** 공고 1건 + 가상 기업 1곳 + 질문 5개부터 시작해 사람이 검수하고, 그다음 표본을 늘린다. 필요하면 100건 파일럿으로 토큰·시간·품질을 먼저 측정한다.
6. **UI 실연결.** 목업 부분과 실제 연결 부분을 구분해서 구현한다. 공사·물품 등 미구현 기능은 "준비 중"으로 표시한다.
7. **발표 자료 재검토.** 과거 가정이나 미검증 주장이 남아 있으면 현재 결정에 맞춰 고친다.

논의용 초기 규모(확정 아님): 검색용 공고 최대 1만 건, 상세 공고 30~50건, 가상 기업 3~5곳, 검수 질문 200~300개.

## 7. AI 에이전트가 지켜야 할 것

이 프로젝트에서 작업을 도울 때 다음을 지킨다.

- **검증되지 않은 것을 사실처럼 말하지 않는다.** "번역 손실 0 입증", "CPU 0.1초", "환각 100% 탐지" 같은 표현은 쓰지 않는다.
- **모델 성능 수치는 조건이 다르다.** 위 F1 수치는 실험 설정·임계값·슬라이딩 윈도우가 달라 같은 조건 비교가 아니다. 발표에 쓰려면 원본 실험 기록을 다시 확인한다.
- **탐지 모델은 세상의 모든 사실을 아는 모델이 아니다.** 입력 문서에 대한 지지 여부만 판단한다. 근거 조항을 자동으로 정확히 찾아준다고 보장하지 않는다.
- **실적·수치·기간 비교 같은 규칙 검증**과 **학습된 환각 탐지**는 다른 것이다. 섞어서 설명하지 않는다.
- **목업을 구현된 기능처럼 말하지 않는다.** 로그인, 권한, Q&A 화면은 시연용이다.
- **L2/L3는 보안 등급이지 3D 공간 단계가 아니다.**
- **가상 기업 자료는 합성이다.** L1 원문 인용은 합성 배경일 뿐, 가상 실적이나 가격이 진짜라는 근거가 아니다.
- **모르는 숫자는 추측하지 않는다.** 실제 공고 수, 첨부 현황은 데이터를 본 뒤에만 말한다.
- **원천 데이터, 모델 가중치, API 키는 GitHub나 공유 문서에 올리지 않는다.**
