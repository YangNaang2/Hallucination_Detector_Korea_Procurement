# 1차 회의 — 정할 것과 업무 분담

> 주제: **한국어 환각 탐지** (영어 RAGTruth를 구간 라벨째 한국어로 번역해 한국어판 탐지 모델을 만들고, "번역으로 만든 모델이 진짜 한국어 문서에서 통하는가"를 측정한다)
> 조: **B1조** · 인원: **6인** (양진우 포함) · 기간: **미정 — 1번 안건에서 확정** (문서 내 마일스톤은 5주 가정)

---

## 1. 회의에서 정할 것 (우선순위 순)

| # | 안건 | 결정 기준 / 선택지 | 정해지면 영향받는 것 |
|---|------|------------------|--------------------|
| 1 | **캠프 기간 확정 + 6인 파트 배분** | 인원은 6인 확정. 파트는 A~E 5개이므로 한 파트에 2명 → **D(평가)에 2명 권장**(평가② 손라벨링이 가장 인력에 묶임). 기간이 4주 이하면 마일스톤 압축 | 아래 분담표·마일스톤 |
| 2 | **주제 최종 합의** | 한 줄 정의: "7개 언어엔 있고 한국어엔 없는 RAG 환각 탐지기를, 영어 데이터를 번역해 만든다" | 발표 방향 |
| 3 | **검증 대상 문서 확정** | 학사요람(1순위) vs 법률(팀원 기획서 추천). 판단 기준 = **팀이 도메인 지식 없이 라벨의 정오를 검증할 수 있는가.** 법률·의료는 이 이유로 제외 권장 | A파트 문서 수집, D파트 라벨링 |
| 4 | **진짜 한국어 평가(평가②) 방식** | A안 학사요람 손라벨 수백 건 / B안 K-HALU·K-FinHallu 네이티브 평가셋 사용(라벨링 불필요, span 매칭은 아님) / C안 100~150건만 정밀 라벨 + 신뢰구간. **라벨링에 낼 수 있는 인력·시간에 따라 결정** | D파트 일정, 발표에 낼 "격차" 숫자 |
| 5 | **`verification_result.json` 계약 초안 합의** | 탐지 모델 출력 형식(토큰별 O/X, 환각 구간 start/end, 유형, 신뢰도, 근거 인용 구간). 1주차 내 확정이 팀 전체 필수 동기화 지점 | C↔D↔E 인터페이스 전부 |
| 6 | **컴퓨팅·데이터 자원 확인** | **확인됨: A5000 1장(24GB).** 학습은 충분하나 논문의 27B 번역 모델(bf16 약 54GB)은 안 들어감 → 12B로 낮추거나 양자화. **전체 번역은 2~4일 연속 가동 예상** → 클라우드 A100 1회 대여 또는 번역 API를 쓸지 결정 필요. RAGTruth 라이선스·다운로드도 확인 | B·C파트 착수 시점과 전체 일정 |
| 7 | **발표 도입부 프레이밍 채택 여부** | "환각은 오토리그레시브 생성의 구조적 한계 → 업계는 검색연동·RAG 사실성 평가·교차검증으로 대응 → 우리는 그중 RAG 사실성 평가를 작은 한국어 모델로 한다". 인용 논문 1건 확정(Xu et al. 2024 / OpenAI 2025 중) | E파트 발표자료·대본 |
| 8 | **논문 완독 배정 확정** | 아래 6절 표대로 5명 1인 1편. 특히 KCI 논문 결과(구간 단위 여부)가 "우리가 구간 단위 첫 시도" 주장의 안전성을 가른다 | 착수 전 공통 이해 |
| 9 | **주차별 마일스톤·다음 회의 일정** | 아래 4절 초안을 기준으로 조정 | 전체 |

## 2. 파트별 업무 분담

| 파트 | 담당 | 핵심 산출물 | 다른 파트와의 연결 |
|------|------|-----------|------------------|
| **A. 문서·RAG** | (미정) | ① 검증 대상 문서 수집·청킹 ② 학사요람 하나에 고정한 **데모용 소형 RAG 챗봇** ③ 평가②용 (문서+질문+챗봇답변) 쌍 생산 | 챗봇 답변을 D에 넘김 · 데모 화면을 E와 통합 |
| **B. 데이터(번역 파이프라인)** | (미정) | ① RAGTruth 확보·라이선스 확인 ② `<HAL>` 태그째 기계번역 파이프라인 ③ **gemma-3-27b-it 200건 배치로 태그 보존율 재측정** ④ 겹침 라벨(1.5%) 번역 전 병합 ⑤ 학습 15,090 / 검증 / 평가① 2,700 분할 | 번역·분할된 데이터를 C에 넘김 |
| **C. 검증 모델** | **양진우** | ① 한국어 인코더 3종 선정·비교(이진 토큰 분류) ② **8,192 토큰 긴 문맥 처리 전략**(klue/roberta는 짧은 컨텍스트) ③ 번역 테스트셋 성능 = **평가①** ④ `verification_result.json` 출력 스펙 정의·구현 | B에서 데이터 받음 · 출력 형식을 D·E와 계약 |
| **D. 평가** | (미정 — **2명**) | ① 지표 확정(토큰 F1 · span IoU · NEI 포함 3분류 정확도 · Calibration ECE) ② 베이스라인 구현: **LLM self-check("이거 맞아?")**, NLI 모델 단독 ③ 평가② 라벨 가이드라인·라벨링 진행 ④ K-HALU/K-FinHallu 독립 평가 ⑤ **격차 = 평가① − 평가② 산출** | C 모델 출력을 채점 · A의 챗봇 답변을 라벨링 |
| **E. 프론트·진행** | (미정) | ① **형광펜 데모 UI**(문장별 초록/노랑/빨강, 클릭 시 근거 문서 구간 하이라이트, 틀린 부분 밑줄) ② 발표자료·대본 ③ 일정·회의 관리 ④ `verification_result.json` 소비 | C 출력을 화면에 렌더 · A 챗봇과 한 화면 |

**self-check 베이스라인을 이겨야 프로젝트가 성립한다** — D파트가 1번으로 붙잡을 것.

## 3. 1주차 공통 과제 — `verification_result.json` 계약

그 외에는 3주차까지 각 파트가 병렬로 진행하지만, **이 계약만은 1주차에 팀 전체가 합의**해야 이후 통합이 막히지 않는다. 초안에 담을 것:

- 입력: (근거 문서 텍스트, 질문, 검증 대상 답변)
- 출력: 답변 토큰별 라벨(O/X) · 환각 구간 목록(start·end 문자 위치) · 구간별 유형 · 구간별 신뢰도 · 근거 인용 구간(원문 문자열, 문자열 매칭으로 기계 검증 가능해야 함)
- 3분류(지지 / 반박 / 정보부족)를 구간 단위로 낼지 답변 단위로 낼지
- 버전 필드(스펙 변경 추적용)

| 1 | 문서 수집·청킹 | RAGTruth 확보 + 번역 파이프라인 착수, **gemma 200건 재측정** | 인코더 후보 조사, 학습 스크립트 골격 | 지표·라벨 가이드 초안 | 데모 와이어프레임, **계약 초안 조율** |

| 5 | 리허설 대응 | 리허설 대응 | 여유 시 triage(선별 검증) 실험 | 결과 정리·검산 | **발표자료·대본 완성, 리허설** |

## 5. 논문 완독 배정 (양진우 제외 5명, 1인 1편 — 다음 회의에 1쪽 요약 공유)

| 담당 | 논문 | 깊이 | 무엇을 뽑아올 것 |
|------|------|------|----------------|
| 1 | **Turk-LettuceDetect** (2025.09) | 정독 | MT 모델·태그 보존·겹침 처리, 인코더 선택, 하이퍼파라미터, 평가 프로토콜, 그들의 수치 — **우리 재현·비교 기준** |
| 2 | **LettuceDetect** (2025) | 정독 | ModernBERT 토큰 분류 헤드, 긴 문맥 처리, RAGTruth 전처리 (Turk 논문이 전제로 삼는 부모 방법) |
| 3 | **TinyLettuce** (2025) | 스킴 | "17M이 235B 이김" 수치(피치 근거) + 합성 데이터 생성법(증강·폴백 아이디어) |
| 4 | **RAGTruth 원논문** — "RAGTruth: A Hallucination Corpus for Developing Trustworthy Retrieval-Augmented Language Models" (Niu et al., ACL 2024, arXiv 2401.00396, 코드·데이터 `github.com/ParticleMedia/RAGTruth`) | 정독 + GitHub JSON 스키마 확인 | 3과제 구조(QA=MS MARCO / data-to-text=Yelp / 요약=CNN·DailyMail), 6개 LLM, 구간 라벨 스키마·유형 4종, 공식 train/test split |
| 5 | **KCI 논문** "대형 언어 모델 응답의 신뢰성 향상을 위한 환각 탐지 및 설명 모델" (2025, KIISE) | 정독 | **구간/문장/응답 중 어느 단위인가** — 구간 단위면 "한국어 첫 시도" 주장 수정 필요. 탐지+이유설명 방식, 주장 성능 |

- **K-FinHallu는 배정 제외** — 이미 `K-FinHallu_비교.md` + `K-FinHallu_심층분석.md` 두 문서로 분석 완료. D파트가 재독만.
- **양진우(C)**는 리뷰는 안 하지만, 담당 1·2(Turk-LettuceDetect·LettuceDetect)가 곧 C의 방법 논문이므로 해당 리뷰어와 붙어서 방법·학습 세팅을 공유받을 것.

## 6. 다음 회의까지 각자 숙제

- **A**: 검증 대상 문서 후보(학사요람/법률/그 외) 각각의 확보 난이도·분량 조사해 오기
- **B**: RAGTruth 다운로드 경로·라이선스, 번역 모델 사용 가능 여부 확인
- **C**: 한국어 인코더 후보 3종 + 8,192 토큰 처리 방안(슬라이딩 윈도우 등) 정리
- **D**: 평가 지표 최종안 + 평가② 라벨링에 몇 명·며칠이 필요한지 산정
- **E**: 형광펜 데모 화면 스케치 1장, `verification_result.json` 계약 초안 1장
- **공통**: 5절 논문 배정대로 1인 1편 완독 + 1쪽 요약 공유
