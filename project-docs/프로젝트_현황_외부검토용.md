# 한국어 환각 탐지 프로젝트 — 현황과 검토 요청

작성 2026-09-09 · B1조 (6인) · 최종 발표 **10/2**

> 이 문서는 **배경을 모르는 제3자에게 조언을 구하기 위해** 쓴 것이다.
> 지금까지 한 일, 실제로 나온 숫자, 지금 막힌 지점을 모두 담았다.

---

## 1. 프로젝트가 무엇인가

**문서를 근거로 답하게 한 AI의 답변에서, 그 문서로 뒷받침되지 않는 구절만 골라
표시하는 한국어 모델을 만든다.**

판정 기준이 **"이 말이 사실인가"가 아니라 "이 문서에 있는가"** 다.
사실이어도 그 문서에 없으면 표시한다. 이른바 RAG 환각(faithfulness) 문제이고,
정답이 존재하는 문제를 채점하는 것과는 다르다.

출력은 답변의 **토큰마다 O/X**, 이어붙이면 구절 단위 표시가 된다.

```
답변   하지만  교외  장학금  신청은  가능할  수  있습니다
판정    O      X     X      X      X     X    X
              └────── 문서에 근거 없음 ──────┘
```

## 2. 지금까지 한 일과 실제 숫자

### 2-1. 학습 데이터를 직접 만들었다

한국어에는 **구절 단위로 환각을 표시한 공개 자료가 없다.** 영어 **RAGTruth**
(사람이 답변에서 지어낸 구간을 글자 위치로 표시해 둔 1.7만 건)를 번역해 만들었다.

문제는 표시가 `{start: 636, end: 661}` 처럼 **글자 위치**로 저장돼 있다는 점이다.
번역하면 어순이 바뀌어 위치가 전부 어긋난다.

해법 — **표시를 위치가 아니라 내용에 태그로 붙이고 통째로 번역한 뒤,
태그 자리에서 글자 위치를 다시 센다.**

```
영어    ... but <HAL>you may still be eligible</HAL> ...
한국어  ... 하지만 <HAL>신청은 가능할 수 있습니다</HAL> ...
```

- 번역 모델 — `google/gemma-3-12b-it` (선행 연구는 27B, 우리 GPU 한계로 12B)
- 파일럿 200건에서 **태그 보존율 98%**
- 자동 검사를 통과한 것이 **17,537건** (학습 14,863 / 평가 2,674)

### 2-2. 인코더 3종을 학습시켰다

`AutoModelForTokenClassification(num_labels=2)` — 답변 토큰만 0/1 라벨을 받고,
문서·질문 토큰은 `-100`으로 손실에서 제외한다.

| 인코더 | 파라미터 | 문맥 | macro F1 | AUROC |
|---|---|---|---|---|
| `klue/roberta-base` | 1.1억 | 512 | 0.6980 | 0.837 |
| `xlm-roberta-base` | 2.7억 | 512 | 0.6527 | 0.847 |
| **`BAAI/bge-m3`** | 5.7억 | 8192 | **0.7385** | **0.8834** |

비교 대상은 터키어 선행 연구(Turk-LettuceDetect, arXiv:2509.17671)의 **0.7266**이고,
bge-m3가 **세 과제 전부에서** 이를 넘었다.

학습 설정 — epochs 6 · lr 1e-5 · 유효 배치 4(배치1×누적4) · warmup 0.06 ·
bf16 · gradient checkpointing · `metric_for_best_model="hallu_f1"`.

### 2-3. 세 가지 실험 결과

**① 절삭이 원인이었다.** 512 토큰 모델은 긴 문서를 자른다. 과제를 고정해 비교하니
**요약 과제에서만 파괴적**이었다(AUROC 차 +0.13~0.15), QA는 무해(+0.001~0.008).
8,192를 다루는 bge-m3로 옮겨 해결했다.

**② 번역 손실이 관측되지 않았다.** 같은 인코더·같은 512·같은 응답 집합으로
**영어 원본**을 학습시켜 대조했다.

| | 한국어(번역본) | 영어(원본) | 차이 |
|---|---|---|---|
| macro F1 | **0.6531** | 0.6087 | +0.044 |
| AUROC | **0.847** | 0.8041 | +0.043 |

한국어가 오히려 높다. 터키어와의 격차를 번역 탓으로 돌릴 수 없고, 원인은
**문맥 길이**였다는 해석과 일치한다.

**③ 도메인을 옮겨도 판별력이 유지된다.** 학습에 없던 도메인(화학·법령 기술문서)인
MSDS 평가 세트로 재보았다.

| | 벤치마크 AUROC | MSDS AUROC | 차이 |
|---|---|---|---|
| bge-m3 | 0.8834 | **0.8140** | −0.069 |
| klue | 0.837 | 0.7941 | −0.043 |

문체·구조가 완전히 다른데 0.07 밖에 떨어지지 않았다.

### 2-4. 확인된 한계

**숫자를 대조하지 못한다.** MSDS 세트에서 유형별 탐지율이 이렇게 나왔다.

| 유형 | bge-m3 | klue |
|---|---|---|
| 지어내기 | 62% | 46% |
| **숫자변조** | **20%** | **20%** |
| 과일반화 | 50% | 75% |
| 의무예외 | 0% | 33% |

**숫자변조만 두 모델이 정확히 같다.** 크기가 5배 다른 두 모델이 같은 비율로
실패하므로 **모델을 키워 해결될 문제가 아니라 학습 자료의 한계**로 보고 있다.

문서에 "측정주기 6개월 / 진단주기 12개월"이 있는데 답변이 둘을 맞바꿔도 놓친다.
두 숫자가 모두 문서에 있어 어휘 대조로는 잡히지 않는 사례다.

### 2-5. 팀원이 만든 평가 자산

- **MSDS 평가 세트** — 톨루엔 MSDS를 법정 16개 항목 기준 18조각으로 분리,
  질문 52문항 설계(질문유형 5종 × 답변유형 5종 교차), 정답 22 / 환각 30
- **생성 모델 6종 실측** — 같은 문서·질문을 2.5~4.9GB 소형 오픈 모델에 넣어
  312개 답변을 받고 전부 라벨링

| 모델 | 환각률 |
|---|---|
| llama3.1:8b | 13% |
| mistral:7b | 23% |
| qwen2.5:7b | 25% |
| exaone3.5:7.8b | 37% |
| qwen2.5:3b | 38% |

**검색 단계 없이 문서를 프롬프트에 직접 넣은 조건**이므로 "못 찾아서 틀린 것이
아니라 눈앞에 두고 틀린 것"이다.

**교차 함정** — 톨루엔 문서만 주고 에탄올·벤젠을 물었더니 **18번 중 12번**
톨루엔 값을 그대로 답했다. 3B든 8B든 같았다.

### 2-6. 그 외

- RAG 데모 — `bge-m3` 임베딩(CLS 풀링·정규화) + numpy 내적 top-4 + `gemma-3-12b-it`(4bit)
  생성 + 탐지기 형광펜. 벡터 DB·리랭커 없음
- 팀원 배포 패키지 — CPU에서 도는 `klue` 모델 + 형광펜 앱 + 채점 스크립트
- 발표 덱 19장 (HTML)

## 3. 자문에서 받은 지적

자문 자료가 요구하는 것은 이렇다.

**환각을 3개 class로 나눈다** — 검색 실패 / 생성 실패 / 불충분한 증거

**3단계 로드맵**

| 단계 | 내용 |
|---|---|
| 1 · 연구 필요성 검증 | 2B~8B 경량 LLM 비교 → MSDS RAG 환각률 확인 → **zero-shot 환각·근거 지목 성능 측정** |
| 2 · 핵심 기술 개발 | **전용 라벨 데이터 구축 [환각 Span ↔ Evidence Span]** → 경량 모델 2개 파인튜닝 → **zero-shot 대비 향상 검증** |
| 3 · 서비스 확장 | 원인 진단 → 검색 실패면 재검색 / 생성 오류면 부분 재생성 / 근거 없음이면 답변 제한 |

**아키텍처**

```
[문서 전체] → Evidence Retriever → 관련 문단 Top-k ─┬─ LLM 답변
                                                    ↓
                                         Fine-tuned 경량 LLM
                                                    ↓
                      ┌─────────────────┼─────────────────┐
                  환각 Span        Evidence Span      유형 + 관계 판정
                      └─────────────────┬─────────────────┘
                                        ↓
                                  규칙 기반 진단
                        ┌───────────────┼───────────────┐
                    검색 실패        생성 실패        근거 부족
```

**지금 우리와 다른 네 가지**

| | 현재 | 자문 |
|---|---|---|
| 학습 데이터 | RAGTruth 번역본 | **전용 데이터 직접 구축** |
| 출력 | 환각 Span 하나 | **Span + Evidence Span + 유형** |
| 베이스 | 인코더 | **경량 LLM 2B~8B 파인튜닝** |
| 비교 기준 | 터키어 선행연구 | **zero-shot 대비 향상** |

## 4. 지금 막힌 지점 네 가지

### ① 적용 도메인을 MSDS로 유지할 것인가

**MSDS를 고른 이유** — 틀리면 사람이 다친다 / 법정 공개 자료라 확보가 쉽다 /
16개 항목이 법으로 고정돼 "문서에 있다·없다"가 명확하다.

**걸리는 점**
- 팀에 화학 전공자가 없어 **대량 라벨링에 부담**이 있다
- 톨루엔처럼 **유명한 물질은 모델이 이미 알아서** 문서를 안 보고 답한다.
  환각이 발생하지 않으면 평가 자체가 성립하지 않는다
- 도메인 하나로는 "그 문서에서만 되는 것 아니냐"에 답할 수 없다

**대안 후보를 이렇게 정리했다.** 가장 중요한 조건은 **①모델이 그 내용을 모를 것**이다.
모르는 내용이라야 문서를 보고 답하고, 그래야 환각이 관측된다.

| 후보 | ①모름 | ②판정 명확 | ③근거 위치 | ④비전공자 가독 | ⑤오류 대가 |
|---|---|---|---|---|---|
| **정부 지원사업 공고** | ◎ 매년 바뀜 | ◎ | ◎ | ◎ | ○ 기회·금전 |
| **의약품 허가사항** | ○ | ◎ | ◎ | ○ | ◎ 안전 |
| 행정 절차 안내 | ◎ | ◎ | ○ | ◎ | ○ |
| MSDS (현행) | △ 유명물질은 앎 | ◎ | ◎ | △ | ◎ |
| 학사 규정 (보유) | ◎ | ○ | ○ | ◎ | ✕ |
| 보험 약관 | ○ | ✕ 해석 여지 | △ | △ | ◎ |
| 법령·판례 | ○ | ○ | △ | ✕ | ◎ |

### ② 다른 조와 주제가 겹쳐 보인다

같은 캠프의 다른 조가 **수학 문제 풀이를 LLM에 시키고 틀린 해설에 밑줄을 긋는**
주제를 한다.

우리가 보는 차이 — 그쪽은 **정답이 존재하고 검산이 가능**하다. 계산기로 확인된다.
우리는 **정답이 없고 문서만 있다.** 문서가 바뀌면 정답도 바뀐다.
"밑줄을 긋는다"는 결과물이 같을 뿐 푸는 문제가 다르다고 본다.

다만 심사자에게 그 차이가 즉시 보이지 않을 위험이 있다.

### ③ 규모 비교 압박

다른 팀은 위스키 제조 공정이라는 특정 분야를 잡고 **약 6,000장을 라벨링**한다고 한다.
우리 규모를 세어 보면 이렇다.

| 자산 | 규모 |
|---|---|
| RAGTruth 한국어 번역본 | 17,537건 (직접 번역·검증) |
| MSDS 답변 (사람 1 + 모델 6) | 364건 · 물질 1종 |
| 물질 5종으로 늘릴 경우 | 약 1,800건 |

**규모 자체는 밀리지 않는데, 발표에서 "우리가 만든 것"이 잘 안 보인다.**
17,537건은 우리가 만든 것인데 "RAGTruth를 썼다"로만 읽힌다.

### ④ CPU 제약을 유지할 것인가

지금은 "노트북 CPU에서 2~5초"를 목표 사양으로 두고 있다. 데이터를 밖으로
내보낼 수 없는 현장을 상정한 조건이다. 그런데 자문대로 경량 LLM을 파인튜닝하면
이 조건이 깨진다.

## 5. 내부적으로 검토한 방향

### 안 A — RAGTruth를 버리지 않고 2단계 학습으로 엮는다

```
1차   RAGTruth 번역본 17,537건   ← 형태를 배운다 (양이 많다)
 ↓
2차   전용 라벨 데이터            ← 도메인을 배운다 (질이 맞다)
```

이러면 비교 조건이 넷 생긴다.

| 조건 | 무엇을 말하는가 |
|---|---|
| A. RAGTruth만 | **이미 측정 — MSDS AUROC 0.8140** |
| B. 전용 데이터만 | 도메인은 맞되 양이 적을 때 |
| C. RAGTruth → 전용 | 이어 붙였을 때 |
| D. zero-shot | 자문이 요구한 기준선 (**아직 없음**) |

`D < A·B < C`가 나오면 **"번역 데이터가 도메인 데이터의 부족을 메운다"**는
주장을 실측으로 낼 수 있다.

### 안 B — 주력 도메인을 옮기고 MSDS는 대조군으로 남긴다

```
주력   새 도메인 (지원사업 공고 등)  ← 대량 라벨링. 여기서 데이터를 만든다
대조군 MSDS                        ← 팀원 작업 보존. 도메인 일반화 근거
```

### 안 C — 두 갈래 모델을 모두 유지한다

| 갈래 | 모델 | 출력 | 용도 |
|---|---|---|---|
| 가벼운 쪽 | 인코더 klue 1.1억 | 환각 Span | 현장·실시간·CPU |
| 정확한 쪽 | 경량 LLM 파인튜닝 | Span + Evidence + 유형 + 원인 | 정밀 진단·서버 |

두 갈래의 성능 차이 자체가 **"가볍게 하면 얼마를 잃는가"**라는 결과가 된다.

### 새로 만들어야 하는 것

**Evidence Span** — 지금 라벨은 환각 구절 하나뿐이다. 그 구절이 문서의 어느
부분과 어긋나는지를 짝지어 표시해야 한다.

```
답변    측정주기는 12개월이며, 진단주기는 6개월입니다.
환각    [12개월]  [6개월]
근거    15항 "작업환경측정대상물질 (측정주기 : 6개월)"     ← 새로 붙일 것
관계    값 불일치 (서로 뒤바뀜)
```

**3-class 중 "검색 실패"는 지금 설계로 만들 수 없다.** 문서를 프롬프트에 직접
넣었기 때문이다. 검색을 실제로 붙인 세트를 따로 만들어야 한다.

## 7. 조언을 구하고 싶은 것

1. **도메인 선택** — MSDS를 유지하는 것과 다른 도메인(정부 지원사업 공고,
   의약품 허가사항 등)으로 옮기는 것 중 어느 쪽이 나은가.
   특히 **"모델이 그 내용을 모를 것"**이라는 조건을 얼마나 무겁게 봐야 하는가.

2. **자문 반영 범위** — 남은 3주에 자문의 3단계를 어디까지 하는 것이 현실적인가.
   Evidence Span 라벨링과 경량 LLM 파인튜닝 중 하나만 한다면 무엇을 골라야 하는가.

3. **인코더 대 경량 LLM** — 지금 인코더(bge-m3 5.7억)로 AUROC 0.8140이 나온 상태에서,
   경량 LLM(2B~8B) 파인튜닝으로 갈아타는 것이 성능·기여 측면에서 값어치가 있는가.
   Evidence Span과 유형을 함께 내려면 생성 모델이 필요하다는 판단인데 타당한가.

4. **차별화** — "정답이 있는 문제의 풀이 검증"과 "정답이 없는 문서 기반 근거 추적"의
   차이를 심사자에게 즉시 보이게 하려면 어떤 프레이밍이 좋은가.

5. **규모** — 라벨 데이터의 규모를 어느 선까지 만들어야 "야무지다"는 인상을 주는가.
   번역으로 만든 17,537건과 직접 라벨링한 수백~수천 건 중 어느 쪽을 앞세워야 하는가.

6. **빠진 실험** — 지금 없는 것 중 가장 먼저 채워야 할 것은 무엇인가.
   (자체 판단으로는 **zero-shot 기준선**이 1순위다. 이것이 없으면 어떤 숫자가 나와도
   "그래서 좋아진 것인가"에 답할 수 없다.)

## 부록 — 용어

| 용어 | 뜻 |
|---|---|
| RAG | 문서를 검색해 그 내용을 근거로 LLM이 답하게 하는 방식 |
| RAG 환각 | 문서를 줬는데도 그 문서에 없는 내용을 말하는 것 |
| Span | 답변 안에서 문제가 되는 **구간** (몇 번째 글자부터 몇 번째까지) |
| Evidence Span | 그 구간이 어긋나는 **문서 쪽 근거 구간** |
| macro F1 | 환각 클래스 F1과 정상 클래스 F1의 평균. 선행 연구가 쓰는 지표 |
| AUROC | 임계값과 무관한 판별력. **클래스 비율에 둔감해 분포가 다른 두 세트를 비교할 때 씀** |
| zero-shot | 파인튜닝 없이 프롬프트만으로 시키는 것 |
| MSDS | 물질안전보건자료. 화학물질의 유해성·취급·응급조치를 담은 법정 문서 |
