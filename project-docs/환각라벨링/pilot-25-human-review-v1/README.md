# 팀원 검수 25문항 통합 · 2026-09-15

팀원 4명이 제출한 7/6/6/6문항을 기존 정본 답변·근거·구절 좌표와 대조했다. **제출 검수는 25건 모두 접수 완료, 최종 조정 승인과 학습 내보내기는 미완료**다. 기존 pilot-25-v1, 질문 300건, 원본 모델 답변, 회사 마스터 및 RAG 입력은 수정하지 않았다.

## 먼저 볼 파일

- [통합 형광펜 미리보기](review.html): 원래 답변, 제출 의견, 구절별 조정안, 근거를 함께 확인한다. 노랑은 환각 조정안, 파랑은 인용 오류, 보라 점선은 보류다. 자동 탐지 결과나 확정 정답이 아니다.
- [통합 검수 목록](통합검수목록.tsv): 25문항의 담당자·사람 판정·의견을 Excel에서 확인한다.
- [구절 조정 목록](구절조정목록.tsv): 기존·추가 구절 88개와 분류·처리 제안을 확인한다.
- [주요 조정 사항](조정사항.md): 최종 조정자가 확인할 분류 차이와 문항 문제.
- [기계 판독 조정안](adjudication_proposals.jsonl), [제출 의견 원문](submitted_reviews.jsonl).
- [입수·해시 기록](intake_manifest.json), [검증 결과](validation_report.json), [오류 주입 테스트](test_report.json).
- received/의 T01.xlsx~T04.xlsx는 제출 원본의 바이트 보존 사본이다. 새 엑셀 파일을 편집·재작성하지 않았다.

## 실제 집계

| 구분 | 결과 |
|---|---:|
| 문항 검수 | 25건: 동의 12 / 수정 제안 12 / 재검토 1 |
| 기존 구절 검수 | 68건: 동의 65 / 분류 수정 3 |
| 팀원의 추가 구절 제안 | 14개 위치 |
| 에이전트의 추가 인용 오류 제안 | 6개 위치 |
| 통합 구절 레코드 | 88개 |
| 조정 처리 | 채택 제안 70 / 보류 16 / 품질 메모만 2 |
| 채택 제안의 구성 | 환각 대상 56 / 인용 오류 14 |
| 자동 검사 | 19개 테스트 통과 |

88개가 모두 환각이라는 의미가 아니다. 반복 구절은 실제 출현 위치별로 계산한다. 기존 모호한 구절에 동의했다는 검수도 모호함을 유지한다. CITATION_ERROR는 환각 BIO 대상과 분리한다. 채택 제안에도 final_human_approval=pending을 유지했으며, 모든 approved_spans=null, training_ready=false다.

## 제출 파일의 정본 차이 처리

T01~T03은 보호된 셀 값이 동일했다. T04는 답변전문 C열 11개, 근거 C열 5개에서 앞뒤 공백/줄바꿈이 제거됐고 빈 Sheet7이 추가됐다. 공백을 제외한 문장 내용은 동일했다. 제출본 자체를 고치지 않고 통합본의 답변·근거·offset은 기존 v1 정본에서 가져왔다. 내부 공백·문장·숫자 등이 바뀌면 가져오기가 실패하도록 했다. 원본과 제출본 해시, 달라진 셀 좌표는 intake_manifest에 기록했다.

## 검토 범위와 한계

- 25개 문항 의견과 68개 기존 구절 의견, 추가 제안을 읽었다. 수정·추가 구절은 실제 답변과 생성 입력 근거를 대조해 조정했다.
- 실제 로컬 색인을 읽기 전용으로 열어 생성 입력 79개 청크 참조의 해시를 대조했다. 이 수는 문항별 참조 횟수이며 고유 청크 수나 검색 성능이 아니다. 기존 근거 발췌의 위치·인용도 확인했다.
- 새 근거 앵커는 기존 모델 입력 청크의 필요한 문항에만 추가했다. 입력 밖 참고 근거를 당시 프롬프트에 소급 삽입하지 않았다. 전체 원천 캐시를 복제하지 않았다.
- 원본 HWP/PDF를 이번에 다시 렌더링하거나 팀원 의견의 원문 전체 단어 횟수를 재집계하지 않았다. 해당 주장은 제출 의견으로만 남겼다. 이번 작업은 법률 해석이나 최종 입찰 적격 판정이 아니다.
- 팀원별 문항이 서로 달라 검수자 간 일치도나 독립 이중 검수 성능을 계산할 수 없다. 25문항은 의도적으로 고른 개발 자료이며 독립 테스트셋이 아니다.
- HTML은 이스케이프된 정본 텍스트로 생성했다. 이번 브라우저의 file URL 보안 정책 때문에 실제 렌더링·스크린샷 검증은 미실시다. 사용자는 review.html을 로컬 브라우저에서 직접 열어볼 수 있다.

## 재현

저장소 루트에서 실행한다. 개인 PC 경로는 코드에 고정하지 않았다. 입력 폴더에는 원 제출 파일명 또는 보존 사본 T01.xlsx~T04.xlsx가 있으면 된다.

~~~text
python procurement-pipeline/import_pilot_reviews.py --input-dir project-docs/환각라벨링/pilot-25-human-review-v1/received --index <기존 index.sqlite 경로>
python procurement-pipeline/test_pilot_reviews.py
~~~

생성기는 Excel 수식·매크로·외부 연결을 실행하지 않고 차단한다. 기존 생성 답변을 다시 만들거나 색인에 쓰지 않는다. 조정 내용은 procurement-pipeline/review_pilot_return_specs.py에 명시돼 있다. 새로운 제출 내용으로 바뀌면 기존 received 파일을 덮어쓰지 말고 후속 버전에서 새롭게 검토해야 한다.

## 다음 단계

1. 최종 조정자가 조정사항.md의 보류·분류 변경·문항 모호성에 대해 확정한다. 승인자의 이름·일시·대상 구절을 기록한 별도 승인본을 만든다.
2. UNCERTAIN과 미해결 영역은 학습에서 마스킹한다. 보류 구절이나 품질 메모를 자동으로 O 토큰으로 바꾸지 않는다.
3. 승인된 구절만 모델 토크나이저의 offset/BIO로 변환해 문자↔토큰 정합성과 잘림·윈도우 경계를 검사한다. 인용 오류는 별도 평가로 유지한다.
4. 이 기준을 고정한 뒤 나머지 답변의 검수 확대와 워크스테이션 학습을 진행한다. 이번에는 모델 실행·학습·전체 RAG 재실행을 하지 않았다.

이 폴더에는 합성 회사 L2/L3 근거 및 평가 정답이 포함된다. 내부 검수용이며 공개 데모 정적 폴더나 RAG 검색 코퍼스에 배포하지 않는다.
