# KLUE 단독 개선 실험 결과

## 결론

**추가 학습한 KLUE 단독의 오류 검출과 F1은 개선됐다. 다만 평가 정밀도40% 목표에 미달하여 운영 교체는 보류한다.** 기존 demo/UI 및 기본 가중치는 변경하지 않았다. 선택한 모델을 호출하는 별도 단일모델 실행기를 제공한다.

공고 단위로 묶은 학습182·개발50·평가63 답변을 사용했다. 평가63건은 이번 추가 학습·설정 선택에서 제외하고, 선택을 커밋 `831cf07`로 고정한 뒤 한 번 비교했다. 다만 기존300 전체는 이전 RAG 개발·에이전트 검토에 노출됐다. **새 독립 test도, 최종 사람 승인 gold도 아니다.** 기존 전체295의 F1 0.0449와 아래63건의 기준선0을 직접 비교하면 안 된다.

## 같은 평가63건의 잠정 비교

| 지표 | 기존 KLUE | 개선 KLUE |
|---|---:|---:|
| 문자 Precision | 0.0000 | 0.2142 |
| 문자 Recall | 0.0000 | 0.2418 |
| 문자 micro F1 | 0.0000 | 0.2272 |
| 답변 F1 | 0.1026 | 0.7229 |
| strict exact-span F1 | 0.0000 | 0.0000 |

- 오류 포함35답변 중 경고한 답변: **2→30건**. 정상으로 라벨된28답변 중 오탐: **2→18건**.
- 문자 TP/FP/FN: **0/27/2,390 → 578/2,121/1,812**. 경고한 문자의 약78.6%는 잠정 라벨상 오탐이다. 총 문자 오분류(FP+FN)는 오히려 늘었다. F1 상승을 일반적인 정확도 상승으로 표현하지 않는다.
- 답변 단위 TP는 오류 답변에서 어디든 경고하면 인정한다. 기존 모델의2건은 경고 위치가 오류 위치와 달라 문자TP는0이었다.
- 공고 묶음 bootstrap 2,000회 F1 차이의95% 구간: **+0.1469~+0.3184**. 라벨 초안의 불확실성·과거 노출 편향을 포함한 구간은 아니다.
- 평가63건의 전체 29,867문자 중 공통 평가 22,722문자. 같은 마스킹·검사영역을 사용했다. uncertain/citation_error/quality_only는 내용 환각 점수에서 제외한다.

## 선택 구성

- KLUE 원래 가중치에서 추가 학습2epoch. 학습용182답변의 **미승인** 초안·통합안을 사용했다.
- 매 답변192토큰 분할, 모든 근거 창에 질문·문서 접두부 반복, 근거 절반 stride 순회, min 집계, 임계값0.2.
- 학습 시 각 답변 구간의 어휘 관련도 상위2개 근거 창을 사용했다. 이는 전체근거 라벨을 일부창에 전달하는 근사이며 잘못된 감독 가능성이 남는다. 추론 시에는 전체근거를 순회한다.
- 하위6개 encoder 층과 embedding 동결, 상위층·분류기 학습, lr5e-6, positive weight2, 유효batch4, seed20260915, BF16. epoch별 체크포인트·optimizer/RNG를 ignored work에 보존한다.
- 모델 선택: 개발용 문자 Precision≥0.40 중 F1 최대. epoch1은 F1 0.0926, epoch2는0.2724였다. **개발 정밀도41.2%가 평가에서는21.4%로 낮아졌다.**
- 규칙 결합은 개발·평가에서 추가 이득0이라 껐다. 앙상블과 XLM-R/BGE-M3 재실행은 하지 않았다.

## 수행한 진단·실험

1. 학습 입력과 추론의 CLS/SEP·label mapping·loss mask·토큰 순서를 대조했다. 과거 번역 RAGTruth36건으로 학습 encode와 추론 래퍼를 비교해 확률 오차0. 기존 개발50건 min 예측 재현 최대오차1.2e-7. 구현 방향 오류의 증거는 찾지 못했다.
2. FP32/BF16 개발 표본의 최대 확률차0.000149, threshold0.5 판정변경0. 한 표본 결과로 모든 수치 오차를 배제하지 않는다.
3. 기존 min 확률의21개 임계값, 3개 입력 프로파일(기존192·질문반복192·문장경계96/중첩16), 6개 집계(min/min2/평균/25분위/max/어휘관련도 가중)를 비교했다. 원모델399개 개발 설정 + 추가학습2개×126개 설정으로 총651개 설정점을 기록했다. 평가63의 설정을 고르는 데 사용하지 않았다.
4. 낮은 임계값으로 거의 모두 경고하는 설정은 F1이 높아도 정밀도 조건에서 제외했다. 질문반복·주장단위·집계변경만으로는 원모델 min/0.05보다 좋아지지 않았다.
5. 명시적 하도급·우편·공동수급·계열사 금지와 무조건 허용 주장의 충돌 규칙을 시험했다. 조건·예외·승인 문장은 보류하며 이득이 없어 운영 구성에서 제외했다. 숫자·VAT·FTE의 무조건 문자열 불일치 규칙은 유효한 계산·환산을 오탐할 위험이 있어 이번에 채택하지 않았다.
6. 최대 위치514인 KLUE를 지원범위 밖으로 늘리지 않았다. 새 대형 검증 모델·LLM gold 생성·유료 API·기존 RAG/원답변 재생성은 하지 않았다.
7. 기존 번역 RAGTruth train14,863/test2,674를 확인했다. 기존 모델 선정·평가에 사용된 자료라 새 독립검증 자료로 인정하지 않았다. 신규 사람확정 조달 검증자료는 찾지 못했다.

## 비용·검증

선택 모델295건 전부 성공, 실패0, 5,196개 근거 창, 답변별 처리시간 합계 62.78초(로드·워밍업 제외), 최대 allocated VRAM 0.61GiB다. 기존295건58.92초보다 약6.6% 늘었다. 실행 시점·GPU 부하가 달라 엄밀한 성능 벤치마크는 아니다.

단일모델 실행기 검증에서는 로드5.95초, 별도 워밍업0.30초를 측정했다. 한 번 로드한 모델로 개발3답변을 처리해 캐시 예측과 일치했다. 기존 프로세스 PID4922를 보존했다.

- 기존26 + 신규10 = **36개 테스트 통과**. 원입력300건 무결성 통과.
- 선택모델295건 모두 기존과 같은 문자 검사영역, 비공백 미검사0. 정상차단5건은 v1 별도검증을 그대로 보존했다.
- 입력·라벨·모델·설정·코드 해시 및 모든 확률 행렬 범위를 검증했다. 기존 v1·pilot25·원가중치는 변경하지 않았다.
- 공고51묶음, 동일/유사 질문 및 동일답변을 분할 전 묶었다. 추가 답변유사도0.9 이상 분할간 사례0. 의미적으로 닮은 보편 규정까지 완전히 독립이라는 뜻은 아니다.
- 동일설정 재개 시295건을 건너뛰는 것을 확인했다. 각 문항 행렬은 atomic 저장, 학습은 완료epoch 상태에서 재개한다. epoch 중간 종료 시 그 epoch는 다시 수행한다.

## 다음 단계와 미달 사항

검출 개선은 확인했지만 정밀도40%의 평가 목표는 미달했다. 자동 차단·정답 보증 용도로 승인하지 않는다. 사람 검수 후보를 넓게 찾는 보조 검사로도 오탐 부담을 먼저 검증해야 한다.
