# 워크스테이션 환각 탐지기 300문항 평가 인계

## 목적과 고정 입력

새 Llama/Qwen/EXAONE 답변을 생성하는 작업과 별개다. 기존 effective_results.json이 선택한 300레코드(생성295, 차단5)를 보존하고 생성된295답변에 KLUE/XLM-R/BGE-M3 탐지기를 비교 적용한다. 기본 추론 슬롯은 885개이며 차단5건은 별도 무호출 검사다.

selected_inputs.json은 이 인계 시점의 질문ID·선택 원 실행 파일·답변 해시·생성 입력 근거 해시를 고정한다. hash가 다르면 새 버전으로 명시적으로 갱신하며 이전 답변을 몰래 교체하지 않는다.
full prompt 또는 index에서 당시 실제 제공한 근거를 복원한다. 평가용 기대답이나 사후 근거로 대신하지 않는다. 일부 프롬프트는 계산/시나리오 맥락을 추가했을 수 있으므로 prompt_evidence뿐 아니라 prompt()와 원 프롬프트 캐시도 대조한다. 템플릿 지시문을 업무 근거로 분류하지 않는다. 정확한 생성 입력이 복원되지 않는 문항은 해당 범위를 보류하고 다른 문항은 진행한다.

## 처음 실행

1. 현재 작업과 미커밋 변경을 보존하고 origin/feature/sample-expansion-demo를 fetch한다. 원격을 기존 브랜치에 강제 덮어쓰지 않는다. 새 작업 브랜치나 별도 checkout에서 이어간다.
2. WORKSTATION_PROMPT.md를 해당 PC의 AI에 전달한다.
3. 저장소 루트에서 python procurement-pipeline/prepare_detector300_handoff.py --check 실행.
4. 기존 원천/색인/프롬프트 캐시와 학습 가중치를 탐색한다. source 경로는 RAG파일럿/workstation-275/README.md 및 v1/SOURCE_TRANSFER.md, 가중치 체크섬은 팀원배포/dashboard-integration-v1/checkpoints.json 참고.
5. GPU와 학습 runtime을 확인한 뒤 소수 검사 → 재개 가능한 전체 실행 순으로 진행한다.

## 산출물 구획

- inputs/: 동결 manifest와 복원 품질. 전체 프롬프트/근거 텍스트 캐시는 ignored work 아래에만 저장.
- predictions/<model>/<run>/: 실제 탐지 결과·문자 offset·점수·검사범위·시간·오류.
- annotation/agent_draft/: 모델 예측을 보지 않고 근거와 정본으로 만든 라벨 초안·판단 이유·근거 위치.
- annotation/human_submitted/: 기존25 검수 원본을 참조, 수정하지 않음.
- annotation/adjudicated/: 조정안과 보류, 실제 사람 승인과 분리.
- evaluation/: 잠정 점수·승인 라벨 기준 점수·범위·N/A·검토 커버리지.

결과 폴더는 후속 작업에서 생성한다. 현재는 인계 문서와 동결 목록까지 준비했으며 885추론 실행은 아직 하지 않았다.

## 핵심 규칙

기존25건은 의도적으로 고른 개발 자료이며 승인pending. 나머지275레코드에는 차단 여부를 확인하고 실제 생성 답변만 구절 작업한다. 질문 개수와 답변 개수와 추론 슬롯을 구분한다.
미검토 구간을 정상으로 취급하지 않는다. 검출된 부분만 검토하면 Recall을 측정할 수 없다. 전체 답변을 훑어 놓친 오류도 검수한다. 사후 전체 원문과의 진실성 평가와 당시 입력 근거 지지 여부를 별도 평가한다.
정답지에 모델의 예측을 그대로 복사하지 않는다. 기존25 의견·인용 오류·품질 메모·모호함은 서로 구분한다. CITATION_ERROR는 내용 환각과 별도다.
학습·임계값 튜닝과 최종 평가를 같은 문항으로 하면 개발 결과로 표시한다. 미승인 에이전트 라벨 기준 수치를 사람gold 성능으로 발표하지 않는다.
원문·가중치·전체캐시·비밀키는 Git에 올리지 않는다. 실제 수행한 검사만 완료로 보고하고, 독립적인 사람 검수는 자동으로 승인 처리하지 않는다.
