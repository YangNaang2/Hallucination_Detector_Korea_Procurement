# KLUE 검수 우선순위 및 에이전트 라벨 수정 — v4

## 결론

사용자 위임에 따라 근거를 대조해 학습 자료의 구절 라벨 2개를 에이전트 승인으로 수정했다. 사람 제출 원본과 사람 승인 상태는 유지했다. 새 운영 지표와 검수 순위 설정 36개를 비교했지만 기존 방식 대비 개선되지 않아 새 순위 방식을 채택하지 않았다. **80% 목표 미달이며, 모델 성능이 향상됐다는 새 주장은 하지 않는다.** 기존 v3 문자 F1 31.13%는 그대로다.

## 지표를 먼저 고정

주목표: 답변 묶음의 60% 이하를 검수할 때, 환각 답변 80% 이상을 검수 대상으로 포함하기. 보조 검수량은 30%, 50%다. N건 중 floor(N×예산)건을 점수순으로 선택한다. 동점은 질문 ID 해시로 처리한다. 점수 산출에는 정답 라벨을 사용하지 않는다.

포착률 = 검수 대상 안의 환각 답변 수 / 전체 환각 답변 수. 실제 오류 구절을 정확히 표시했는지와는 별도다. 문자 P/R/F1을 대체하지 않으며, 정상 답변 경고율과 검수 정밀도도 함께 기록한다. 예산이 다르면 같은 성능으로 비교하지 않는다.

앞서 제안한 30% 검수/80% 포착은 현재 데이터에서 불가능하다. 개발 50건 중 양성 35건이면 15건 검수의 최고 포착률은 42.86%다. 비교용 63건에서도 18건 검수의 상한은 51.43%다. 따라서 결과를 보기 전에 60% 예산을 주목표로 정했다.

KLUE epoch2와 mil3, 근거 집계 6가지, 답변 점수 집계 max/평균/상위10% 토큰 평균을 개발 50건에서 비교했다. 최고 개발 포착률은 60% 검수 기준 71.43%였다. 선택은 epoch2/min2/top10mean. 지표·코드·선택을 ddf9ac6에 커밋한 뒤 이미 노출된 기존 63건을 비교했다.

## 동일 예산 비교 결과

| 검수 예산 | 기존 v2 점수 최대값 순위 | 기존 v3 점수 최대값 순위 | 새 개발 선택 순위 |
|---|---:|---:|---:|
| 30% (18/63건) | 31.43% | 37.14% | 28.57% |
| 50% (31/63건) | 54.29% | 54.29% | 54.29% |
| 60% (37/63건) | 68.57% | 65.71% | 65.71% |

새 선택은 37건을 검수하면 오류 35건 중 23건을 포함하고 12건을 놓친다. 정상 답변 14건도 포함한다. 포착률 65.71%, 검수 정밀도 62.16%, 정상 답변 오경보율 50%다. 같은 예산의 무작위 추출 기대 포착률은 58.73%이다. 기존 v2는 동일 예산에서 24건을 포함한다. 새 설정을 채택할 근거가 없다. 30% 예산에서 새 방식은 무작위 기대 포착률과 같았다.

여기서 기존 v2/v3 기준은 동일 검수량에 맞춘 최대 토큰 점수 순위다. 이전 threshold 0.5 경고 방식의 91.43% 재현율과 직접 같은 조건이 아니다. 비교용 63건은 이미 여러 차례 노출된 개발 자료이며 독립 벤치마크가 아니다. 결과를 본 뒤 설정을 바꾸어 재평가하지 않았다.

## 근거 기반 라벨 수정

1. ASTRA-300-C03-N48-E1 [360,382): “최종 마감일로 명시” 구절을 unsupported → supported로 수정. 실제 제출 종료 시각이 근거에 있으며, 현재 마감일이라는 표현 자체가 영구 고정을 뜻하지 않는다. 메타데이터만으로 고정한다는 다른 오류 주장은 유지했다. 기존 pilot 제출 의견은 원본에 보존하고 변경 전 라벨·의견도 새 기록 안에 남겼다.
2. ASTRA-300-C05-N12-E4: “부품 교체가 없으면 하드웨어 유지관리 범위 밖으로 간주” 구절에 unsupported를 추가. 근거는 부품을 교체할 경우의 조건을 규정하며, 교체가 없으면 범위 밖이라는 주장을 지지하지 않는다. 기존 인용번호 오류와 별도로 처리했다.
3. ASTRA-300-C05-N25-E1: 제안서 평가 불이익 주장은 근거가 없어 기존 unsupported를 유지했다.

수정된 두 레코드는 모두 학습 분할에 있다. 개발/비교 63건 라벨은 변경하지 않았다. 전체 295건을 이번에 다시 승인한 것이 아니며, `agent-revised-labels.json` 안의 수정하지 않은 구절은 원래 상태다. 사람 승인 gold로 부르지 않는다. 원본/v2/v3의 동일 예측을 변경된 두 답변의 구·신 라벨로 각각 재채점하여 라벨 변경 효과를 따로 남겼다. 이 재채점은 모델 개선 점수가 아니다. 이번에는 수정 라벨로 추가 학습하지 않았다.

## 산출물과 검증

- `policy.json`, `selection.json`, `dev-curves.json`: 고정 기준과 36개 개발 설정.
- `comparison.json`, `evaluation-scores.json`: 비교 결과와 답변 우선순위 점수. 점수는 보정된 환각 발생 확률이 아니다.
- `review_queue.json`: 295건의 실험용 검수 순위. train182를 포함하므로 전체 순위를 독립 성능으로 채점하지 않는다. 새 방식은 미채택이다.
- `annotation/revisions.json`, `agent-revised-labels.json`, `paired-relabel-audit.json`: 에이전트 수정과 출처, 동일 모델 재채점.
- `validation.json`: 원본 보존, 295건 순위 중복·누락 없음, 비교 라벨 불변 확인.

입력 무결성 300건 통과, 자동 테스트 42개 통과. 이번 순위 실험은 저장된 KLUE 확률을 재사용하여 GPU 재추론·재학습 없이 실행했다. 다른 모델·RAG·기존 서버는 재실행하거나 중단하지 않았다. 기존 운영 구성과 가중치는 보존했다.
