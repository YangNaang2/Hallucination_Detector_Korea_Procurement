# KLUE 정상 답변 오탐 억제 학습 — v5

## 결과 요약

**실제 GPU 추가 학습 후 정상 답변 오경보는 비교용 63건에서 21건 → 10건으로 줄었다. 환각 답변 탐지는 32건 → 24건으로 줄었다.** 전체 문자 F1은 31.13% → 15.28%로 하락했다. 오탐을 낮추는 운영점은 만들었지만 전반적 성능 향상이나 F1 80% 달성으로 발표하면 안 된다.

정상 오탐률 ≤20%, 환각 답변 재현율 ≥50%라는 사전 성공 기준 중 오탐률 조건을 충족하지 못했다. 현재 .8 설정은 오탐률 35.71%, 재현율 68.57%다. 기존 운영 기본값과 UI는 변경하지 않고 명시적 실험 구성으로 제공한다.

## 동일 63건 비교

| 설정 | 정상 답변 오경보 | 환각 답변 포착 | 답변 정밀도 | 답변 F1 | 문자 F1 |
|---|---:|---:|---:|---:|---:|
| 기존 v3 | 21/28 (75.00%) | 32/35 (91.43%) | 60.38% | 72.73% | 31.13% |
| 오탐 억제 .8 | 10/28 (35.71%) | 24/35 (68.57%) | 70.59% | 69.57% | 15.28% |
| 엄격 .9 | 8/28 (28.57%) | 15/35 (42.86%) | 65.22% | 51.72% | 7.81% |

.8 설정은 TP/FP/FN/TN=24/10/11/18, 답변 accuracy 66.67%다. .9 설정은 15/8/20/20이다. 답변 포착은 정확한 오류 구절 탐지를 보장하지 않는다. strict exact-span F1은 비교용 자료에서 모든 설정이 0이다.

같은 Unicode 평가영역 22,722자, 같은 마스킹 446자, 같은 v1 라벨로 비교했다. 라벨 수정 2건은 학습 분할에만 있으며 비교 라벨은 그대로다. 정상 차단 5건은 기존 별도 검증을 보존하고 탐지 대상에서 제외했다. 모든 수치는 사람 최종 승인 전 에이전트 라벨 기준 잠정 평가다. 비교 63건은 이번 추가 학습에는 넣지 않았지만 이전 실험에 노출된 자료이므로 독립 테스트가 아니다.

## 실제 학습 변경

- v3 mil3 체크포인트에서 시작한 KLUE 단일 모델. XLM-R/BGE-M3/앙상블/규칙 사용 없음.
- 학습 자료 182건만 사용. 이전 v4의 근거 기반 수정 2건을 적용한 라벨 사용. 개발 50건과 비교 63건 라벨 불변 확인.
- 정상 토큰의 오분류 loss에 4배 가중치. 완전 정상 답변의 구간 묶음을 2배 반복.
- 실제 전체 근거 window의 최소 logit으로 BCE 계산. microbatch 4, 상위 6개 층 학습, 학습률 5e-6, seed 916, 3 epoch, 432개 묶음/epoch.
- 가중치와 optimizer/RNG는 별도 work/quality-v5에 저장. epoch 중간에 중단되면 해당 epoch를 다시 수행하며, 완료된 epoch는 건너뛴다.
- 기존 mil3와 새 fp1/fp2/fp3, 집계 6개, 임계값 26개를 개발 자료에서 비교했다. 624개 개발 설정 중 오탐률 ≤20%에서 답변 F1 최대, 동률은 문자 F1으로 선택했다.
- 주 설정 fp1/repeat192/min/.8: 개발 정상 15건 중 FP3, 환각 35건 중 TP21. 선택 커밋 e325d37 이후 비교를 실행했다.
- 부 설정 fp1/min/.9: 개발 오탐 0에서 가장 높은 답변 F1. 개발 TP17/35, FP0/15. 0b0b082에서 비교 전 고정했다. 재현율 50%를 보장하는 설정이 아니다.

## 단순 임계값 조정과 학습 효과 구분

동일 min/.8 기준에서 추가 학습 전 v3는 TP16/FP10, 추가 학습 후 fp1은 **TP24/FP10**이었다. 따라서 동일 오탐 수에서 환각 답변 8건을 더 포착했다. 기존 v3 원래 설정 min2/.5와 비교하면 FP 감소와 함께 재현율도 하락한다. loss 가중치·정상 oversampling·수정 라벨은 함께 적용했으므로 각 요소의 독립 효과까지 입증한 것은 아니다. 고정 ablation은 ablations.json에 남겼으며 그 결과로 추가 설정을 고르지 않았다.

## 학습 자료와 비교 자료의 차이

학습 정상 답변 65건에서 .8은 오탐 1건, .9는 **오탐 0건**이다. 학습 환각 117건에서 .8은 94건, .9는 80건을 포착했다. 엄격 설정으로 이미 학습한 정상 답변을 모두 정상 처리하는 결과는 얻었다.

하지만 비교용 정상 28건에서는 .8이 10건, .9가 8건을 오판했다. 학습 자료의 정상 처리율 100%를 일반 성능으로 발표할 수 없다. 모든 정상 답변을 절대 틀리지 않는 모델은 확보하지 못했다. 개발용 .9 오탐 0건도 비교 자료로 일반화되지 않았다.

## 실행법

저장소 루트에서 기존 학습 환경을 사용한다. 대형 가중치와 private 확률/근거는 Git에 포함하지 않는다.

```bash
PY=/home/piai/바탕화면/ko_lettucedetect/.venv-train/bin/python
$PY procurement-pipeline/klue_fp_train.py train
$PY procurement-pipeline/klue_fp_train.py infer --model fp1 --part train,dev,evaluation
$PY procurement-pipeline/klue_fp_select.py report
$PY procurement-pipeline/klue_fp_strict.py report
$PY procurement-pipeline/klue_fp_validate.py
$PY procurement-pipeline/klue_fp_runtime_check.py
```

새 JSONL 입력은 context/question/answer를 포함한다. .8 구성을 명시해 사용하는 방법:

```bash
$PY procurement-pipeline/klue_quality_predict.py --input work/input.jsonl --output work/output.jsonl --selection project-docs/환각라벨링/detector-300-workstation-v1/results-v5/runtime_selection.json --checkpoint work/quality-v5/checkpoints/fp1
```

.9 설정은 selection 경로를 같은 폴더의 runtime_strict_selection.json으로 바꾼다. 기존 CLI 기본값은 그대로이므로 설정과 체크포인트를 명시해야 한다. 운영 적용 승인이 아니라 재현 가능한 실험 프로파일이다.

작업 브랜치 feature/klue-false-positive-v5. main 자동 병합 없음. 목표 80%는 여전히 미달이며, 추가 성능 개선에는 학습 정상 사례의 암기와 새 문서 일반화를 구분하는 데이터 보강이 필요하다.
