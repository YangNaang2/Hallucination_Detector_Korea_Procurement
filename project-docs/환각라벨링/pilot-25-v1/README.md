# RAG 답변 25개 구절 라벨 초안

기준 실행 커밋 `772bfd5`, 라벨 기준 버전 `pilot-25-v1`, 작성일 2026-09-14.
이 폴더는 **팀 검수용 평가 자료**다. RAG 색인·공개 UI·학습 입력에 자동 투입하지 않는다. 모든 사람 승인은 `pending`, 학습 허용은 `false`다. 기존 실행 파일의 `hallucination_spans: null`과 기존 300문항은 변경하지 않았다.

## 먼저 열 파일

- [검수 시트](검수시트_25개.xlsx): 검수 목록·구절·근거·답변 전문·기준. 노란 입력 칸에 사람 판단을 남긴다.
- [형광펜 미리보기](review.html): 네트워크 없이 열리는 답변 25개와 근거 발췌. 표시 구절에 마우스를 올리면 이유가 나온다.
- [라벨링 기준](GUIDELINES.md): 환각/인용/품질 문제의 구분 및 구절 경계 규칙.
- [기계 판독 초안](labels_draft.jsonl): 원시 답변 해시, 정확한 구절 offset, 원문 근거 및 승인 상태.
- [검증 결과](validation_report.json), [오류 주입 검사](test_report.json).

회사마다 5개, 총 25개를 의도적으로 선정했다. 잘림 4개와 잘못된 인용번호 1개를 모두 포함하고, 정상·부분충족·계산·만료·증빙·서비스 보유 주체 사례를 섞었다. 전체 295개 답변의 오류 비율을 추정하는 표본이 아니다. 이전 train/validation/test 표기는 보존하되 이번 검수에도 노출된 개발 자료로 취급한다.

## 이번에 한 검토

25개 실제 답변과 생성 당시 제공된 청크를 읽고 초안을 작성했다. 청크는 로컬 원본 캐시/회사 JSON 정본과 문자 범위·해시를 대조했다. 근거표는 읽기 편한 발췌이며, 입력 전체는 청크 ID·해시·실행 경로로 복원한다. 모든 HWP/PDF 원본의 표와 페이지를 새로 육안 검증한 것은 아니다. 페이지 번호가 없는 파싱 결과에 페이지를 만들어 붙이지 않았다.

4개 사례에는 입력에서 누락된 참조 자료도 추가했다. `reference_only_not_in_prompt` 표시를 유지하고 생성 모델이 보았던 근거로 계산하지 않는다. 동아보건대 공고의 11:00, 로봇 RFP 대구 본점, C02-P-02 잔여 FTE, C05-P-09 기간제 자료가 해당한다. 추가 참조를 과거 프롬프트에 소급 삽입하지 않는다.

기존 에이전트의 정상/오답 판정은 그대로 참고란에 두었다. 새 구절 판정은 별도다. 예를 들어 공동이행·하도급의 판단이 맞더라도 페이지 위치는 틀릴 수 있고, 산식이 맞아도 요청 숫자를 누락할 수 있다. 기존 정상 판정을 그대로 무환각 정답으로 복사하지 않았다.

## 팀원이 할 일

1. 가능하면 실제 답변과 근거를 먼저 읽고 본인의 구절 판단을 작성한다. 기존 초안에 자동 동의하지 않는다.
2. 구절별 동의/수정/삭제/보류와 이유를 남긴다. 누락 구절은 새 구절로 제안한다.
3. 원문 밖 사실·문서충돌·계산/기간·모호한 반복문은 다른 검수자가 교차 확인한다.
4. 답변 전문 자체를 수정하지 않는다. 수정 라벨은 원래 문자열의 위치에 연결한다.
5. 최종 조정자가 두 판단과 근거를 확인한 뒤 별도 승인본을 만든다. 엑셀의 의견 입력만으로 JSON이 자동 승인되거나 학습 자료로 변환되지 않는다.

명확한 오류가 없는 답변의 빈 `draft_spans`는 에이전트 초안이다. 사람 검수 전에는 정답 음성 샘플이 아니다. `approved_spans`는 검수 완료 전 `null`을 유지한다. 미검수/보류 구절을 O 토큰으로 학습하지 않는다.

## 재현

저장소 루트에서, 기존 로컬 색인과 그 원천 캐시를 사용한다. 생성기에는 추론·DB 적재 기능이 없다.

```text
python procurement-pipeline/build_label_pilot.py --index <index.sqlite> --source-cache <source-texts.json 또는 source-texts.posix.json>
python procurement-pipeline/test_label_pilot.py
```

Linux의 색인 L1 경로가 POSIX로 달라도 텍스트/offset/문서 ID는 동일해야 한다. 회사 문서는 저장소 상대 경로를 사용한다. 엑셀 제작은 bundled Node와 `@oai/artifact-tool`로 `build_label_workbook.mjs`를 실행한다. 패키지는 저장소에 포함하지 않는다. 기존 사람이 입력한 검수 시트는 덮어쓰지 말고 새 버전으로 생성한다.

이후 295개 확대 시 이 기준을 팀이 확정한 뒤 적용한다. 사람 승인된 구절에서만 토크나이저별 BIO/offset 변환을 수행하고, 토크나이저 revision·잘림·윈도우 경계를 기록한다. 모델 훈련·독립 평가·추가 답변 생성은 이번에 하지 않았다.
