# 팀원 4명 배포 자료

대표 답변 25개를 7·6·6·6개로 나눴다. 문항 수뿐 아니라 구절 행 수와 답변 길이를 고려한 작업 배정이며, 회사별 담당 고정이나 검수 소요시간 예측은 아니다.

|---|---:|---:|---|
| 팀원 1 | 7 | 18 | [Excel](T01/팀원1_검수시트_7문항.xlsx) |
| 팀원 2 | 6 | 17 | [Excel](T02/팀원2_검수시트_6문항.xlsx) |

팀장은 저장소 `work/team-review-delivery/`의 팀원별 ZIP을 전달한다. 각 ZIP에는 해당 검수시트, 작업 지시서, 오프라인 질문·답변·전체 입력 근거 HTML, 추가 검수 근거, 필요한 공고 원본과 합성 회사 문서가 들어 있다. 저장소에 커밋한 Excel만 전달하면 전체 입력과 원문을 볼 수 없으므로 **ZIP으로 전달**한다. 원천 공고가 들어 있는 ZIP은 로컬 `work/`에만 두고 Git에는 추가하지 않았다.

- [팀원들에게 보낼 메시지](보낼메시지.txt)
- [정확한 문항 배정](assignments.json)
- [패키지 검증 결과](package_validation.json)
- [Excel 내용 검증 결과](workbook_validation.json)

팀원은 압축 해제 후 `00_작업지시서.html` → `01_검수도움.html` 순으로 읽고 Excel의 노란 칸을 작성한다. 긴 근거는 Excel 행 높이 때문에 일부만 보일 수 있으므로 전체 문맥은 HTML에서 읽는다. 원문 HWP/HWPX는 해당 프로그램이 필요하다. 제출물은 의견을 작성한 Excel 하나이며, 마감은 팀장이 별도로 정한다.

25문항의 중복·누락, 실제 답변 복원과 문자 위치, 청크 해시·정본 위치, 원본 해시, ZIP CRC 및 파일별 해시를 검사했다. 4개 Excel의 6개 시트 미리보기와 입력 칸을 검토했다. 이 검사는 **파일과 배포 자료 검증**이며 사람의 라벨 승인이나 모델 성능 평가가 아니다. 원래 25개 초안과 RAG 결과는 그대로 보존했다. 사람 승인 `pending`, 학습 사용 `false`를 유지한다.

## 재현

저장소 루트에서 다음을 실행한다. 원본 경로는 `source-texts.json` 및 `export/`가 있는 폴더다. 기존 로컬 색인은 읽기 전용으로 사용한다.

```powershell
python procurement-pipeline/validate_team_workbooks.py
python procurement-pipeline/package_team_review.py --source-root "원본이 있는 실제 경로"
```

Excel 재생성은 `build_label_workbook.mjs <저장소절대경로> T01 <T01출력폴더>` 형식으로 T01~T04를 실행한다. `@oai/artifact-tool`을 해석할 수 있는 Node 실행 디렉터리가 필요하다. 기존 25문항 Excel을 덮어쓰지 않는다. 현 런타임은 저장 성공 출력 후 종료 코드 1을 반환했으나, 생성 파일의 ZIP/XML·답변 전문·기대답·문자 위치는 별도 검증을 통과했다.

배포 패키지는 팀 내부 평가용이다. 여러 회사의 L2/L3가 함께 포함되므로 실제 사용자용 공개 화면이나 RAG 입력 폴더로 복사하지 않는다. 팀원 의견을 받은 뒤 수정·삭제·보류·계산·문서충돌 사례를 교차검수하고 최종 라벨을 조정한다.
