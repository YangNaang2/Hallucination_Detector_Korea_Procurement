## 1. 자문이 요구하는 것

### 3단계 로드맵

| 단계 | 내용 |
|---|---|
| **1 · 연구 필요성 검증** | 최신 2B~8B 경량 LLM 비교 → MSDS RAG 환각 발생률 확인 → **zero-shot 환각·근거 지목 성능 측정** |
| **2 · 핵심 기술 개발** | **MSDS 전용 라벨 데이터 구축 [환각 Span ↔ Evidence Span]** → 경량 모델 2개 파인튜닝 → **zero-shot 대비 향상 검증** |
| **3 · 서비스 확장** | 환각 원인 진단 → 검색 실패면 재검색 / 생성 오류면 부분 재생성 / 근거 없음이면 답변 제한 |

### 아키텍처

```
[MSDS 전체]
     ↓
Evidence Retriever
     ↓
관련 문단 Top-k ──┬── LLM 답변
                 ↓
        Fine-tuned 경량 LLM
                 ↓
   ┌─────────────┼─────────────┐
환각 Span    Evidence Span   환각 유형 + 관계 판정
   └─────────────┬─────────────┘
                 ↓
            규칙 기반 진단
     ┌───────────┼───────────┐
 검색 실패    생성 실패    근거 부족
```

### 지금 우리와 다른 네 가지

| | 현재 | 자문 |
|---|---|---|
| 학습 데이터 | RAGTruth 번역본 | **MSDS 전용 직접 구축** |
| 출력 | 환각 Span 하나 | **환각 Span + Evidence Span + 유형** |
| 베이스 | 인코더(RoBERTa·bge-m3) | **경량 LLM 2B~8B 파인튜닝** |
| 비교 기준 | 터키어 선행연구 | **zero-shot 대비 향상** |

## 2. 핵심 판단 — RAGTruth 를 버리지 않는다

자문을 "RAGTruth 를 버리고 새로 만들라"로 읽으면 지금까지 한 일이 전부 죽는다.
그렇게 읽을 필요가 없다. **두 단계 학습으로 엮으면 둘 다 산다.**

```
1차 학습   RAGTruth 한국어 번역본 17,537건   ← 형태를 배운다 (양이 많다)
   ↓
2차 학습   MSDS 전용 라벨 데이터            ← 도메인을 배운다 (질이 맞다)
```

MSDS 전용 데이터만으로는 양이 부족하고, RAGTruth 만으로는 도메인이 어긋난다.
**둘을 이어 붙이는 것이 자연스러운 해법이고, 동시에 진짜 연구 질문이 된다.**

### 이 설계가 만드는 비교 실험

| 조건 | 무엇을 말하는가 |
|---|---|
| A. RAGTruth 만 | 지금까지 한 것. 도메인 이전만으로 얼마나 되나 (**이미 측정: AUROC 0.8140**) |
| B. MSDS 만 | 도메인은 맞지만 양이 적을 때 |
| C. **RAGTruth → MSDS** | 둘을 이어 붙였을 때 |
| D. zero-shot 경량 LLM | 아무것도 학습하지 않았을 때 (자문이 요구한 기준선) |

**D < A·B < C 가 나오면 그것이 이 프로젝트의 결론이다.**
"번역 데이터가 도메인 데이터의 부족을 메운다"는 주장을 실측으로 낼 수 있다.
지금 A 가 이미 측정돼 있으므로 **B·C·D 만 채우면 된다.**

## 3. 새로 만들어야 하는 것

### 3-1. Evidence Span — 가장 중요한 추가

지금 라벨은 **환각 구절 하나뿐**이다. 자문은 **그 구절이 문서의 어느 부분과
어긋나는지**를 함께 표시하라고 한다.

```
답변    측정주기는 12개월이며, 진단주기는 6개월입니다.
환각    [12개월]  [6개월]
근거    문서 15항 "작업환경측정대상물질 (측정주기 : 6개월)"      ← 새로 붙이는 것
        문서 15항 "특수건강진단대상물질 (진단주기 : 12개월)"
관계    값 불일치 (서로 뒤바뀜)
```

**왜 중요한가**

- 출력에 근거가 붙으면 **사용자가 확인할 자리를 바로 연다.** 지금은 밑줄만 긋는다.
- **설명을 생성하지 않고도** "왜 틀렸는지"를 보여줄 수 있다. 원문을 오려 붙이면 된다.
- 유형 판정의 근거가 된다 — 근거가 있는데 값이 다르면 `내용충돌`, 근거 자체가
  없으면 `지어내기`. 지금은 사람이 감으로 유형을 붙이고 있다.

**작업량** — 이미 라벨링된 환각 Span 하나당 근거 구절을 찾아 적는 일이다.
톨루엔 312개 답변에 환각 Span 이 약 100개이므로, 물질을 늘리면 수백~1,000 쌍 규모가 된다.

### 3-2. 3-class 원인 라벨 — 설계 변경이 필요하다

자문의 세 갈래는 이렇다.

| class | 뜻 | 조치 |
|---|---|---|
| 검색 실패 | 엉뚱한 문단을 가져옴 | 재검색 |
| 생성 실패 | 문단은 맞는데 답이 어긋남 | 부분 재생성 |
| 근거 부족 | 문서에 답이 없음 | 답변 제한 |

**지금 승형이 실험에서는 "검색 실패"가 원천적으로 나올 수 없다.**
문서를 프롬프트에 직접 넣었기 때문이다. 이 class 를 만들려면 **검색을 실제로 붙여야 한다.**

다행히 `demo/build_index.py` 와 `Retriever` 가 이미 있다. Top-k 검색을 거치게 하면
"가져온 문단에 답이 있었나"를 기록할 수 있고, 그것이 곧 검색 실패 라벨이 된다.

> 지금까지 검색을 뺀 것은 "눈앞에 두고도 틀렸다"를 보이기 위해서였다.
> 그 실험은 그대로 두고, **검색을 붙인 세트를 하나 더 만든다.** 두 조건의 비교가
> 곧 "검색이 환각에 얼마나 기여하는가"라는 또 하나의 결과가 된다.

### 3-3. zero-shot 기준선

자문 1단계의 요구다. 경량 LLM 에게 파인튜닝 없이 그냥 시킨다.

```
문서와 답변을 준다 → "이 답변에서 문서에 없는 부분을 찾아 표시하라"
```

그 성능이 우리 파인튜닝 모델보다 낮아야 **우리가 한 일에 값어치가 생긴다.**
지금 우리에게는 이 기준선이 없다. 터키어 선행연구와 비교했는데, 그건 다른 언어라
심사자가 받아들이기 어렵다. **zero-shot 대비 향상이 훨씬 설득력 있다.**

### 3-4. 경량 LLM 파인튜닝

인코더(RoBERTa·bge-m3) 대신 2B~8B LLM 을 파인튜닝한다.
A5000 24GB 에서 LoRA 로 가능하다.

**다만 인코더를 버리지 않는다.** 둘의 비교 자체가 결과다.

| | 인코더 (현행) | 경량 LLM (추가) |
|---|---|---|
| 출력 | 토큰별 O/X | Span + Evidence + 유형을 **글로 생성** |
| 속도 | CPU 2~5초 | GPU 필요 |
| 장점 | 싸고 안정적 | **근거와 유형을 함께 낼 수 있다** |

Evidence Span 과 유형을 함께 내려면 생성 모델이 자연스럽다.
인코더로는 "어디"까지만 되고 "무엇과 어긋나는지"는 어렵다.

## 4. "MSDS 하나로 약하다"에 대한 답

### 규모는 이미 밀리지 않는다

다른 팀이 6,000장을 라벨링한다고 들었다. 우리 규모를 세어 보면 이렇다.

| 자산 | 규모 |
|---|---|
| RAGTruth 한국어 번역본 | **17,537건** (직접 번역·검증) |
| MSDS 답변 (사람 1 + 모델 6) | 364건 · 물질 1종 |
| 물질 5종으로 늘리면 | **약 1,800건** |
| 환각 Span | 물질 5종 기준 **500~700개** |
| Evidence Span 쌍 | 같은 규모 |

**규모가 문제가 아니라 "우리가 만든 것"이 안 보이는 것이 문제였다.**
번역본 17,537건은 우리가 만든 것인데 지금 발표에서 "RAGTruth 를 썼다"로만 읽힌다.
MSDS 전용 라벨이 생기면 **명백히 우리 것인 데이터**가 앞에 선다.

### 도메인을 넓히는 방향

MSDS 하나가 얇다면 **같은 성격의 문서를 하나 더** 붙인다.
성격이 같아야 라벨링 기준을 재사용할 수 있다.

| 후보 | 판정 명확성 | 확보 | 비고 |
|---|---|---|---|
| **MSDS** (유지) | 16개 항목 법정 고정 | 공개 API | 이미 진행 |
| **산업안전보건 법령·고시** | 조문 단위로 명확 | 국가법령정보센터 | **자문이 말한 "법"에 해당.** MSDS 작성 근거라 문맥이 이어진다 |
| 의약품 허가사항 | 항목 표준화 | 식약처 공개 | 성격이 MSDS 와 가장 비슷 |
| 학사요람 (보유) | 보통 | 있음 | **도메인 대조군**으로만 |

**권고 — MSDS + 산업안전보건 법령.** 둘이 한 묶음이라 "화학물질 안전 분야"라는
하나의 도메인이 되고, 승형이가 지적한 대로 법령에는 *"다만 ~인 경우에는 그러하지
아니하다"* 가 많아 **의무·예외 유형을 보강**할 수 있다. 지금 그 유형이 3개뿐이라
판단이 불가능한 상태다.

학사요람은 버리지 말고 **도메인 대조군**으로 남긴다. "성격이 다른 문서에서도
되는가"에 답하는 유일한 재료다.

## 5. CPU 제약을 푸는 문제

지금 덱에는 "노트북 CPU 에서 2~5초"가 목표 사양으로 박혀 있다.
경량 LLM 을 쓰면 이 조건이 깨진다.

**두 갈래를 모두 살리는 것이 맞다.**

| 갈래 | 모델 | 내는 것 | 어디에 |
|---|---|---|---|
| **가벼운 쪽** | 인코더 (klue 1.1억) | 환각 Span | 실시간·현장·CPU 데모 |
| **정확한 쪽** | 경량 LLM 파인튜닝 | Span + Evidence + 유형 + 원인 | 정밀 진단·서버 |

이렇게 두면 "CPU 로도 된다"는 강점을 버리지 않으면서 자문의 요구도 채운다.
그리고 **두 갈래의 성능 차이 자체가 결과가 된다** — "가볍게 하면 얼마를 잃는가".

## 6. 남은 일정과 우선순위

| 순위 | 일 | 담당 | 비고 |
|---|---|---|---|
| **1** | **zero-shot 기준선 측정** | 검증 모델 | 이게 없으면 우리 기여를 말할 수 없다. 데이터가 이미 있어 바로 가능 |
| **2** | **Evidence Span 라벨링** | 평가 파트 + 라벨러 | 기존 환각 Span 에 근거 구절을 붙이는 일 |
| **3** | 물질·법령 문서 확대 | 평가 파트 | 의무·예외 유형 보강 포함 |
| **4** | 검색을 붙인 세트 생성 | 데모 파트 | 3-class 중 "검색 실패"를 만들기 위해 |
| **5** | 경량 LLM 파인튜닝 (LoRA) | 검증 모델 | 2개 모델 |
| **6** | 두 단계 학습 비교 (A/B/C/D) | 검증 모델 | 최종 결과표 |
| 7 | 규칙 기반 원인 진단 | 검증 모델 | 자문 3단계. 시간이 남으면 |

**1번을 먼저 하는 이유** — 기준선이 없으면 나중에 어떤 숫자가 나와도
"그래서 좋아진 건가"에 답할 수 없다. 그리고 지금 있는 데이터로 바로 잴 수 있다.

## 7. 이렇게 하면 무엇이 달라지나

**발표에서 할 수 있는 말이 바뀐다.**

| 지금 | 확대 후 |
|---|---|
| 공개 데이터를 번역해 모델을 학습시켰다 | **화학물질 안전 분야 전용 환각 탐지 데이터를 직접 구축했다** |
| 환각 구절에 밑줄을 긋는다 | **환각 구절과 그 근거를 짝지어 보여주고, 원인을 나눠 조치를 제안한다** |
| 터키어 연구보다 높다 | **아무 학습 없이 쓸 때보다 이만큼 좋아진다** |
| 도메인 하나에서 쟀다 | **두 도메인에서 재고, 데이터를 이어 붙이면 얼마나 나아지는지 보였다** |

옆 조(수학 풀이 검증)와 겹칠 여지도 사라진다. 우리는 **정답이 없는 문서 기반
문제**에서 **근거를 짝지어 찾는** 일을 하고, 그 데이터를 직접 만든다.
