# 나라장터 × 환각 탐지 — 문제정의 1차 리서치 및 후속 조사 지시서

조사일: 2026-09-10  
대상: B1조 문제상황·추진배경 조사 담당  
검토 자료: 프로젝트 폴더의 `Finding_Hallucination.html`, 조달청·공공데이터포털·ACL·NIST 자료, 서비스 제공사 소개 페이지

## 1. 이번 리서치의 결론

새 주제는 **“입찰 담당자가 공고 조건과 회사 자료를 대조할 때, AI 답변의 의심 구절과 근거를 확인하도록 돕는 입찰 검토 시스템”**으로 설명하는 것이 좋다.

기존 질문은 “AI 답변에서 어디가 환각인가?”였다. 확장된 질문은 “선택한 공고의 올바른 버전과 열람 가능한 자료를 기준으로 답했는가? 담당자는 의심 구절의 근거를 확인할 수 있는가?”다.

추천하는 추진배경의 우선순위:

1. **문서·조건 대조:** 공고 요건을 찾는 것과 우리 회사의 충족 여부를 확인하는 것은 다르다.
2. **정정·예외 누락:** 실제 문장이라도 다른 공고나 이전 버전의 조건이면 잘못된 판단으로 이어질 수 있다.
3. **AI 답변의 검토:** 문서를 제공해도 근거와 불일치하는 답변이 나올 수 있다.
4. **내부 자료의 접근 제어:** 회사 실적·인력·원가를 함께 사용할 때는 사용자에게 허용된 자료만 처리해야 한다.

이 중 1·2를 새로운 업무 문제로 앞에 놓고, 기존 환각 탐지를 3의 해결 요소로 연결한다. 4는 내부 자료를 실제 범위에 포함하는 경우의 추가 요구다.

## 2. 근거의 상태를 구분하는 규칙

| 표시 | 의미 | 발표에서의 사용 |
|---|---|---|
| 공식 확인 | 정부 안내·공식 공고·논문에서 확인한 사실 | 해당 출처와 적용 범위를 붙여 사용 |
| 제공사 설명 | 서비스 사업자가 자사 기능으로 설명 | “제공한다고 소개한다”로 표현. 실제 성능 검증 아님 |
| 연구 가설 | 우리 팀이 가능성을 제안 | 조사·실험으로 검증할 내용으로 표시 |
| 가상 시나리오 | 데모용 회사·수치·답변 | 실제 사고나 실제 고객 사례로 소개하지 않음 |

아직 확인하지 못한 것: 국내 입찰 담당자의 평균 문서 검토 시간, 조건 누락률, AI 사용 중 오류 경험률, AI 오류 때문에 생긴 실제 입찰 손실액. 이를 임의 숫자로 채우지 않는다.

## 3. 기존 발표에서 유지·교체·보완할 내용

실제 HTML의 제목과 본문을 확인했다. 파일 내 슬라이드 번호가 변경 이력과 섞여 있으므로 아래는 제목으로 식별한다.

| 기존 슬라이드 | 제안 |
|---|---|
| 환각이 허용되지 않는 문서 — MSDS | 입찰 담당자의 실제 업무 상황으로 교체 |
| 문서가 있어도 지어내는 LLM | 기존 MSDS 실험으로 유지 가능. 나라장터 실측 결과로 해석하지 않기 |
| 선행 연구 사례 | 기술적 배경으로 유지하되 연구의 데이터·조건 명시 |
| 아직 해결되지 않은 네 가지 | 범용 AI 주장보다 문서 대조·정정·예외·근거 추적으로 재구성 |
| 토큰 단위 환각 판정 / 학습 과정 | 기존 코어 기술 설명으로 유지 |
| 검증 대상 RAG 시스템 구성 | 공고·버전 필터, 인가 자료 검색, 답변 검토, 원문 연결을 반영 |
| 현재 진행 상황 및 향후 계획 | 2026년 5월 자료 확보, 4·6월 수집 중, 실제 데이터 연동 예정으로 갱신 |

함께 정정할 표현:

- “한국어 자료 0건”은 조사 범위가 제시되지 않으면 단정하지 않는다.
- “모델 크기로 해결되지 않는다”는 일부 MSDS 실험만으로 입증되지 않는다.
- “재순위화·벡터 검색 라이브러리를 쓰면 CPU 시연 불가능”은 일반적으로 성립하지 않는다. 필요성은 실제 검색 품질·지연으로 판단한다.
- “중요 자료는 모두 외부 반출 불가능” 대신 “자료와 조직 정책에 따라 외부 서비스 사용이 제한될 수 있다”.
- “구절을 탐지하면 이유와 정답 근거도 자동으로 나온다”는 설명은 피한다. 탐지와 근거 연결은 별도 기능이다.
- 이번 조사에서는 발표 HTML 자체를 수정하지 않았다.

## 4. 추가 문제상황과 조사할 근거

### A. 공고 하나를 검토하려면 여러 조건을 함께 확인해야 한다

**공식 확인:** 조달청 용역 총액계약 안내에는 과업내용서·예산·납기·특수조건 등을 포함한 요청과 제안서·가격 평가 절차가 설명되어 있다. 공공데이터포털 API도 공고 상세 외에 면허·지역 제한과 변경 이력을 제공한다. 이는 검토 대상이 단일 제목·키워드를 넘어선다는 근거다. [조달청 용역 총액계약](https://www.pps.go.kr/kor/content.do?key=00726), [입찰공고정보서비스](https://www.data.go.kr/data/15129394/openapi.do)

**연구 가설:** 담당자가 여러 문서에서 조건을 모아 회사 자료와 대조하는 과정에 시간이 들고 누락 가능성이 있다. 공식 문서의 구조만으로 그 시간이나 오류 빈도를 입증한 것은 아니다.

**추가 조사:** 5월 공고 10건을 선정해 자격·일정·평가·제출서류의 근거가 각각 어느 파일·조항에 있는지 기록한다. 기본 공고만으로 답할 수 있는 질문과 첨부가 필요한 질문을 구분한다.

**발표 문장 후보:** “입찰 검토는 공고를 찾는 데서 끝나지 않습니다. 참가 자격·제출 일정·평가 조건을 확인하고 회사 자료와 대조해야 합니다.”

### B. 정정공고는 같은 문서의 단순 중복이 아니다

**공식 사례:** 나라장터 공고 `R26BK01336025`, 차수 `001`, 「2026년 김포 덕포진 역사문화체험관 디지털컨텐츠 제작·설치」에는 업종코드가 1468에서 1469로 바뀐 정정 내용과 일정 변경 안내가 있다. 이 자료는 **3월 사례**이며 팀의 5월 수집분에서 발견한 사례가 아니다. 정정 내용은 PDF 뷰어 기준 첫 페이지에 있다. [나라장터 공식 공고 PDF](https://www.g2b.go.kr/pn/pnp/pnpe/UntyAtchFile/downloadFile.do?bidPbancNo=R26BK01336025&bidPbancOrd=001&fileSeq=1&fileType=&prcmBsneSeCd=03)

**연구 가설:** 이전 버전의 조건을 검색하면 생성 모델이 그 내용을 충실히 답해도 업무상 오답이 된다. 이는 환각 탐지기만으로 해결되지 않을 수 있다.

**추가 조사:** 5월 자료에서 원공고·정정공고 쌍 2개 이상을 찾아 변경된 문장, 공고번호·차수, 변경 시점과 적용 기준을 기록한다. 없으면 없다고 보고하고 외부 사례와 분리한다.

**발표 문장 후보:** “원문에 있는 내용이라도, 지금 검토하는 공고의 유효한 조건인지 확인해야 합니다.”

### C. 한 가지 요건의 충족과 전체 참가 가능 여부는 다르다

**공식 확인:** 위 공고에는 복수 참가 자격을 함께 요구하는 조항과 별도의 공동수급협정 제출 조건이 있다. 단일 수치 하나만으로 참여 가능 여부를 판단하는 예시는 실제 검토를 단순화한 것이다. 위 PDF의 참가 자격·공동계약 항목 참조.

**가상 시나리오:** 회사가 실적 요건은 충족했지만 요구되는 등록·증빙은 확인되지 않았다. AI가 “참여 가능합니다”라고 종합 결론을 내리는 상황을 시험한다. 가상 회사와 잘못된 AI 답변은 팀이 제작한 테스트 사례다.

**추가 조사:** AND/OR 조건, 단일/누적 실적, 기준 기간, 공동수급 예외, 증빙 유효기간 중 실제 공고에서 확인 가능한 3종을 선정한다. 모든 공고에 동일한 조건이 적용된다고 가정하지 않는다.

**발표 문장 후보:** “조건 하나를 찾는 것과 모든 요건을 충족하는지 판단하는 것은 다릅니다.”

### D. RAG 답변도 검토 대상이다

**논문 확인:** RAGTruth는 검색 문맥을 제공해도 근거가 없거나 문맥과 모순되는 주장이 생성될 수 있음을 다룬다. 그러나 그 결과는 나라장터의 특정 환각률을 의미하지 않는다. [RAGTruth, ACL 2024](https://aclanthology.org/2024.acl-long.585/)

**추가 조사:** 실제 공고 근거를 고정한 질문 30개를 만들고, 자연 생성 답변을 사람이 대조한다. 인위적으로 바꾼 답변은 별도 도전 세트로 관리한다. 정상 답변과 답변 보류도 빠뜨리지 않는다.

**차별화할 평가:** 수치 변경, 다른 공고의 조건 혼입, 예외 누락, 확인되지 않은 종합 결론을 구분한다. 문서에 똑같은 단어가 없다는 이유만으로 환각으로 표시하지 않는다. 의미상 지지되는 바꿔쓰기는 정상이다.

**발표 문장 후보:** “답변을 제공하는 것에 더해, 검토가 필요한 구절을 원문과 대조할 수 있도록 합니다.”

### E. 회사 자료를 넣는 순간 접근 권한이라는 문제가 생긴다

**공식 배경:** NIST의 생성형 AI 위험 프로파일은 잘못된 내용 생성과 데이터 프라이버시, 사람의 과신 등을 구분해 다룬다. 이는 정확성과 정보 노출을 별개로 관리할 근거이지, 나라장터에 L1~L3 제도를 의무 적용하라는 규정은 아니다. [NIST AI 600-1, 2024-07-26](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)

**설계 제안:** 공개 공고와 사내 실적·원가를 함께 쓰는 시나리오에서, 사용자에게 허용된 자료만 검색·답변·원문 열람에 사용하도록 한다.

**추가 조사:** 실제 현업에서는 어떤 자료를 어떤 역할이 열람하는지 인터뷰한다. L1 공개 / L2 사내 / L3 제한은 우리 데모의 예시 등급으로 표시한다. 회사 직급과 국가 비밀취급인가를 동일시하지 않는다.

**발표 문장 후보:** “답변이 정확한지뿐 아니라, 그 답변에 사용한 자료를 해당 사용자가 볼 수 있는지도 확인해야 합니다.”

공개 공고를 사용한다는 이유만으로 폐쇄망이 필수인 것은 아니다. 내부 자료 보호와 운영 정책이 로컬 배포를 선택하는 근거가 되어야 한다. 로컬 GPU도 가능한 선택이다.

## 5. 시장 조사에서 발견한 중요한 반례

“입찰 AI가 없다”, “원문을 보여주는 서비스가 없다”를 추진배경으로 삼지 않는다.

| 대상 | 이번에 확인한 내용 | 후속 확인 |
|---|---|---|
| 조달청 공공조달 길잡이 | 전문가 컨설팅을 안내하며, 게시판에는 2026-06-15자 챗봇 이용 안내도 있다 | 챗봇의 답변 범위·출처·개별 공고 검토 가능 여부 확인 |
| 비드라온 | 자사 소개에서 공고 분석·회사 자격 매칭·원문 페이지/조항 하이라이트 연결을 설명 | 실제 데모에서 답변의 오류 구절을 별도로 판정하는지 확인 |
| 체크아이 | RFP 기반 제안서 검수 서비스로 소개 | 요구사항 누락 검수와 생성 답변 환각 판정의 범위 차이 확인 |

출처: [공공조달 길잡이](https://www.pps.go.kr/kor/bbs/list.do?key=01325), [비드라온 공식 소개](https://bidraon.ai/), [체크아이 공식 소개](https://checkai.co.kr/).

사업자 사이트는 **기능에 관한 자기 설명**이다. 소개에 없는 기능은 “미제공”이 아니라 “확인 안 됨”으로 기록한다. 성능·보안·고객 효과는 이번 조사에서 독립 검증하지 않았다.

우리 팀의 차별화 후보는 **“선정 공고와 회사 자료에 대한 구절 검증·근거 추적·권한 처리를 한 흐름으로 구성하고, 실패 유형별로 직접 평가한다”**다. 독창성이나 우월성이 입증되었다는 주장은 아니다.

## 6. 발표 앞부분 구성안

### 슬라이드 1 — 입찰 담당자의 검토 업무

상황: 5월 공고를 검토하는 제안 PM. 공고의 참가 조건을 찾고 회사 실적·인력 자료와 대조해야 한다.

화면: 공고문 → 제안요청서 → 회사 자료의 세 문서. 가운데 질문 “우리 회사가 이 공고에 참여할 수 있을까?”

사용자상은 가설이다. 현업 인터뷰를 하면 실제 표현으로 갱신한다.

### 슬라이드 2 — 정정·예외가 바꾸는 판단

화면: 공식 정정공고의 변경 부분 캡처 1개. 원공고와 정정공고의 차이를 표시한다.

메시지: “공고의 버전과 조건을 구분하지 않으면 다른 기준으로 검토하게 됩니다.”

외부 3월 사례인지 자체 5월 수집 사례인지 반드시 표시한다. 실제 사례를 AI 오류 발생 사례로 둔갑시키지 않는다.

### 슬라이드 3 — AI 답변에도 필요한 원문 검토

화면: 공고의 실제 조건, 가상으로 잘못 작성한 답변, 원문 연결을 나란히 배치.

메시지: “의심 구절을 표시하고 근거로 돌아갈 수 있어야 합니다.”

기존 MSDS 실험을 넣는다면 기술 검증 이력으로만 짧게 소개한다. 나라장터에서도 같은 성능이라고 말하지 않는다.

### 슬라이드 4 — 우리의 범위와 검증 목표

화면: 허용 문서 검색 → 답변 생성 → 의심 구절 표시 → 원문 대조.

메시지: “담당자의 검토를 돕고, 자료가 부족하면 판단을 보류합니다.”

낙찰률 향상·자동 참가 자격 확정·환각 0%는 실증 전 목표나 성과로 제시하지 않는다.

## 7. 팀원에게 맡길 후속 조사 — 한 사람이 시작할 수 있는 분량

권장 기한: **착수 다음 날 1차 자료 제출**, 인터뷰는 가능 일정에 따라 별도 갱신. 팀 합의 전 확정 마감이 아니다.

| 우선순위 | 할 일 | 분량 | 제출물·완료 기준 |
|---|---|---|---|
| P0 | 5월 공고에서 검토가 복잡한 실제 사례 찾기 | 공고 10건 확인, 대표 사례 3건 | 공고 ID·차수·파일·페이지/조항·내용·왜 어려운지·캡처. AI가 틀렸다고 단정하지 않기 |
| P0 | 공식 출처 확인 | 핵심 주장 3개 | 출처 제목·기관·발행일 또는 미표시·URL·확인일·주장 범위·원문 위치 |
| P1 | 기존 서비스 비교 | 위 3곳 | 검색/회사대조/답변생성/오류구절/원문연결/권한 항목별 제공사 설명 또는 직접 관찰 기록 |
| P1 | 발표 초안 작성 | 3~4장, 장당 핵심 문장 1개 | 실제 근거와 가상 예시를 표시한 문안·캡처 |
| P2 | 현업 의견 수집 | 가능하면 2명, 각 15~20분 | 익명 요약과 실제 불편. 만날 수 없다면 미실시라고 기록 |

대표 사례 3건은 가능하면 다음 조합으로 고른다: 정정·버전 변경 1건, 여러 문서의 조건 대조 1건, 예외·복수 요건 1건. 한 사례에 겹쳐도 되지만 서로 다른 사례인 것처럼 중복 집계하지 않는다.

인터뷰 질문:

1. 최근 공고 하나를 검토할 때 어떤 파일을 어떤 순서로 보았나요?
2. 참가 여부를 검토하려면 어떤 회사 자료가 필요했나요?
3. 조건·예외·변경 사항을 다시 확인했던 사례가 있나요? 실제 불이익과 단순 우려를 구분해 주세요.
4. 이미 쓰는 검색·입찰 분석 도구와 부족한 점은 무엇인가요?
5. AI의 결론, 원문 링크, 조건별 체크리스트 중 무엇이 검토에 도움이 되나요?
6. 외부 AI에 넣기 곤란한 자료가 있나요? 그 이유는 조직 정책인가요, 개인정보인가요, 다른 이유인가요?

질문에서 “기존 방식이 불편하죠?”처럼 답을 유도하지 않는다. 공개가 곤란한 실적·금액·개인정보를 제출받을 필요는 없다.

## 8. 이번 수집 데이터로 직접 만들면 좋은 근거

5월 자료 점검에서 아래 수치를 산출하면 외부의 거대한 시장 규모보다 프로젝트 필요성과 직접 연결된다.

- 중복·정정 버전을 구분한 고유 공고 수와 공사/물품/용역 구성.
- 공고당 사용 문서 수·페이지 수의 중앙값과 범위. 추출 실패·누락 건은 따로 보고.
- 원공고·정정공고가 함께 존재한 공고 수. 분모와 수집 범위 표시.
- 질문 30개 중 공고 본문만으로 답할 수 있는 수, 첨부 또는 복수 문서가 필요한 수, 답을 알 수 없는 수.
- 사람이 근거를 찾는 시간과 UI 사용 시 시간. 같은 문제를 반복해서 푸는 학습 효과를 피하도록 서로 다른 동등 난이도 문제를 교차 배정.

이 수치는 우리 표본의 관측 결과다. 한국 입찰 시장 전체나 모든 담당자에게 일반화하지 않는다.

후속 모델 평가는 검색의 정답 근거 회수율, 답변 오류, 탐지기의 놓침·오탐, 원문 연결 정확도, 권한 위반 노출을 나누어 측정한다. 정정본·같은 공고의 청크·유사한 합성 답변이 학습과 평가에 섞이지 않도록 공고 단위로 분리한다.

## 9. 카카오톡 전달용

> 이번 조사에서는 ‘환각은 위험하다’보다 ‘나라장터 입찰 담당자가 어떤 검토에서 어려움을 겪는지’를 찾아줘.
>
> ① 5월 공고 10건 정도를 보고, 여러 문서를 대조해야 하거나 정정·예외 조건 때문에 주의가 필요한 실제 사례 3건을 골라줘. 공고번호/차수, 파일명, 페이지나 조항, 캡처, 왜 어려운지까지 부탁해.
>
> ② 조달청 공식 자료로 추진배경을 뒷받침할 주장 3개를 정리해줘. 평균 몇 시간 걸린다거나 오류가 몇 %라는 수치는 확인된 자료가 있을 때만 써줘.
>
> ③ 공공조달 길잡이 챗봇, 비드라온, 체크아이를 비교해줘. 특히 원문 연결과 오류 구절 판정이 어떻게 다른지 봐줘. 소개에 안 나온 기능은 ‘없음’ 대신 ‘확인 안 됨’으로 적어줘.
>
> ④ 최종 제출은 조사 메모 + 사례 캡처 3개 + 발표 앞부분 3~4장 문안이면 돼. 먼저 착수 다음 날까지 확보한 내용으로 1차 공유하고, 인터뷰 가능 여부도 알려줘.
>
> 우리 목표는 자동 낙찰이나 자격 확정이 아니라, 담당자가 AI 답변을 원문과 대조하도록 돕는 시스템이야. 실제 공고와 가상 회사·답변은 구분해서 표시해줘.
