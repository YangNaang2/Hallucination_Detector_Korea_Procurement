# 팀원별 요건 추출 지시서 (표본 51건)

작성 2026-09-12. 기한 **9/15(월) 24:00**. 제출: `요건추출시트.csv` 자기 행만 채워 팀 드라이브 `제출/팀원N/` 에 올린다.

자료: 팀 드라이브 `표본_정보시스템_51건.zip` (풀면 공고번호별 폴더). 각 폴더 안 `원본/` 이 첨부 원본, `텍스트/` 가 같은 문서의 텍스트(HWP가 안 열릴 때), `공고정보.json` 이 공고 메타데이터.


## 공통 작업 순서 (공고 1건당 30분)

1. `배분표.csv` 에서 자기 공고를 확인한다. 아래 자기 절에 공고마다 **열어야 할 파일**이 적혀 있다. 그 파일만 연다. 내역서·서식·계약예규·상생결제 안내는 읽지 않는다.
2. **공고문**을 먼저 읽는다. 참가자격, 기초금액(예산), 입찰·개찰 일시, 공동수급·하도급 허용 여부, 지역 제한이 보통 앞 두 쪽에 있다.
3. **제안요청서(또는 과업지시서)** 를 읽는다. 사업 개요(사업비·기간), 제안사 자격·실적 요건, 투입 인력 요구, 인증 요구, 평가 배점표, 보안 요구를 찾는다. 요구사항 표(MPR-001 같은 번호)가 길면 "인력", "실적", "인증", "평가", "보안" 항목만 찾아 읽는다.
4. `요건추출시트.csv` 의 자기 행 10칸을 채운다. 열별 작성법은 `요건추출_작성요령.md`. 아래 예시 행을 참고한다.
5. 근거문서_쪽수 열에 어느 문서 몇 쪽(또는 몇 항)에서 봤는지 적는다. 나중에 답변의 근거를 확인할 때 쓴다.

## 원칙

- 문서에 적힌 대로만. 추측·요약하지 않는다. 없으면 `없음`, 못 찾았으면 `미확인`.
- 숫자는 원문 표기 그대로 (`58,000,000원(부가가치세 포함)` 처럼). 단위를 바꾸지 않는다.
- 공고문과 제안요청서의 숫자가 다르면 둘 다 적고 검토메모에 표시한다. 이런 곳이 나중에 환각 유도에 가장 좋은 재료다.
- 한 칸에 여러 항목은 `;` 로 구분.
- HWP가 열리지 않으면 `텍스트/<같은 파일명>.jsonl` 을 메모장으로 연다. 한 줄이 한 구간이고 `text` 값이 본문이다.
