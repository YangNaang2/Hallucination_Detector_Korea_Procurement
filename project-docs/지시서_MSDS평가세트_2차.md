담당: 박승형 (평가·페르소나 파트) · 작성 2026-09-08 · 대상 `msds.zip` v0.2

## 1. 검수 결과 — 통과

52문항을 자동 검사와 수동 확인으로 모두 살펴봤다. **구조 결함 0건이며, 그대로 평가에 투입한다.**

| 검사 항목 | 결과 |
|---|---|
| JSON 파싱 · id 중복 | 52줄 전부 정상 |
| `<HAL>` 태그 짝 | 40쌍 전부 일치 |
| 태그 제거 후 `answer` 와 일치 | 전부 일치 — **문자 오프셋 복원 가능** |
| `hall_spans` 와 태그 내용 일치 | 전부 일치 |
| 스팬이 `answer` 안에서 검색됨 | 전부 검색됨 |
| 정답 22건 스팬 0 / 환각 30건 스팬 보유 | 라벨 일관 |
| `context` 공백 | 없음 (최소 77자 · 평균 667자) |

자동 검사가 의심으로 올린 **MSDS-048은 확인 결과 정상이며, 오히려 가장 잘 만든 문항 축에 든다.** 문서의 측정주기 6개월과 진단주기 12개월을 서로 맞바꾼 것인데, 두 숫자가 모두 문서 안에 있으므로 **단어만 대조하는 모델은 이것을 반드시 놓친다.** 관계를 보는지 재는 문항이다.

MSDS-013과 MSDS-021도 원문과 대조했다. 013은 표시하지 않은 첫 문장이 문서 원문과 글자 그대로 같았고, 021은 국내 TWA 50ppm과 ACGIH 20ppm을 정확히 뒤바꾼 것이 맞았다. **라벨이 정확하다.**

### 특히 잘한 것

**정답 22건을 넣은 것.** 요청하지 않은 부분이다. 이것이 없으면 "모든 문장에 형광펜을 칠하는 모델"과 제대로 된 모델을 구별할 수 없다. 탐지율만 재면 아무 의미가 없고 오탐률과 같이 봐야 한다는 것을 스스로 짚었다.

**안전 원칙.** 응급조치·소화·누출대처 항목에서 행동 지시 자체는 뒤집지 않았고, 초안에 있던 세척 시간·해독제 문항 2건을 그 원칙에 따라 삭제했다고 밝혔다. 평가 데이터가 그대로 유출돼도 위험하지 않다.

**교차형 3문항(50·51·52).** 에탄올 인화점 13℃는 사실로는 맞지만 톨루엔 문서에는 없는 값이다. 이 프로젝트의 판정 기준이 **"사실인가"가 아니라 "이 문서에 있는가"** 라는 점이 그대로 문항이 됐다.

**한계를 먼저 밝힌 것.** 도메인 밖 데이터라 탐지율이 낮게 나오는 것이 예상 범위라고 README에 적었다. 결과가 나쁘게 나와도 설명할 수 있는 상태를 미리 만들어 둔 셈이다.

## 2. 확인이 필요한 것 하나 — 임계값

README 7절의 **"임계값 0.35 고정"** 의 근거를 알려 달라.

우리가 교차적합(cross-fitting)으로 낸 값은 다음과 같다.

| 모델 | 최적 임계값 | 비고 |
|---|---|---|
| `klue/roberta-base` | **0.5** | 이미 최적이라 조정 이득 없음 |
| `xlm-roberta-base` | 0.268 | 조정 시 +0.0133 |
| `bge-m3` | 과제별 튜닝 | 대표 모델 |

**임계값을 평가 세트에서 고르면 그 숫자는 부풀려진다.** 같은 데이터에서 기준을 정하고 그 데이터로 채점하는 셈이기 때문이다. 학습 쪽에서 정한 값을 그대로 가져와 고정해야 한다. 어느 모델로 돌릴지 정해지면 그 값을 알려 주겠다.

## 3. 이 세트의 위치 — 오해가 없도록

이 세트는 **사람이 답변을 쓰고 환각을 의도적으로 심은 것**이고, 원래 계획한 평가②는 **챗봇이 실제로 낸 답변을 사람이 라벨링하는 것**이다. **두 가지는 재는 대상이 다르다.**

| | 이 세트 | 챗봇 답변 라벨링 |
|---|---|---|
| 환각의 출처 | 사람이 설계해 심음 | 모델이 실제로 냄 |
| 강점 | **유형별로 분해 가능** — 어떤 종류를 못 잡는지 나온다 | 실제 분포 그대로 |
| 약점 | 사람이 만든 환각은 모델의 실제 실수와 다르다 | 유형이 골고루 나오지 않는다 |
| 발표에서 부를 이름 | **통제된 진단 세트에서의 유형별 탐지율** | **실제 문서에서의 성능** |

**둘 다 한다.** 이 세트의 숫자를 "실제 문서에서의 성능"이라고 쓰면 과장이 되므로 이름을 구분해서 쓴다. 대신 이 세트 덕분에 **라벨러 2명을 기다리지 않고 먼저 숫자를 낼 수 있게 됐다.** 일정상 큰 이득이다.

## 4. 2차 작업 지시

우선순위 순이다. **시간이 부족하면 아래쪽부터 버린다.**

### 작업 1 — 물질 2종 추가 (자일렌 · 메탄올)

| 항목 | 내용 |
|---|---|
| 담당 | 박승형 |
| 분량 | 물질당 25~30문항 · 총 50~60문항 |
| 기한 | **9월 12일(금)** |
| 소요 | 물질당 반나절 |
| 제출물 | `examples_msds_자일렌.jsonl` · `examples_msds_메탄올.jsonl` · 각 `chunks_*.json` · **원문 PDF 또는 텍스트** |

**왜 필요한가.** 톨루엔 하나로 낸 숫자는 "그 문서 하나에서만 되는 것 아니냐"는 질문에 답할 수 없다. 물질이 셋이 되면 **물질 간 성능 차이**를 볼 수 있고, 그것이 곧 도메인 일반화의 근거가 된다. 교차형 문항도 진짜로 성립한다 — 지금은 톨루엔 문서에 에탄올을 묻는 형태지만, 세 물질이 있으면 **우리가 가진 다른 문서의 물질**을 물을 수 있다.

**반드시 지킬 것**

- **id에 물질 코드를 넣는다.** 지금은 `MSDS-001`~`MSDS-052` 인데 새 파일도 같은 번호로 시작하면 합칠 때 충돌한다. **`TOL-001` · `XYL-001` · `MEO-001`** 형태로 바꿔 달라. 톨루엔 파일도 같이 고쳐 주면 좋겠다.
- **스키마를 바꾸지 않는다.** 필드 이름과 구조를 v0.2 그대로 유지한다. 검사 스크립트가 그 스키마를 전제로 돌아간다.
- **정답(환각 없음) 비율을 40% 이상 유지한다.** 오탐을 재는 대조군이다. 톨루엔은 22/52 = 42%였다.
- **안전 원칙을 그대로 유지한다.** 응급조치·소화·누출대처의 행동 지시는 뒤집지 않는다. 메탄올은 실명 위험이 있어 특히 조심할 것.
- **조각을 고르게 쓴다.** 톨루엔에서는 9번(10건)과 8번(8건) 두 조각에 문항의 3분의 1이 몰렸고 16번은 쓰이지 않았다. 조각당 최대 4문항을 넘기지 않는 쪽으로 분산해 달라.

### 작업 2 — 얇은 유형 보강

| 항목 | 내용 |
|---|---|
| 담당 | 박승형 |
| 분량 | 의무예외 · 과일반화를 **각각 8문항 이상**으로 |
| 기한 | 9월 12일(금) · 작업 1과 함께 |
| 제출물 | 작업 1의 파일에 포함 |

**왜 필요한가.** 지금 의무예외 3개, 과일반화 4개다. 이 숫자로는 "이 유형을 못 잡는다"고 말할 수 없다 — 두세 개 틀리면 탐지율이 30%씩 출렁인다. **유형별 분해가 이 세트의 유일한 강점이므로, 그 강점을 쓸 수 있을 만큼은 채워야 한다.** 유형당 8개면 12.5% 단위로 읽을 수 있다.

본인이 README 8절에 적은 해법이 맞다 — **산업안전보건법 시행규칙 제156·157·159·160조나 고시 제11조**를 조각으로 추가하면 "다만 ~인 경우에는 그러하지 아니하다" 형태가 많아 조건절을 뒤바꾸기 쉽다. 이 조각들은 MSDS 작성의 법적 근거이므로 도메인을 벗어나지도 않는다.

### 작업 3 — 채점 결과 정리 양식 (조건부)

| 항목 | 내용 |
|---|---|
| 담당 | 박승형 |
| 착수 시점 | **검증 모델 담당이 첫 채점 결과를 넘긴 뒤** |
| 분량 | 표 2개 + 실패 사례 3~5건 |
| 소요 | 2시간 |

유형별 탐지율 표, 물질별 탐지율 표, 그리고 **놓친 사례 중 발표에 쓸 만한 것 3~5건**을 골라 정리한다. 마지막 것이 특히 중요하다 — 숫자만 있으면 "그래서 뭐가 문제인데?"에 답할 수 없지만, MSDS-048 같은 사례 하나를 보여 주면 한계가 즉시 이해된다.

### 하지 않아도 되는 것

- **학사요람 24문항과의 병합** — 지금은 결정하지 않는다. 두 도메인을 섞으면 어느 쪽 때문에 점수가 그런지 알 수 없게 된다. 따로 두고 각각 채점한 뒤에 비교한다.
- **문항 수를 더 늘리는 것** — 3종 100문항 남짓이면 충분하다. 그 이상은 시간 대비 얻는 것이 없다.
