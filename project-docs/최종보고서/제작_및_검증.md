# Blue Jay 종합보고서

사용자가 제공한 최종 발표자료와 저장소 산출물을 종합한 A4 세로 보고서다. 참고 PDF의 표지·국문초록·목차·11부 본문·부록·참고문헌 형식을 따랐다. 내용에 필요한 페이지를 확보하여 총 46쪽으로 구성했다.

## 결과물

- `output/pdf/Blue_Jay_공공입찰_AI_종합보고서.pdf`: 배포용 PDF
- `Blue_Jay_종합보고서_원고.md`: 편집 가능한 원고
- `report_content.py`: 본문·표·출처의 정본
- `assets/`: 9개 재작성 도식·그래프와 기존 UI 캡처 1개
- `검증결과.json`: 페이지·배치·텍스트·글꼴·에이전트 시각 검토 기록
- `출처_manifest.json`: 주요 사용 파일의 이름·역할·해시

## 반영한 근거와 해석

최종 PPT의 모델 선택, 청킹 비교, 번역과 탐지 실험을 포함했다. 기존 저장소에서 확인되는 데이터·합성 회사·300문항·검수 결과·코드의 상태와 PPT의 최신 보고값을 구분했다. 100건/80%는 제공된 manifest의 사후 선별 설명을 반영했고, 11%→2.2%는 가정 계산으로 명시했다. 100건 자료의 KLUE 표기와 PPT의 BGE-M3 표기, 기존 Window 460 코드와 PPT의 384 설정 차이는 삭제하지 않고 본문에서 설명했다.

회사 설정은 합성 자료이며, 실제 기업의 증빙으로 표현하지 않았다. 원천 공고·전체 원문 캐시·모델·색인·비밀키는 이 보고서 패키지에 포함하지 않는다. 사람 최종 승인 상태도 이번 작성 과정에서 변경하지 않았다.

## 재생성

Python 3.12와 `reportlab`, `pypdf`, `Pillow`, `matplotlib`을 사용했다. Windows에서는 맑은 고딕 보통·굵은 글꼴을 PDF에 포함한다. 다른 환경은 `REPORT_FONT`, `REPORT_FONT_BOLD` 환경변수로 한국어 TrueType 글꼴을 지정한다.

저장소 루트에서 실행한다.

```text
python project-docs/최종보고서/build_assets.py
python project-docs/최종보고서/build_report.py
```

`dashboard.png`는 기존 공개 L1 저장 결과 모드를 별도 루프백 정적 서버에서 열어 촬영했다. 생성·탐지 모델은 호출하지 않았다. 캡처의 ASTRA 명칭은 기존 코드의 실제 화면이며 후속 UI가 아니다.

## 검증

PDF 전체를 Poppler로 렌더링하고 전 페이지 축소판과 주요 페이지 원본 크기를 에이전트가 검토했다. 본문·표·캡션 넘침, 목차 페이지 연결, 한국어 글꼴 포함과 텍스트 추출을 확인했다. 내용 검토에서는 QAR 예제, 공고 집계, 질문 유형 합계, 혼동행렬, 가정 계산과 발표 수치의 출처를 대조했다. 자동 검사와 에이전트 검토는 사람 최종 승인과 구분한다.

이번 작업은 기존 기록을 정리한 보고서 제작이다. 모델 재학습·전체 RAG 재실행·새 독립 성능 측정은 수행하지 않았다.
