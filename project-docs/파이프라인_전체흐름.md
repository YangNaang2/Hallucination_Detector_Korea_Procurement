# 전체 파이프라인 — 무엇으로 배우고, 무엇에 서비스하는가

> 팀 공유용. 세션 27까지의 결정을 하나의 흐름으로 이은 문서.

---

## 0. 먼저 이것부터 — 모델은 학사요람을 외우지 않는다

이 프로젝트를 이해하는 열쇠는 여기 하나다.

우리가 만드는 모델은 **지식을 저장하는 모델이 아니라, 두 글을 나란히 놓고 대조하는 모델**이다.

> **비유 — 채점자.**
> 채점자에게 **정답지**와 **학생 답안지**를 나란히 준다. 채점자가 하는 일은
> "답안지에서 **정답지에 없는 말**을 한 부분에 밑줄을 긋는 것" 하나뿐이다.
> **채점자는 그 과목을 몰라도 된다.** 정답지가 옆에 있기 때문이다.

우리 모델도 같다.

| | 채점자 비유 | 우리 모델 |
|---|---|---|
| 받는 것 ① | 정답지 | **근거 문서** (예: 학사요람에서 찾아온 문단) |
| 받는 것 ② | 학생 답안지 | **챗봇이 생성한 답변** |
| 하는 일 | 답안지에 밑줄 | **답변의 각 토큰이 문서에 근거하는가 판정** |
| 필요 없는 것 | 과목 지식 | **학사요람을 외울 필요 없음** |

**그래서 영어 데이터로 훈련한 채점자를 한국어 시험장에 투입할 수 있다.**
그게 되는지가 바로 **우리 프로젝트의 질문**이다.

## 1. 데이터가 3종류다 — 역할이 전부 다르다

여기가 가장 헷갈리는 지점이다. 세 데이터는 **경쟁 관계가 아니라 순서대로 쓰이는 것**이다.

| | 이름 | 어디서 오나 | 규모 | 무엇에 쓰나 |
|---|---|---|---|---|
| **①** | **RAGTruth 한국어 번역본 (학습용)** | 영어 RAGTruth를 `<HAL>` 태그째 기계번역 | **15,090건** | **모델을 학습시킨다.** 우리 모델의 재료 |
| **②** | **RAGTruth 한국어 번역본 (평가용)** | 위와 같은 방식, 겹치지 않는 부분 | **2,700건** | **평가 ①.** 터키어 논문과 같은 조건. "제대로 학습됐나" 확인 |
| **③** | **한국어 실전 평가셋** | **학사요람**으로 팀이 직접 만든다 | **300~500건 목표** | **평가 ②.** "진짜 한국어 문서에서 통하나" |

### 우리가 발표할 숫자는 ②와 ③의 차이다

```
평가 ② 성능 (번역 데이터)   0.72 라고 치면
평가 ③ 성능 (진짜 한국어)   0.58 이 나왔다면
────────────────────────────────────
격차 = 0.14  ←  이 숫자가 우리 논문/발표의 결론
```

- **격차가 작으면** → "번역 데이터만으로 충분하다. 한국어 데이터를 손으로 만들 필요 없다." (실용적 결론)
- **격차가 크면** → "번역 데이터의 한계를 처음으로 밝혔다." (경고이자 기여)

**어느 쪽이 나와도 발표할 내용이 된다.** 실패할 수 없는 실험 설계다.

> **왜 학습(①)과 서비스 대상(③)이 다른가?**
> 그게 **버그가 아니라 연구 주제 그 자체**다. 터키어 팀은 ①로 배워서 ②로만 평가하고 끝냈다.
> ③을 아무도 하지 않았고, 그 자리가 우리 자리다.

## 1-A. RAGTruth가 대체 뭔가 (실제 데이터로 보기)

### 한 줄
**"AI가 문서를 보고 답하다가 지어낸 말"에 사람이 형광펜을 그어 둔 자료집.**
영어로 17,790건이 있고, **환각 구간의 시작·끝 위치가 글자 단위로 적혀 있다.** 우리가 필요한 건 이 위치 정보다.

### 어떻게 만들어졌나
1. 문서(또는 데이터)와 질문을 준비한다
2. **여러 LLM에게 실제로 답을 생성시킨다** (GPT-4, Llama, Mistral 등)
3. **사람이 답변을 읽고, 문서에 근거가 없는 부분에 밑줄을 긋고 사유를 적는다**

> **중요 — 환각을 억지로 심은 게 아니라, LLM이 실제로 저지른 것을 사후에 채집했다.**
> 그래서 실제 서비스에서 마주치는 환각과 성질이 같다. (K-FinHallu는 반대로 **주입** 방식이다.)

### 실제 수록 예시 1 — 숫자를 바꿔 말함

| | 내용 |
|---|---|
| **근거 데이터** | `{'name': 'Los Tarascos', 'city': 'Goleta', ... 'stars': 4.5 }` |
| **AI 답변** | "...Overall, Los Tarascos is rated **3** stars..." |
| **환각 구간** | `'3'` ← **글자 하나** |
| **유형** | Evident Conflict |
| **사람이 적은 사유** | `Original: 4.5 / Generative: 3` |

### 실제 수록 예시 2 — 문서에 있는 사실을 뒤집음

| | 내용 |
|---|---|
| **근거 데이터** | `{'name': "Ike's Love & Sandwiches", ... 'parking lot': true }` |
| **AI 답변** | "The restaurant offers outdoor seating and **does not have a parking lot**..." |
| **환각 구간** | `'does not have a parking lot'` |
| **사유** | `Original: true for parking lot / AIGC: does not have a parking lot` |

### 실제 수록 예시 3 — 문서에 없는 말을 지어냄

| | 내용 |
|---|---|
| **질문** | "butcher shop phone number" |
| **근거 문서** | 정육점 여러 곳의 주소와 전화번호 목록 |
| **AI 답변** | "Based on the given passages, there are several different phone numbers... **However, none of them are for a specific location named "bear" or have any indication of being related to bears.** Therefore..." |
| **환각 구간** | `However, none of them are for a specific location named "bear"...` (102~214번째 글자) |
| **유형** | Evident Baseless Info |
| **사유** | `No mention of this in the passages` — **문서에 "bear" 얘기는 한 글자도 없다. AI가 혼자 지어냈다.** |

### 데이터 한 건의 구조

```
source_info :  질문 + 근거 문서(또는 구조화 데이터)
response    :  AI가 생성한 답변 전문
labels      :  [ {start: 102, end: 214, text: "...", label_type: "...", meta: "사유"} , ... ]
                       ↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑  이것이 우리가 원하는 정답
```

### 그래서 왜 이걸로 학습하나

우리 모델의 정답지는 **"이 답변의 몇 번째 글자부터 몇 번째 글자까지가 환각인가"**다.
그 정답이 **사람 손으로 17,790건 붙어 있는 데이터는 사실상 RAGTruth뿐**이다.
LettuceDetect도, 터키어 팀도 전부 이걸 썼다. **이 분야의 표준 학습 데이터다.**

- 환각 라벨 보유 7,664건(43.1%) + **정상 답변 10,126건** → 정상/환각을 함께 배운다
- 과제 3종(QA·Data2txt·Summary)이 고르게 들어 있어 한쪽에 치우치지 않는다
- 학습 15,090 / 평가 2,700으로 **분할이 이미 정해져 있어** 다른 논문과 숫자를 직접 비교할 수 있다

### 다만 영어다 — 그래서 번역한다

RAGTruth의 가치는 **글자 위치 라벨**인데, 보통 번역하면 이 위치가 다 날아간다.
그래서 환각 구간을 `<HAL>` 태그로 감싸고 번역해서 **라벨이 번역을 따라오게** 만든다.
**이게 되는지는 세션 26에서 확인했다 — 13/13 구간 100% 보존.** (`HAL태그_시험/결과_보고.md`)

```
영어 원본  : The restaurant offers <HAL>does not have a parking lot</HAL>...
한국어 번역: 이 식당은 <HAL>주차장이 없으며</HAL>...
                      ↑ 태그가 따라왔으므로 한국어에서도 정답 위치를 안다
```

## 2. 서비스는 무엇에 대해 돌아가나

**대학 학사요람**이다. (예: "복수전공 신청은 몇 학점부터 가능한가요?")

**왜 학사요람인가**
- 팀에 도메인 전문가가 없다. **법률·의료는 팀이 라벨의 정오를 검증할 수 없어서 제외했다.**
- 학사요람은 팀원 전원이 당사자라 **"이 답이 맞는지" 판단이 가능하다.**
- 심사위원도 대학 맥락을 안다 → 데모가 즉시 이해된다.
- 공개 PDF라 데이터 확보가 쉽다.

## 3. 전체 흐름 — 한 장

### 만드는 단계 (1~4주차, 사용자에게 안 보임)

```
[영어 RAGTruth 17,790건]  ← GitHub에서 이미 받아뒀다
        │
        │  B파트: 환각 구간을 <HAL>태그로 감싸고 기계번역
        │         (겹치는 구간 1.5%는 먼저 병합)
        ▼
[한국어 RAGTruth]  ── 학습 15,090 ─┐
                   └─ 평가 2,700 ─┐│
                                  ││
        C파트: 한국어 인코더 3종을 ││
        토큰 이진분류로 학습       ││
                ▼                 ││
        [한국어 환각 탐지 모델] ←──┘│
                │                  │
                └────── 평가① ─────┘   (번역본 성능)
                │
                └────── 평가② ──── [학사요람 평가셋]  ← A·D파트가 제작
                                          │
                                    격차 = 평가①－평가②
```

### 쓰는 단계 (데모 화면, 심사위원이 보는 것)

```
사용자: "복수전공 신청은 몇 학점부터 가능한가요?"
        │
        ▼
[A파트] 학사요람에서 관련 문단을 찾아온다 (RAG 검색)
        │  → 근거 문서: "복수전공은 2학기 이상 등록하고 36학점 이상 취득한 자에 한하여..."
        ▼
[일반 챗봇] 답변을 생성한다
        │  → "36학점 이상 취득하면 신청할 수 있으며, 신청 기간은 매 학기 초 2주간입니다."
        ▼
[C파트 = 우리 모델]  근거 문서와 답변을 나란히 놓고 대조
        │
        ▼
화면 출력:
   "36학점 이상 취득하면 신청할 수 있으며,  ← 초록 (문서에 있음)
    신청 기간은 매 학기 초 2주간입니다."     ← 빨강 형광펜 (문서에 없음 = 환각)
```

**우리 모델이 붙는 자리는 챗봇 뒤가 아니라 챗봇 다음이다.** 답을 만드는 게 아니라 **답을 검사한다.**

## 4. 그래서 각 파트는 무엇을 만드나

| 파트 | 담당 산출물 | 위 그림에서의 위치 |
|---|---|---|
| **A · 문서·RAG** | 학사요람 수집 → 문단 분할 → 검색기 | 데모의 "근거 문서 찾아오기" |
| **B · 데이터** | `<HAL>` 태그 번역 파이프라인 → **한국어 RAGTruth ①②** | 데이터 ①② 전량 |
| **C · 검증 모델** | 인코더 3종 학습·비교, **격차 측정** | 모델 본체 + 평가①② |
| **D · 평가** | **학사요람 평가셋 ③ 제작**, 베이스라인 4종 비교 | 데이터 ③ + 채점 |
| **E · 프론트·진행** | 형광펜 데모 화면, 발표 | 사용자가 보는 전부 |

**팀 필수 동기화는 1주차 `verification_result.json` 계약 하나뿐이다.**
C가 무엇을 내보내고 E가 무엇을 받아 칠할지만 정하면, 3주차까지 각자 병렬로 굴러간다.

## 5. 자주 나오는 질문

**Q. 영어 데이터로 배운 모델이 한국어 학사요람을 어떻게 판단하나?**
→ 영어로 배운 게 아니다. **①은 이미 한국어로 번역된 데이터**다. 모델은 한국어만 본다.
다만 그 한국어가 **번역된 한국어**라서, 사람이 쓴 진짜 한국어와 다를 수 있다. 그 차이를 재는 게 우리 실험이다.

**Q. 학사요람 데이터가 300~500건뿐인데 학습이 되나?**
→ **학습에 안 쓴다. 평가에만 쓴다.** 학습은 ①의 15,090건으로 한다.
(격차가 크게 나오면, 추가 실험으로 ③ 일부를 섞어 학습하는 것도 가능하다.)

**Q. 도메인이 다른데(일반 문서 → 학사요람) 되겠나?**
→ **0절의 채점자 비유가 답이다.** 모델은 학사요람 지식이 아니라 "문서와 답변의 대조"를 배운다.
그래도 도메인 차이는 성능을 떨어뜨리며, **그 하락폭 역시 우리가 재려는 격차의 일부**다.

**Q. K-FinHallu와 겹치지 않나?**
→ 그쪽은 **턴 단위 판정(답변 전체가 환각인가)**, 우리는 **구간 단위(어디가 환각인가)**.
그쪽 출력으로는 형광펜을 못 긋는다. 상세는 `K-FinHallu_비교.md`.
