# RAGTruth 가 학습되는 과정 — 한 건을 끝까지 따라가기

B1조 · 검증 모델 파트 · 2026-09-08

문서 한 건이 **영어 원본에서 시작해 모델의 가중치를 바꾸기까지** 무슨 일이 일어나는지
순서대로 적었다. 중간에 건너뛰는 단계 없이 전부 담았다.

---

## 전체 그림

```
① RAGTruth 원본 (영어, 글자 위치로 표시)
        ↓  표시를 태그로 바꾼다
② <HAL> 태그가 박힌 영어 문장
        ↓  gemma-3-12b-it 로 번역
③ <HAL> 태그가 박힌 한국어 문장
        ↓  태그 자리에서 글자 수를 다시 센다
④ 한국어 문장 + 새 글자 위치
        ↓  자동 검사 — 어긋난 건 버린다
⑤ 학습 데이터 17,537건
        ↓  토큰으로 자르고 라벨을 매긴다
⑥ 숫자 배열 두 줄 (input_ids · labels)
        ↓  모델에 넣는다
⑦ 토큰마다 확률 → 손실 → 가중치 갱신
```

①~⑤가 **데이터 만들기**, ⑥~⑦이 **학습**이다. 아래에서 각 단계를 예시 하나로 따라간다.

---

## ① RAGTruth 원본은 이렇게 생겼다

한 건은 네 덩어리다.

| 항목 | 내용 |
|---|---|
| `context` | 모델에게 준 근거 문서 |
| `question` | 사용자 질문 |
| `response` | 모델이 만든 답변 |
| `labels` | 사람이 표시한 환각 구간 목록 |

`labels` 는 **글자 위치**로 저장돼 있다.

```json
{
  "start": 636,
  "end": 661,
  "text": "you may still be eligible",
  "label_type": "Evident Baseless Info"
}
```

"답변의 636번째 글자부터 661번째 글자까지가 지어낸 부분"이라는 뜻이다.
사람이 답변을 읽으며 직접 표시했다.

전체는 **약 17,790건**이고, 6개 LLM 이 3가지 과제(QA · Data2txt · Summary)에서 만든
답변이다. 그중 약 3분의 1에 환각이 들어 있다.

---

## ② 표시를 태그로 바꾼다

여기서 이 프로젝트의 핵심 문제가 나온다.

**글자 위치는 번역하면 전부 어긋난다.** 한국어는 어순이 달라서 636번째 글자가
전혀 다른 곳을 가리키게 된다. 그렇다고 표시를 버릴 수도 없다. 그게 정답이니까.

해법은 **위치가 아니라 내용에 표시를 붙이는 것**이다.

```
번역 전   ... but you may still be eligible for external ...
          ↓ 636~661 자리에 태그를 씌운다
          ... but <HAL>you may still be eligible</HAL> for external ...
```

이제 표시가 문장 안에 글자로 들어가 있으므로, 문장이 어떻게 움직이든 따라간다.

---

## ③ 번역 — gemma-3-12b-it

태그가 박힌 문장을 통째로 번역한다. 프롬프트가 중요하다.

```
Translate the following text from English to Korean.
If the original text contains <HAL> tags, translate the content inside
<HAL> tags and ensure the number of the <HAL> tags remain exactly the same
in the output. ...
Do NOT add any <HAL> tags if they were not in the original text.
Do NOT remove any <HAL> tags that were in the original text.
```

지시의 대부분이 **태그 개수를 유지하라**에 쓰여 있다. 번역을 잘하는 것보다
태그가 온전한 것이 중요하기 때문이다. 하나라도 어긋나면 그 건은 버려야 한다.

```
번역 후   ... 하지만 <HAL>신청은 가능할 수 있습니다</HAL> ...
```

어순이 바뀌었지만 **태그는 자기가 감싼 내용을 따라 움직였다.**

> 선행 연구는 27B 모델을 A100(80GB)에서 돌렸다. 우리 워크스테이션은 A5000(24GB)이라
> 27B 가 들어가지 않아 12B 로 낮췄고, 파일럿 200건에서 **태그 보존율 98%** 를 확인하고
> 확정했다.

---

## ④ 글자 위치를 다시 센다

번역된 문장에서 태그를 떼어내면서, 그 자리가 몇 번째 글자였는지 센다.

```
문장    ... 하지만 <HAL>신청은 가능할 수 있습니다</HAL> ...
        ↓ 태그를 제거하면서 위치 기록
답변    ... 하지만 신청은 가능할 수 있습니다 ...
표시    { start: 12, end: 34 }
```

이제 **한국어 문장에 맞는 새 글자 위치**가 생겼다. 원본과 같은 형식이므로
이후 과정은 영어든 한국어든 똑같이 돌아간다.

---

## ⑤ 자동 검사 — 어긋난 건 버린다

세 가지가 깨질 수 있다.

1. 번역 모델이 태그를 지우거나 늘린다
2. 한국어 **조사**가 태그 밖으로 밀린다 (`신청은` 의 `은` 이 밖으로 나가는 식)
3. 번역이 부정확해 엉뚱한 구절에 태그가 붙는다

1·2 는 자동으로 걸러낸다 — 여는 태그와 닫는 태그의 개수가 다르거나, 태그 안이
비었거나, 복원한 구간이 답변 길이를 벗어나면 버린다. **버리는 것이 손해가 아니다.**
잘못된 정답으로 학습하는 것이 훨씬 나쁘다.

통과한 것이 **17,537건**(학습 14,863 · 평가 2,674)이다.

## ⑥ 토큰으로 자르고 라벨을 매긴다

여기서부터가 `src/dataset.py` 다.

### 6-1. 답변을 토큰으로 자른다

```python
enc_ans = tokenizer(answer, add_special_tokens=False, return_offsets_mapping=True)
```

`return_offsets_mapping=True` 가 핵심이다. 각 토큰이 **원문의 몇 번째 글자부터
몇 번째까지인지**를 함께 돌려준다.

```
답변    하지만 신청은 가능할 수 있습니다
토큰    ['하지만', '신청', '은', '가능', '할', '수', '있', '습니다']
오프셋  [(0,3),  (4,6), (6,7), (8,10), (10,11), (12,13), (14,15), (15,18)]
```

### 6-2. 표시 구간과 겹치는 토큰에 1 을 준다

```python
def align_labels(answer, spans, offsets):
    labels = []
    for (s, e) in offsets:
        if s == e:                                  # 빈 토큰
            labels.append(LABEL_SUPPORTED)
            continue
        hit = any(s < he and e > hs for hs, he in spans)
        labels.append(LABEL_HALLUCINATED if hit else LABEL_SUPPORTED)
    return labels
```

조건이 `s < he and e > hs` — **겹치기만 하면 1** 이다. 토큰이 구간에 걸쳐 있어도
포함으로 센다. 토큰 경계와 사람이 그은 경계가 정확히 맞을 리 없기 때문이다.

```
토큰    하지만  신청  은   가능  할   수   있   습니다
라벨      0     1    1    1    1    1    1     1
              └────── 표시 구간(12~34) 과 겹침 ──────┘
```

### 6-3. 문서와 질문을 앞에 붙인다

```python
prompt = f"질문: {question}\n\n문서:\n{context}"
```

문자열로 이어 붙인다. **특별한 구조가 없다.** 그냥 긴 한 덩어리다.

### 6-4. 최종 배열을 조립한다

```
input_ids   [CLS]  질문:… 문서:…  [SEP]  하지만 신청 은 가능 …  [SEP]
labels      -100   -100  -100    -100     0    1   1   1   …   -100
```

**`-100` 은 "채점하지 말라"는 표시다.** 파이토치의 교차 엔트로피 손실이
이 값을 만나면 그 자리를 건너뛴다. 그래서 **문서와 질문 토큰은 학습에
아무 영향을 주지 않는다.** 읽으라고 넣어주는 것뿐이다.

### 6-5. 길이가 넘치면 문서를 자른다

```python
budget = max_length - len(ans_ids) - n_special
prompt_ids = prompt_ids_full[:budget]
```

**답변은 절대 자르지 않는다.** 답변을 자르면 그 구간의 정답 라벨이 통째로
사라져 평가가 왜곡된다. 대신 **문서 뒤쪽을 버린다.** 이 때문에 문서가 긴
요약 과제에서 근거가 사라지는 문제가 생겼고, 그래서 8,192 토큰을 다루는
`bge-m3` 로 옮겼다.

## ⑦ 배치로 묶는다

문장 길이가 제각각이므로 한 묶음 안에서 가장 긴 것에 맞춰 뒤를 채운다.

```python
out["input_ids"].append(b["input_ids"] + [pad_id] * pad)
out["attention_mask"].append(b["attention_mask"] + [0] * pad)
out["labels"].append(b["labels"] + [IGNORE_INDEX] * pad)
```

세 가지를 함께 맞춘다.

| 배열 | 채우는 값 | 뜻 |
|---|---|---|
| `input_ids` | 패딩 토큰 | 자리만 채운 가짜 토큰 |
| `attention_mask` | `0` | **여기는 쳐다보지 말라** |
| `labels` | `-100` | 여기는 채점하지 말라 |

## ⑧ 모델 안에서 일어나는 일

### 8-1. 구조

```python
AutoModelForTokenClassification.from_pretrained(model_name, num_labels=2)
```

두 부분이다.

- **인코더** — 사전학습된 트랜스포머(`bge-m3` 등). 토큰 배열을 받아 각 자리마다
  숫자 벡터(1,024차원 등)를 만든다.
- **분류 머리** — 그 벡터를 받아 **숫자 두 개**로 줄이는 아주 작은 선형 층.
  `num_labels=2` 가 이것이다. 처음에는 무작위 값으로 시작한다.

### 8-2. 인코더가 하는 일 — 여기가 핵심이다

토큰마다 벡터가 나오는데, 그 벡터는 **그 토큰 하나만 보고 만든 것이 아니다.**

셀프 어텐션 때문에 각 자리의 벡터는 **문장 전체를 참조한 결과**다. 답변의
`신청` 자리 벡터에는 다음이 모두 섞여 있다.

- `신청` 이라는 단어 자체
- 바로 앞의 `하지만`
- **문서에 있는 `교내 장학금 신청이 제한된다`**
- 질문 내용

그래서 "이 토큰이 문서에 있나"가 아니라 **"이 문맥에서의 이 토큰이 문서로
뒷받침되나"** 가 표현된다. 문서를 함께 넣는 이유가 여기 있다.

### 8-3. 분류 머리가 확률을 낸다

각 답변 토큰 자리에서 숫자 두 개가 나오고, softmax 를 거쳐 확률이 된다.

```
토큰      하지만   신청   은    가능   할
지지 확률  0.92   0.09  0.14  0.17  0.21
환각 확률  0.08   0.91  0.86  0.83  0.79
```

## ⑨ 손실 — 얼마나 틀렸는지 잰다

정답과 비교한다. 교차 엔트로피다.

```
자리      하지만   신청   은    …
정답        0      1     1
환각 확률  0.08   0.91  0.86
손실       작음   작음   작음     ← 잘 맞힘
```

만약 `신청` 의 환각 확률이 0.10 이었다면 그 자리의 손실이 크게 잡힌다.

**`-100` 자리는 계산에서 빠진다.** 문서가 아무리 길어도 손실에 기여하지 않는다.
그래서 한 건의 손실은 **답변 토큰들의 손실 평균**이다.

> 참고로 환각 토큰은 전체의 약 4% 다. 그래서 "전부 지지"라고만 찍어도 손실이
> 꽤 낮게 나온다. 모델이 이 함정에 빠지면 환각 F1 이 0 이 되는데, 실제로
> `xlm-roberta-large` 에서 그런 붕괴가 일어나 `CollapseGuard` 를 만들어 붙였다.

---

## ⑩ 가중치를 고친다

손실을 줄이는 방향으로 모든 가중치를 아주 조금씩 움직인다(역전파).
**분류 머리만이 아니라 인코더 전체가 함께 바뀐다.** 이것이 파인튜닝이다.

우리 설정은 이렇다.

| 항목 | 값 | 왜 |
|---|---|---|
| 학습률 | `1e-5` | 사전학습된 지식을 망가뜨리지 않을 만큼 작게 |
| 배치 | 1 × 누적 4 = **4** | 문서가 길어 GPU 에 한 번에 하나만 올라간다. 4번 모아 한 번 갱신 |
| 워밍업 | 6% | 처음에는 더 작은 학습률로 시작해 서서히 올린다 |
| 에폭 | 6 | 전체 데이터를 6바퀴 |
| 가중치 감쇠 | 0.01 | 과적합 억제 |
| bf16 | 켬 | 메모리 절약 |
| 그래디언트 체크포인팅 | 켬 | 메모리 절약(속도는 느려진다) |

**배치가 4 라는 것은 실제로 이렇게 돈다는 뜻이다** — 예시 4건을 하나씩 통과시키며
기울기를 쌓아 두었다가, 4건이 모이면 그제야 가중치를 한 번 고친다.
14,863건 ÷ 4 ≈ 3,716번 갱신하면 1에폭이 끝난다.

## ⑪ 에폭이 끝날 때마다 평가한다

```python
eval_strategy="epoch"
metric_for_best_model="hallu_f1"
load_best_model_at_end=True
```

평가셋 2,674건으로 채점해 네 가지를 찍는다 — macro F1 · 환각 F1 · AUROC · 정밀도/재현율.

**최종적으로 남기는 것은 마지막 에폭이 아니라 환각 F1 이 가장 높았던 에폭이다.**
6바퀴를 다 돌아도, 4바퀴째가 제일 좋았다면 그 상태로 되돌려 저장한다.

`CollapseGuard` 가 함께 붙어 있어서 AUROC 가 두 에폭 연속 0.55 미만이면
**붕괴로 보고 학습을 중단**한다. 5시간을 헛돌리지 않기 위해서다.

## ⑫ 다 배운 모델을 쓸 때

학습 때와 **완전히 같은 형식**으로 입력을 만든다. 이것이 어긋나면 성능이 떨어진다.

```
[CLS] 질문:… 문서:… [SEP] 답변토큰들 [SEP]
```

다른 점은 정답이 없다는 것뿐이다. 답변 토큰마다 환각 확률이 나오고,
**기준선을 넘으면 X**, 붙어 있는 X 를 이어 붙여 구간으로 만든다. 그것이 형광펜이다.

기준선(임계값)은 **학습 데이터에서 따로 정한다.** 평가 데이터에서 고르면
그 데이터에 맞춰 고른 셈이라 점수가 부풀려진다.

## 자주 헷갈리는 것 넷

**1. 모델이 문서를 외우는 것이 아니다.**
문서는 학습 때도 쓸 때도 **매번 입력으로 함께 들어간다.** `-100` 으로 채점에서
빠지므로 문서 내용이 가중치에 새겨질 이유가 없다. 모델이 익히는 것은
**"문서와 답변을 나란히 놓고 어긋난 곳을 찾는 요령"** 하나다. 그래서 문서 자리에
MSDS 를 끼워 넣으면 MSDS 기준으로 판정한다.

**2. 문서 없이는 아무것도 못 한다.**
추측조차 하지 않는다. 대조할 대상이 없기 때문이다.

**3. 정답이 단어가 아니라 구간에 붙어 있다.**
사람이 표시한 것은 `교외 장학금 신청은 가능할 수 있습니다` 전체이고, 그 안의
모든 토큰이 1 이다. 그래서 모델이 배우는 것은 "이 단어가 문서에 있나"가 아니라
**"이 자리가 지어낸 구절 안에 속하나"** 다. 개별 단어가 문서에 있어도(예: `장학금`)
구간 안이면 1 이다.

**4. 환각의 유형은 가르치지 않는다.**
RAGTruth 에는 `Evident Conflict` 같은 유형이 있지만 쓰지 않는다. 이진으로만
학습한다. 유형별로 나누면 데이터가 잘게 쪼개져 불안정해지고, 실무에서 필요한 것은
