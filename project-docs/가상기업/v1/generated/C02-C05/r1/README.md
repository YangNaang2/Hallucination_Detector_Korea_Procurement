## 문서와 접근 역할

| 접미사 | 내용 | 등급 | 허용 역할 |
|---|---|---|---|
| PROFILE / PERF / STAFF / CERT | 기업·본점·등록 / 실적 / 인력·기존 배치 / 인증·서비스 | L2 | bid_analyst, cost_analyst, bid_approver |
| COST | 회사 공통 인건비·원가·마진 정책 | L3 | cost_analyst, bid_approver |
| PLAN | 공고별 자체 인력 배치 초안 | L2 | bid_analyst, cost_analyst, bid_approver |
| ESTIMATE / QUOTE | 부분 원가 / 공개 가격 참고·합성 경비 가정 | L3 | cost_analyst, bid_approver |
| BID | 참여 보류 사유와 후속 확인 | L3 | bid_approver |

모든 역할은 해당 회사 tenant의 인증된 활성 사용자에 한한다. 다른 회사의 approver, 미인증 사용자, 비활성 사용자, viewer는 차단하는 오프라인 정책을 검사했다. 실제 인증 서버와 벡터 검색 필터는 이번에 구현·시험하지 않았다.

## 합성 배치 및 부분 원가

| 회사 | 신규 배치 가정 | 자체 인건비(원, VAT 제외) | 자체 인건비+방문 경비+간접비·예비비(원, VAT 제외) |
|---|---|---:|---:|
| C02 | P-02 0.5 FTE, 8개월 | 20,515,600 | 25,624,408 |
| C03 | P-02 .4 / P-03 .8 / P-04 .5 / P-05 .2 / P-06 .2 FTE | 72,585,755 | 87,805,048 |
| C04 | P-07 .15 / P-03 .25 / P-08 .1 FTE, 7개월 | 19,972,260 | 24,686,712 |
| C05 | P-07 .2 / P-03 .8 / P-04 .8 / P-06 .3 FTE, 6개월 | 76,574,520 | 95,559,169 |

이 금액은 **계산값이며 전체 사업비·투찰가가 아니다.** 인건비는 마스터의 직무별 기준급과 사업주 부담률, 배치 FTE를 사용한다. 방문 경비는 C02·C03 각 8회, C04 4회 × 150,000원, C05 12회 × 200,000원의 명시적 합성 가정이다. 실제 출장 운임이나 시장 견적이 아니며 숙박·장비·상용SW 비용을 포함하지 않는다.

계산은 `기준급 × 월별(배치일수/해당 월 일수) × FTE × (1+사업주 부담률)`이다. 양 끝 날짜를 포함하며 Decimal 중간값을 유지하고 최종 원 단위 HALF_UP 한다. C03의 12월은 10/31개월이다. 표시는 반올림된 각 행의 합과 총액에 차이가 날 수 있어 `row_rounding_difference`를 기록했다. 내부 인건비의 실제 달력 일수 방식과 부산 공고의 **유지관리 지급액 30일 기준**은 서로 다른 계산이다.

해온에는 공개 협약 총액을 가정 적용한 추가 민감도 예시를 넣었다. 그 범위의 목표 매출대비 마진을 적용하면 VAT 포함 112,672,300원으로 공고 기초금액 71,970,330원을 넘는다. 이 사실을 숨기거나 인력을 줄여 예산에 맞추지 않았다. 미확정 부품 비용도 있어 실제 투찰가는 여전히 null이다. 다른 회사들도 전체 외부비용을 0원으로 채우지 않았다.

새 시나리오는 모두 `committed=false`인 독립 대안이다. 기존 확정 배치와 신규 초안의 겹치는 FTE를 검사했다. C02 P-02는 1.0, C03 P-02는 기존 업무와 겹치는 기간 0.9 FTE다. 여러 대안을 동시에 확정하려면 회사별 기존 배치와 **모든 확정 신규 계획을 합친 재검사**가 필요하다. 가용 FTE 검사는 SLA, 야간근무, 실제 일정 충돌 또는 기술등급 적합성의 보증이 아니다.

## 청킹·근거·버전

기존 generated_document.schema.json 1.0.0을 유지했다. 실적 1건, 인력 1명, 인증 1건, 서비스 1건, 계산 범위 또는 인건비 1행을 의미 단위로 청킹한다. 5,000문자 상한, 중복 overlap 없음, 중간 절단 없음이다. 모델 토큰 수는 측정하지 않았으므로 실제 tokenizer 검사는 색인 전에 필요하다.

문자 위치는 정본 Markdown의 **Unicode code point, 0부터, text_end 미포함**이며 LF 줄바꿈을 사용한다. Markdown bytes와 문서 JSON content가 동일하다. 기존 JSONL 전송 계약에 공고번호·차수·시나리오 ID/버전을 추가했고 회사별 `chunk_export.schema.json`에서 검사한다. C01 계약과 파일은 바뀌지 않았다.

공통 사실은 master Pointer와 합성 증빙 ID로 연결한다. C04 서비스의 연결 증빙은 서비스 CSAP 항목을 뜻하며 공급계약 증명이 아니다. 공고별 계획은 별도 `inputs/scenario_plans.json`에 있고 원가 계산은 `review/cost_calculations.json`에 있다. `review/chunk_provenance.json`은 청크→원장·공고·계획 Pointer의 **감사용 연결표**다. 계획 원장·평가·review에는 여러 등급과 회사가 섞여 있으므로 전부 검색 금지다. L2 문서에는 L3 계획 원장을 통째로 복사하지 않는다.

## 재현 및 검증

저장소 루트, Python 3.10 이상, 외부 패키지·API·유료 LLM 불필요:

```powershell
python procurement-pipeline/generate_remaining_companies.py --check
python procurement-pipeline/generate_c01_documents.py --check
python -m unittest discover -s procurement-pipeline -p test_company_master.py
python -m unittest discover -s procurement-pipeline -p test_c01_documents.py
python -m unittest discover -s procurement-pipeline -p test_remaining_companies.py
```

빈 출력 경로의 최초 생성은 `--check`를 빼서 실행한다. 같은 버전의 파일이 다르면 덮어쓰지 않고 실패하므로, 승인·수정 이후에는 새 revision으로 확장해야 한다. 생성기는 평가 내용을 문서 생성 입력으로 읽지 않는다.

원본을 가진 환경에서만 추가 대조한다. 경로는 로컬 실제 위치로 바꾼다:

```powershell
python procurement-pipeline/generate_remaining_companies.py --verify-sources <source-texts.json> --source-root <export의_상위_폴더>
```

`--capture-sources`는 검토된 구절의 최초 캡처용이며 일상 재현에 필요하지 않다. 새 원문 버전을 받으면 기존 인용을 조용히 덮어쓰지 말고 차수·해시·충돌을 검토한 새 revision에 반영한다.

자동 검사는 스키마·원장 투영 일치·날짜·인증/증빙 상태·VAT/지분·공수/마진·tenant/역할·offset·질문 연결·정답 격리·C01 byte 회귀를 대상으로 한다. 오류 주입과 실행 기록은 `review/test_results.json`, 원본 대조는 `review/source_validation.json`, 생성 결과는 `validation_report.json`을 본다.

에이전트는 회사별 제약, 질문 20개의 주장 범위, 원문 인용, 신규 배치·원가·공개가격 적용 한계를 내용 검토했다. 자동 검사가 자유서술 전체의 무환각을 보장하지 않으며 이 검토가 사람 승인은 아니다. 실제 답변 생성·환각 탐지·span 라벨링은 수행하지 않았다.

## 다음 단계

1. 사람 검수에서 회사 사실/요건 해석/합성 가정/보류 사유를 검토하고 문서별 승인 상태를 관리한다. 기존 증빙 missing은 승인을 받아도 실제 확보 전에는 바뀌지 않는다.
2. 300문항 설계는 이 20개와 기존 C01 5개의 연결 방식을 확장한다. 공고·회사·시나리오 단위로 학습/평가를 분리하고 미충족·자료부족·권한 차단 사례를 유지한다.
3. 색인은 manifest의 `retrieval_candidate_allowlist`에서 승인된 개별 청크만 선택한다. 회사 원장·상위 폴더 재귀 수집은 금지한다. tokenizer 검사 후 tenant·역할 필터를 실제 서버에서 별도 시험한다.
4. 공급권한·서비스 인증·견적은 자료가 확보된 부분만 새 버전에 반영한다. 미확정 금액 없이도 문서 검색·근거 대조·권한 차단의 파일럿 검토는 진행할 수 있다.
