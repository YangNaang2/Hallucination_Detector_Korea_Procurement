# 선행연구 분석과 방향 재설정 (검증 완료판)

> 2026-09-01 · 팀 전체 공유용
> **결론 : 우리가 하려던 것은 영어·터키어 등으로 이미 만들어져 있다. 그런데 한국어는 정말로 비어 있고, 그걸 만드는 설계도까지 공개돼 있다.**

---

## 1. 확인 결과 요약

앞선 초안에서 "직접 확인해야 한다"고 남겨둔 다섯 가지를 모두 확인했다.

| 확인 항목 | 결과 |
|---|---|
| LettuceDetect 성능 수치 | 영어 예시 단위 **F1 79.22%**. v2 구간 단위는 Qwen-2B **0.574**, mmBERT-base **0.528** |
| **다국어 지원 여부** | **광범위하게 지원한다.** 아래 표 참조 |
| 한국어 구간 탐지기 존재 | **없다.** 확인된 한국어 연구는 K-FinHallu 하나이며 접근이 다르다 |
| Beyond Document Grounding | LettuceDetect **v2 계열**이다. 코드·툴 출력으로 확장한 것이라 우리와 직접 충돌하지 않는다 |
| K-FinHallu 형식 | 한국어 **금융** 다중턴, 환각을 **주입**해 구성. **8B LLM을 파인튜닝**했다 — 소형 인코더가 아니다 |

---

## 2. 이미 만들어진 것 — 생각보다 훨씬 많다

**LettuceDetect 계열이 1년 반 사이에 크게 확장됐다.**

| 갈래 | 모델 | 크기 | 대상 |
|---|---|---|---|
| v1 영어 | `lettucedect-base/large-modernbert-en` | 210M / 610M | 영어 |
| 다국어 | EuroBERT 기반 | 210M / 610M | **영어·독일어·프랑스어·스페인어·이탈리아어·폴란드어·중국어 (7개)** |
| PsiloQA | 다국어 구간 라벨 데이터셋 | — | **아랍어·카탈루냐어·중국어·체코어·영어·바스크어·페르시아어·핀란드어·프랑스어·독일어·힌디어·이탈리아어·스페인어·스웨덴어 (14개)** |
| v2 | `lettucedect-v2-qwen-2b`, `v2-mmbert-base` | 2B / base | 코드·툴 출력·구조화 문서 |
| **TinyLettuce** | Ettin 인코더 | **17M / 32M / 68M** | 영어 |

**TinyLettuce가 특히 중요하다.** 17M 모델이 합성 테스트셋에서 **F1 90.87%**로 GPT-5-mini(83.69%), GPT-OSS-120B(83.38%), Qwen3-235B(79.84%)를 이겼고 **CPU에서 실시간으로 돈다.**

> ⚠️ **우리의 원래 주장 "작은 모델이 거대 LLM을 이긴다"는 이미 증명돼 있다.** 그것만으로는 우리 프로젝트가 성립하지 않는다.

---

## 3. 그런데 한국어는 정말로 비어 있다

**7개 언어에도, 14개 언어에도 한국어는 없다.**

확인된 한국어 연구는 하나뿐이다.

- **K-FinHallu**(2026.05) — 한국어 **금융** 다중턴 RAG 환각 벤치마크. 환각을 주입해 만들었고, **8B LLM을 파인튜닝**해 프론티어 LLM과 대등한 성능을 얻었다. 다만 "근거 없을 때 답변을 거부하는 것"이 가장 약한 축이라고 밝혔다.

즉 한국어에는 **소형 인코더 기반 구간 단위 탐지기가 없다.**

---

## 4. 결정적 발견 — 우리에겐 완성된 설계도가 있다

**Turk-LettuceDetect**(arXiv 2509.17671, 2025.09, Newmind AI)가 **터키어로 정확히 이 일을 했다.** 그리고 방법을 전부 공개했다.

### 그들이 한 일

1. **RAGTruth를 기계번역했다** — 학습 17,790건 / 테스트 2,700건
2. 번역기는 **gemma-3-27b-it**, vLLM으로 **A100 1대에서 약 12시간**, 한 번에 30건 병렬
3. **핵심 트릭 — `<HAL>` 태그.** 환각 구간을 태그로 감싸고, 번역 프롬프트에 *"`<HAL>` 태그의 개수를 정확히 유지하라. 없던 태그를 추가하지 말고 있던 태그를 지우지 말라"*고 지시했다 → **구간 라벨이 번역을 통과해 살아남는다**
4. 인코더 3종을 **이진 토큰 분류**로 학습 (터키어 ModernBERT / TurkEmbed4STS / EuroBERT)

### 결과

| 모델 | 전체 F1 | QA | Data2text | **요약** |
|---|:--:|:--:|:--:|:--:|
| ModernBERT-base-tr | **0.7266** | 0.7588 | 0.7391 | **0.6007** |
| TurkEmbed4STS | 0.7132 | 0.7380 | 0.7365 | 0.5862 |
| EuroBERT-tr 210M | 0.7163 | 0.7323 | 0.7496 | 0.5771 |

부수적 발견 — **거대 LLM은 재현율이 0.99에 육박하지만 정밀도가 낮다.** 즉 멀쩡한 문장까지 환각이라고 찍는다. 과탐지 문제가 실증됐다.

### 이것이 우리에게 뜻하는 것

> **한국어 라벨링 리스크가 사라졌다.**

원래 우리의 최대 위험은 "한국어 구간 라벨을 사람이 만들어야 한다"였다. 그런데 **RAGTruth를 번역하면 라벨이 따라온다.** 사람이 손으로 라벨링할 필요가 없다.
그리고 A100 1대로 12시간이면 되는 작업이다. **A5000 6대면 넉넉하다.**

## 5. 그래서 우리가 할 일 — 새 방향

터키어 논문을 그대로 한국어로 따라 하면 "번역해서 학습시켰다"가 전부다. 한 걸음 더 가야 한다.

**터키어 논문의 빈칸이 우리 자리다. 그들은 번역본으로 학습하고 번역본으로 평가했다. 진짜 터키어 문서에서 얼마나 되는지는 아무도 모른다.**

> ### 우리 질문 한 문장
> ## **"번역해서 만든 한국어 탐지기는, 진짜 한국어 문서에서 통할까?"**

### 실험 설계

```
① 학습 : RAGTruth를 한국어로 번역 → 인코더 학습        (터키어 논문 재현)
② 평가A : 번역된 한국어 테스트셋으로 평가               (그들과 같은 조건)
③ 평가B : 우리가 만든 진짜 한국어 데이터로 평가          ← 아무도 안 한 것
          (학사요람 + 로컬 LLM 답변 + 구간 라벨)
④ 격차 = ② − ③                                        ← 이것이 우리 숫자다
```

**결과가 어느 쪽으로 나와도 발표할 내용이 된다.**
- 격차가 작다 → "번역 데이터만으로 충분하다"는 실용적 결론
- 격차가 크다 → "번역 데이터의 한계"를 처음 밝힌 것

### 함께 다룰 것 두 가지

**한국어 구간 경계 문제.** 한국어는 조사·어미가 붙는 교착어라 **토큰 경계와 의미 경계가 어긋난다.** "1억 원까지"에서 어디까지를 환각 구간으로 잡을 것인가는 영어보다 애매하다. 형태소 단위 처리와 어절 단위 처리를 비교하면 한국어 특유의 기여가 된다.

**운용 임계값.** 여전히 아무도 하지 않았다. "초록불 오답률 2% 이내"를 만족하는 최소 신뢰도를 데이터에서 역산한다. 우리가 역산한 심사 기준표의 F항목을 채운다.

## 6. 파트별로 무엇이 바뀌나

### 안 바뀌는 것
데모 화면(형광펜), 파트 구성 A~E, JSON 계약, 작은 모델을 쓴다는 전제.

### 바뀌는 것

| 파트 | 이전 | 이후 |
|:--:|---|---|
| **A** 문서·RAG | 공고문 | **학사요람**으로 (③ 평가용 진짜 한국어 데이터의 원천) |
| **B** 데이터 | 사람이 한국어 구간 라벨링 | **① RAGTruth 번역 파이프라인** + ③ 소규모 진짜 한국어 평가셋 |
| **C** 검증 모델 | 밑바닥부터 학습 | **터키어 논문 재현 → 한국어 인코더 3종 비교 → 격차 측정** |
| **D** 평가 | 베이스라인 1종 | **베이스라인 4종** — self-check / LettuceDetect 다국어판 / K-FinHallu식 LLM / 우리 |
| **E** 프론트 | 그대로 | 그대로 |

**B 파트의 성격이 완전히 바뀌었다.** 손으로 라벨링하는 일이 아니라 **번역 파이프라인을 돌리는 일**이 됐다. 위험이 훨씬 낮고 자동화된다.

## 7. 이번 주에 각자 할 일 (수정)

| 파트 | 할 일 |
|:--:|---|
| **C** | ① **Turk-LettuceDetect 논문 정독** (우리 설계도다) ② LettuceDetect를 그대로 설치해 영어로 돌려보기 ③ 한국어 문장을 다국어판에 넣어 얼마나 망가지는지 확인 |
| **B** | RAGTruth 원본 확보 → **`<HAL>` 태그 번역 프롬프트를 한국어로 시험** (10건만 먼저) |
| **A** | 학사요람 확보 · 파싱 가능 여부 확인 |
| **D** | 터키어 논문의 평가 표(예시 단위 / 토큰 단위 × 태스크별)를 그대로 재현할 수 있게 지표 정의 |
| **E** | JSON 목업으로 형광펜 화면 |

**가장 먼저 확인할 것 — 번역 10건.** `<HAL>` 태그가 한국어 번역에서 살아남는지가 프로젝트 전체의 전제다. 반나절이면 확인된다. **안 되면 그때 방향을 다시 잡는다.**

## 8. 남은 불확실성

- **번역 품질** — 터키어에서 된다고 한국어에서 된다는 보장은 없다. 한국어는 어순이 달라 구간이 문장 안에서 이동한다. **위 "번역 10건" 시험이 이 위험을 가장 먼저 없앤다.**
- **K-FinHallu 라벨 형식** — 구간 라벨인지 확인하지 못했다. 구간이라면 우리 평가셋에 활용하거나 비교 대상으로 쓸 수 있다. 전문 확인 필요.
- **한국어 KCI 논문** "대형 언어 모델 응답의 신뢰성 향상을 위한 환각 탐지 및 설명 모델" — 내용 미확인. 국내 선행연구이므로 반드시 읽어야 한다.
- **한국어 ModernBERT의 부재** — 터키어에는 터키어 전용 ModernBERT가 있었다. 한국어는 `klue/roberta`(111M) 정도이며 컨텍스트가 짧다. **8,192 토큰 긴 문맥을 어떻게 감당할지**가 실무적 관건이다.
