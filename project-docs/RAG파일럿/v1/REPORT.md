# 로컬 RAG 파일럿 결과 — 실행 완료, 답변 품질 보완 필요

## 실제 완료 범위

회사별 5개씩 고정한 25문항을 실제 실행했다. `qwen3-pilot-v3`에서 LLM 답변 20개와 LLM 호출 없는 권한 차단 5개가 생성됐으며 실행 실패는 없었다. 이후 검색 결과가 바뀐 C03-N11-E3, C04-P01 두 문항만 `qwen3-pilot-v4-followup`으로 추가 실행했다. 재실행을 중복 질문으로 세지 않는다.

[최신 25개 결과 선택표](evaluation/effective_results.json), [질문·기대답·실제 답변 검토표](evaluation/effective_review.tsv), [전체 실행 자동 집계](evaluation/qwen3-pilot-v3-summary.json), [후속 실행 집계](evaluation/qwen3-pilot-v4-followup-summary.json)를 함께 확인한다. 원래 300문항과 가상 기업 v1/r1·v2 자료는 수정하지 않았다.

## 실제 검색 자료·환경

| 구분 | 문서 | 부모 청크 |
|---|---:|---:|
| L1 공개 공고·첨부 | 167 | 3,002 |
| L2 회사 내부 자료 | 34 | 159 |
| L3 회사 민감 자료 | 22 | 114 |
| 합계 | 223 | 3,275 |

51개 공고 모두 읽을 수 있는 자료가 있지만 첨부 16개는 사용 가능한 파싱 텍스트가 없어 제외했다. 전체 첨부 파싱 완료라는 의미가 아니다. 원문 바이너리 SHA와 캐시 연결은 검사했으며 스캔 PDF·복잡한 표의 의미 완전성을 보장하지 않는다.

- 실제 임베딩: multilingual-e5-small, 384차원 float32. 3,275개 부모를 7,195개 토큰 창으로 인코딩했다. query/passage 접두사, mask mean pooling, L2 정규화를 적용했다.
- 실제 생성: Qwen3-4B-GGUF Q4_K_M, llama.cpp b10938, CPU 8스레드, context 4,096, 출력 최대 768토큰, 비사고 모드. 모델 revision·SHA·샘플링은 [환경 기록](environment.json)과 [설정](runtime/generation_profiles.json)에 있다.
- 저장·검색: 로컬 SQLite와 NumPy 벡터. 인증·회사·역할·등급·공고/차수·시나리오/버전/기간으로 후보를 제한한 뒤 E5 cosine과 한국어 부분어 기반 점수를 RRF로 결합한다. top_k=6, 생성에는 최대 4개 부모를 토큰 예산 안에서 온전히 전달한다.
- 준비된 BGE-M3/Gemma 가중치를 찾지 못해 CPU 대체 구성을 사용했다. 예정 아키텍처의 해당 모델 조합을 검증한 결과가 아니다.
- 모델은 loopback 로컬 API로만 호출했다. 외부 유료 추론, 회사 자료 외부 전송, 모델 학습, 운영 배포, UI 로그인 서버 구현은 수행하지 않았다.

## 검증 결과를 구분해서 읽기

자동 검사 158개가 통과했다. 회사·역할 위조, 다른 tenant, 시나리오/기간 오류, 기대답 필드 유입, 잘못된 인용 offset, 문맥 혼입, 변조된 청크 등의 오류 주입과 기존 회사·300문항 데이터 회귀를 포함한다. [검사 결과](validation/tests.json)와 [검사 로그](validation/tests.txt)를 참고한다.

전체 실행의 검색 청크 120개, 추가 실행 12개에 대해 권한·메타데이터·본문 해시·프롬프트 연결을 대조했고 무결성 오류는 없었다. 다섯 권한 차단은 다른 회사, 비활성 계정, viewer, 비인증, 허용되지 않은 L3 요청을 포함하며 제한 값을 출력하지 않았다. 이는 고정된 오프라인 세션 실험이며 운영 인증과 모든 정보 유출 가능성을 검증한 것은 아니다.

검색 자료에서 평가 필드를 차단하고 300개 질문 문장과의 정확 일치 검사 결과 0건을 확인했다. 자유서술에 숨어 있는 의미상의 정답 누출이나 모든 프롬프트 공격을 키워드 검사로 보장하지 않는다. 원문 위치 교집합 진단은 전체 실행에서 20개 비차단 요청 모두 하나 이상의 주석 근거와 겹쳤지만, 일부 겹침만으로 필요한 조항이 전달됐다고 볼 수 없다. Recall@K나 답변 정확도로 표현하지 않는다.

최신 지정 실행에 대한 에이전트 내용 검토는 다음과 같다. 사람 승인은 전부 pending이며 환각 span은 null이다.

| 검토 분류 | 건수 | 의미 |
|---|---:|---|
| 핵심 판단·근거 수용 가능 | 3 | 지정 질문 범위의 의미 검토 |
| 인용 보완 | 4 | 핵심 방향은 맞으나 출처·위치 귀속 보완 |
| 필수 설명·계산 누락 | 5 | 잘못된 사실 생성과 구분되는 불완전 답변 |
| 사실·상태·계산 등 수정 필요 | 8 | 잘못된 추가 주장·상태 해석·산식 등 |
| 정상 권한 차단 | 5 | 검색·LLM 호출 없이 거절 |

이 분류는 독립적인 정확도나 환각률이 아니다. dev 9개·train 8개·test 8개를 개발에 사용했으며 test 8개는 이후 독립 최종 평가에서 제외해야 한다. 이 결과를 보고 기대답을 모델 답변에 맞춰 수정하지 않았다.

## 수정 전후와 남은 실패

- 금액 경계: 회사 실적과 공고의 실적 하한을 앞쪽에 함께 배치했다. C01-P01은 미충족/충족이 뒤섞이던 답변에서 VAT 포함 7천만원이 7천만원 이상을 충족한다는 일관된 답변으로 바뀌었다. 공고 인용 누락은 남았다.
- 회사 상태: 메타데이터 ID만 담은 조각과 불필요한 공개 문맥을 줄였다. C01-S01은 공통 원장 불변을 직접적인 합성 상태 note로 설명했다.
- 제출 부수: 회사명/업체명·표시/표기 표현 대응으로 표기 1부·미표기 6부 원문을 첫 근거에 전달했다. 그래도 모델은 모두 표시해야 한다고 답했다. 검색 개선과 생성 오류를 분리해야 하는 실제 사례다.
- 인증 비교: 회사 ISO와 서비스 CSAP 두 레코드를 함께 전달했다. 모델은 CSAP missing을 보고도 별도 증빙이 존재한다고 서술했다. 합성 레코드 존재와 증빙 확보를 혼동하는 오류가 남았다.
- 원가: C05-S02는 전체 집계와 정확한 산식이 있는데도 일부 장비만 더하고 매출대비 마진을 단순 가산으로 처리해 19,608,000원을 제시했다. 기준 합성 총액 176,521,032원과 다르다. C02에서는 최종 숫자가 맞아도 VAT 설명이 틀렸다.
- 원장: C05-S01은 공고별 실적 인정 규칙과 기존 회사 금액·고객 사실의 변경을 혼동했다. C04-S01은 서비스 ID를 회사 ID로 잘못 답했다.

후속 검색을 전체 25개 요청에 다시 적용해 결과가 달라진 두 문항을 모두 재실행했다. 결과가 좋아진 경우만 고르지 않았으며 기존·후속 답변을 함께 보존했다. 상세 판단은 각 `*-content-review.json`과 최종 검토표에 있다.

## 시간과 미실행 범위

전체 25개 중 생성 20개의 HTTP 요청 시간 합계는 2,739.63초(약 45.7분), 중앙값은 134.07초, 범위는 90.78~165.31초였다. 추가 두 요청은 296.05초였다. 모델 준비·색인·질의 임베딩·preflight·초기 실패·사용자 중단 시간을 포함하지 않는다. 검색 시간도 사전 계산한 질의 임베딩과 인덱스 로드를 제외한다. 실시간 서비스 성능으로 발표하지 않는다.

초기 1.5B 시행, 4B 긴 문맥의 시간 초과, 사용자 중단·재개도 보존했다. 긴 지연의 원인을 로그만으로 CPU·메모리·연결 문제 중 하나로 단정하지 않는다. 생성 서버는 작업 종료 시 중지해 자원을 반환한다.

## 다음 단계

실행 경로는 연결됐지만, 현 설정을 그대로 300문항의 최종 신뢰성 평가에 확대하기에는 답변 품질 문제가 남아 있다. 다음 순서가 필요하다.

1. 사람이 검토표를 확인하고 필수 설명 누락·잘못된 주장·인용 오류를 구분해 승인한다. 실제 답변이 준비됐으므로 이후 해당 답변의 span 라벨링을 시작할 수 있다. 이번에는 라벨링하지 않았다.
2. VAT·마진은 구조화된 입력과 Decimal 계산으로 검증하고 필드별 VAT 기준을 명시한다. 일부 품목을 전체 합계로 취급하지 않도록 한다. 원본 회사 사실을 바꾸는 방식으로 해결하지 않는다.
3. 서비스/회사 보유 주체, missing/합성 가정, 인용 번호와 주장의 일치 여부를 개선한다. 변경된 실적 entity의 과거 금액 등 추가 근거를 명시적인 역사 버전으로 가져오는 기능도 보완한다.
4. 사용 불가 첨부와 토큰 제한으로 빠지는 참조 레코드를 점검한 뒤 같은 개발 문항으로 수정 영향을 확인한다. 독립 평가 분할을 새로 보존하고 300문항 실행 범위를 정한다.

재현은 [README](README.md)를 따른다. 원문·모델·벡터·API 키는 비커밋 work 경로에 있으며 공개 UI 폴더에 복사하지 않았다. 원시 실행 결과는 수정하지 않고 평가 선택표로 최신 버전을 연결한다.
