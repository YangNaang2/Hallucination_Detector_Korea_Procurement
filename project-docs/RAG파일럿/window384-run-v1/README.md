# W384 신규 300 Q·A·R 실행 결과

기준 시점: 2026-09-22 KST  
실행 ID: `window384-gpu-v1`  
코드 기준: `6775cd2e0abddea1ff6ae770152a82a8e411570b`

## 결론

Parent 1,800자 아래 embedding window를 384토큰, stride를 344토큰으로 바꾼 색인을 사용해 고정된 300문항 전체를 다시 실행했다. Qwen3-4B Q4_K_M 생성은 NVIDIA RTX A5000의 Vulkan backend에서 수행했다.

최종 상태는 생성 295건, 정책에 따른 정상 접근 차단 5건이다. 최초 실행 중 HTTP 500이 발생한 `ASTRA-300-C05-N14-E2` 한 건은 같은 모델·설정으로 재시도해 성공했고, 실패와 성공 시도 모두 보존했다. 결과를 보고 문항을 제외하거나 좋은 답변만 선택하지 않았다.

이 실행은 W384 파이프라인의 작동과 출처 연결을 확인한다. 새 답변의 내용 검수, 환각 구절 라벨, 사람 최종 승인은 진행 중이므로 **답변 정확도 또는 환각 탐지 성능으로 발표하면 안 된다.**

호출 시간 합계는 네 슬롯이 동시에 실행된 요청 시간을 더한 값이라 실제 경과 시간과 다르다. 모델 적재, 색인 적재, 사전 계산된 질의 embedding 시간은 포함하지 않는다. 실행 당시 peak VRAM은 별도로 계측하지 않아 보고하지 않는다.

잘못된 인용번호가 확인된 문항은 다음 두 건이다. 답변 정본은 사후 수정하지 않았다.

- `ASTRA-300-C01-N29-E3`
- `ASTRA-300-C02-N41-E2`

## W460과 비교할 때 주의할 점

동일한 300문항에서 W460 정본과 비교하면 top-6 순서가 279건, 생성에 우선 사용되는 top-4 순서가 234건 달라졌고 답변 문자열은 283건 달라졌다. 그러나 생성 temperature가 0.7이므로 답변 차이에는 검색 변경과 확률적 생성 변동이 함께 들어 있다. 이 수치만으로 W384가 답변 품질을 개선했다고 결론 낼 수 없다.

사전 chunk ablation의 292개 offset 평가 가능 문항에서는 다음과 같았다.

| 지표 | W460 | W384 | 변화 |
|---|---:|---:|---:|
| Hit@1 | 49.66% | 50.00% | +0.34%p |
| Hit@6 | 78.42% | 79.79% | +1.37%p |
| MRR@6 | 60.37% | 60.96% | +0.59%p |
| gold 문자 coverage@6 | 70.65% | 72.70% | +2.05%p |

이 ablation은 이미 노출된 292문항의 사후 개발 비교이며 독립 테스트가 아니다. 차이가 작고 불확실성 구간도 겹친다. W384 채택 근거는 제한된 검색 지표의 균형이며, 답변 정확도 개선은 새 답변 검수 후에만 판단한다.

## 남은 평가

1. 새 295개 답변을 실제 W384 근거와 대조해 `correct / partial / incorrect` 잠정 판정을 작성한다.
2. 환각 구절 offset과 오류 유형을 새 답변 기준으로 다시 라벨링한다. W460 구절 라벨을 복사하지 않는다.
3. KLUE 탐지기를 새 답변에 적용하되 모델 예측을 정답 라벨로 사용하지 않는다.
4. 에이전트 조정안과 사람 최종 승인을 분리한다.
5. W460과 W384를 같은 라벨 기준으로 재채점한 뒤에만 답변·환각 품질 변화로 보고한다.

현재 발표 가능한 결론은 “W384 구성으로 300문항 전체의 GPU 재생성과 출처 연결 감사를 완료했다”까지다. W384 답변 정확도와 환각률은 `평가 진행 중`이다.
