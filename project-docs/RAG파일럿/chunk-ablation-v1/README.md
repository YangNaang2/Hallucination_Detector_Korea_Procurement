# 청크 크기 정량 비교 결과

2026-09-22, `experiment/chunk-ablation-v1`. 기존 원천·ACL·lexical+dense RRF와 `multilingual-e5-small`을 고정하고 청크 설정만 비교했다. 생성 모델은 실행하지 않았다.

## 결론

- **Parent 1,800자 구조는 유지할 근거가 생겼다.** 1,200자보다 Hit@6가 높았고, 2,400자는 Hit@6가 0.69%p 높았지만 top4 문맥량이 약 32% 늘고 Hit@1·MRR이 낮아졌다.
- 검색 Window는 현재 460토큰보다 **384토큰이 균형 후보**다. Hit@1 50.00%, MRR@6 60.96%로 가장 높았고 Hit@6도 현재보다 1.37%p 높았다.
- **256토큰은 재현율 우선 후보**다. Hit@6 80.14%로 최고였지만 Window·벡터 수가 현재보다 약 77% 늘었고 MRR은 384보다 낮았다.
- 첫 460토큰만 임베딩하면 Hit@6가 76.03%로 떨어졌다. 긴 Parent를 여러 Window로 빠짐없이 덮는 구조가 실제로 필요했다.
- 차이는 작다. 384토큰은 현재 대비 Hit@6 성공이 7건 늘고 3건 줄어 순증 4건이었다. 95% 신뢰구간도 겹치므로 운영 우위가 확정됐다고 말할 수 없다.

시간은 RTX A5000의 동일 프로세스 내 상대 비교다. 기존 운영 색인은 CPU float32로 약 1,379.6초가 걸렸으므로 이번 GPU 시간과 직접 비교하지 않는다. 모든 비교군은 GPU autocast 조건을 동일하게 적용했다.

## 평가 범위와 제한

- 후보 295건 중 정본 offset이 없는 3건을 제외한 **292건**을 평가했다. 제외 ID와 사유는 `results.json`과 `validation.json`에 있다.
- 자료는 기존 개발·검토 과정에 노출됐다. train/dev/test 이름은 보존했지만 어느 구간도 독립 평가로 주장하지 않는다.
- Gold Hit은 검색 근거 도달률이다. 답변 정확도, 질문 충족도, 환각률을 뜻하지 않는다.
- `parent-1800-w384`를 바로 운영에 교체하지 않는다. 별도 run에서 답변 생성 회귀와 인용·프롬프트 길이·환각 평가를 통과한 뒤 채택한다.

## 발표 답변

> Parent를 임의로 정한 뒤 끝낸 것이 아니라, 같은 292문항에서 작은 청크, 900·1,200·1,800·2,400자 Parent와 256·384·460토큰 Window를 고정 비교했습니다. 1,800자는 1,200자보다 근거 도달률이 높고 2,400자보다 생성 문맥 부담이 작아 균형점으로 남았습니다. Window는 384토큰이 순위 품질과 비용의 균형이 가장 좋았지만, 현재 대비 개선은 292건 중 순증 4건이라 후속 생성 회귀 전에는 확정 우위로 표현하지 않습니다.
