검증 모델을 만드는 이유

1

3
중요 자료일수록 외부 반출이 불가능하다.
안전 지침, 진료 기록, 사내 규정은 외부 서비스로 보낼 수 없다. 내부 장비에서 도는 작은 검증 모델이어야 실제로 도입할 수 있다.

2. 환각의 정의

환각의 정의와 RAG 환각의 구분

일반적인 환각
모델이 배운 지식만으로 답하다가 사실이 아닌 것을 말한다. 존재하지 않는 논문, 틀린 연도, 없는 조항.
RAG 환각 — 이 프로젝트가 다루는 것
문서를 줬는데도 그 문서에 없는 내용을 문서에 있는 것처럼 말한다. 기준이 "세상의 사실"이 아니라 "이 문서"다.
RAG 환각의 두 가지 모양
① 문서에 없는 것을 덧붙인다
문서가 말하지 않은 조건·예외·수치를 만들어 낸다
② 문서와 어긋나게 말한다
문서의 단어를 쓰면서 관계나 숫자를 틀리게 엮는다
실제 사례 — 2024년 캐나다
"유족 할인 요금은 항공권 발권 후 90일 이내에 신청하시면 소급 적용받으실 수 있습니다."
항공사 챗봇의 답변이다. 실제 회사 규정은 정반대였다 — 발권 전에만 신청할 수 있다. 법원은 "챗봇도 회사 웹사이트의 일부"라며 회사의 배상 책임을 인정했다.
캐나다 브리티시컬럼비아 민사재판소 · 2024 BCCRT 149 · 답변은 요약

O·X 는 어떻게 정해지나
문서 전문과 답변을 함께 넣는다. 모델은 답변의 각 단어가 문서의 어느 부분과 맞물리는지 훑은 뒤, "문서로 뒷받침될 확률"을 0~1 사이 숫자로 낸다. 그 값이 기준선을 넘으면 X, 넘지 않으면 O 다.

5. 사용 데이터셋

데이터 한 건의 구조와 학습 입력

데이터 한 건 — 문서·질문·답변이 한 묶음이고, 답변 안에서 지어낸 구간의 글자 위치가 따로 적혀 있다.

과제 QA (검색된 문서로 질문에 답하기) 문서 ... 교내 장학금은 학사경고 시 신청이 제한된다 ... 질문 학사경고를 받으면 장학금 신청이 안 되나요? 답변 교내 장학금은 제한됩니다. 교외 장학금은 가능합니다. 표시 { start: 14, end: 28, type: "근거 없음" }

사람이 답변을 읽으며 글자 단위로 표시해 둔 것이다. 이 형태가 그대로 정답지가 된다.

모델에 넣는 형태 — 셋을 이어 붙이고, 답변 부분에만 정답을 매긴다.

입력 [ 문서 전문 ] [ 질문 ] [ 답변 ] 정답 제외 제외 O O X X X └── 여기만 학습 ──┘
그래서 문서를 갈아 끼울 수 있다
문서는 학습 때도, 쓸 때도 매번 함께 넣는다. 모델이 RAGTruth 문서를 외운 것이 아니라 "문서와 답변을 나란히 놓고 어긋난 곳을 찾는 요령"을 배운 것이다.
그래서 문서 자리에 MSDS 를 끼워 넣으면 그 문서 기준으로 판정한다.
문서 없이 답변만 넣으면 아무것도 판정하지 못한다

6. 데이터 구축 방안

표시를 보존한 번역

번역 품질이 아니라 태그 보존에 집중한다

RAGTruth 는 영어이고 표시가 "몇 번째 글자"로 저장돼 있다. 그냥 번역하면 어순이 바뀌어 표시가 전부 어긋난다. 그래서 표시를 내용에 태그로 붙인 채 통째로 번역한다.

9. 확대 방안

세 가지 방향

1 · 특화 앱
MSDS 안전 도우미 — 화학물질 문서 전용 질의응답. 자주 묻는 질문과 실시간 질문을 나누고, 답변에 형광펜을 그은 뒤 틀린 부분을 누르면 원문 근거가 나란히 열린다.
마지막 단계는 설명을 생성하지 않고 원문을 그대로 발췌한다. 환각을 잡는 도구가 설명을 지어내면 그 설명부터 검증해야 하기 때문이다.
2 · 운영 품질 점검
답변 로그 전량 검사 — 사내에 챗봇을 붙이면 답변이 매일 쌓인다. 그것을 통째로 훑어 주간 환각률과 문제가 잦은 문서를 뽑는다.
작은 모델이라야 가능한 일이다. 큰 모델에게 되묻는 방식은 답변 한 건마다 호출이 한 번 더 필요해 전량 검사가 비용상 불가능하다. 결과는 문서를 고치는 데 쓴다 — 어느 문서가 환각을 부르는지 알 수 있다.
3 · 범용 도구
브라우저 확장 · API — 검증 층은 생성 모델이 무엇이든 그 앞에 그대로 붙는다. 사내 챗봇이나 교육 프로그램에도 연결할 수 있다.
다만 근거 문서를 제시하는 서비스에만 붙는다. 문서 없이 답변만으로는 판정할 수 없다.
