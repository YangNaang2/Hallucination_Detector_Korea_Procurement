# ASTRA 최종발표 발표자 대본

- 권장 발표 시간: 14~16분
- 슬라이드 수: 18장
- 원칙: 화면의 수치만 말하고, 탐지 성능은 평가 완료 전까지 수치로 주장하지 않는다.

## 1. 표지 — 권한에 맞는 근거로 답하고 의심 구절을 표시하는 조달 검토 시스템

안녕하세요. 저희가 만든 ASTRA는 나라장터 공개 공고와 합성 기업 자료를 이용해, 사용자의 권한에 맞는 근거만 검색하고 답변의 의심 구절까지 표시하는 조달 검토 시스템입니다. 오늘은 문제 정의, 데이터 구축, 권한형 RAG, 환각 검증, 실제 시연 순서로 설명하겠습니다. 핵심은 AI가 입찰 여부를 대신 확정하는 것이 아니라, 사람이 근거를 더 빨리 확인하도록 돕는 것입니다.

## 2. 입찰 검토는 문서 한 장을 읽는 일이 아니다

하나의 공고를 검토하려면 공고문, 제안요청서, 과업지시서와 회사의 실적·인력·인증 자료를 함께 봐야 합니다. 기준일과 정정공고도 확인해야 하고, 문서마다 같은 조건을 다르게 표현합니다. 공개 사례에서는 참가 업종 코드가 1468에서 1469로 바뀌고 입찰 일정도 함께 정정됐습니다. 따라서 단순 요약보다 어떤 버전과 어떤 근거를 사용했는지가 중요합니다.

## 3. 검색, 요약, 보안이 따로 움직이면 검토가 끝나지 않는다

키워드 검색은 공고번호와 코드에 강하고, 생성 모델은 긴 문서를 요약하는 데 유용합니다. 접근 통제는 자료 열람 범위를 정합니다. 하지만 세 기능이 분리되어 있으면 담당자는 답을 받은 뒤에도 권한, 최신 버전, 원문 근거를 다시 확인해야 합니다. ASTRA는 이 확인 순서를 하나의 요청 안에 연결했습니다. 이 장은 제품 간 성능 비교가 아니라 업무 흐름의 단절을 설명합니다.

## 4. ASTRA의 목표

질문을 받으면 먼저 신뢰된 세션의 회사, tenant, 역할, 시나리오와 기준일을 확인합니다. 허용된 문서 안에서 키워드와 벡터 검색을 결합하고, 선택한 근거만 로컬 모델에 전달합니다. 생성된 답변에는 규칙 검사와 토큰 분류 탐지기를 적용합니다. 결과는 단순한 가능·불가능 대신 근거, 조건 상태, 자료 부족, 의심 구절을 함께 보여줍니다.

## 5. ASTRA 전체 파이프라인

위쪽은 구축 단계입니다. 공개 공고와 합성 기업 자료를 파싱하고 분류해 223개 문서와 3,275개 청크의 검색 자산을 만들었고, 별도로 평가용 Q-A-R 300건을 구성했습니다. 아래쪽은 운영 단계입니다. 질문과 사용자 조건이 들어오면 권한 필터, 하이브리드 검색, 로컬 생성, 답변 검증을 거쳐 답변·인용·근거·의심 구절을 반환합니다. 이후 장에서 각 구간을 확대하겠습니다.

## 6. 사용자 질의 파이프라인

사용자는 공고와 회사를 선택하고 질문합니다. 서버는 세션을 확인한 뒤 허용 문서만 검색 후보로 남깁니다. 그 안에서 근거를 찾고 로컬 모델로 답변과 인용을 생성합니다. 마지막으로 규칙과 탐지기를 적용해 근거와 의심 구절을 표시합니다. 브라우저에서 역할 이름을 바꾸는 것만으로는 권한이 확장되지 않도록 서버가 검색 범위를 결정합니다.

## 7. 4~6월 수집에서 51건 검수 표본까지

4월부터 6월까지 수집한 공고 행은 차수를 포함해 137,745건입니다. 첨부는 285,252개였고, 파이프라인에서 사용할 수 있다고 판정한 문서는 246,797개였습니다. 완전 공고는 용역 28,852건, 물품 14,145건, 공사 8,082건입니다. 이 가운데 정보시스템 구축·운영 분야에서 월별 17건씩 총 51건을 표본으로 선정했습니다. 읽을 수 없는 파일은 성공으로 세지 않고 별도로 남겼습니다.

## 8. L1·L2·L3는 자료의 성격을 구분한다

L1은 실제 나라장터 공개 공고와 공개 첨부입니다. L2는 가상 기업 5곳의 실적·인력·인증 자료이며, L3는 같은 가상 기업의 원가·마진·투찰 검토 자료입니다. L2와 L3는 실제 기업 기밀이 아닌 합성 설정입니다. 보안 등급은 문서의 성격을 나타내고, 권한 필터는 누가 어떤 자료를 검색할 수 있는지 결정합니다.

## 9. 300개 Q-A-R은 검색 코퍼스가 아니라 평가 기준이다

51건에서 참가자격, 실적, 인력, 인증, 일정, 금액, 공동수급 조건을 추출하고, 서로 다른 제약을 가진 합성 기업 5곳을 설계했습니다. 회사당 60문항씩 300개의 질문·기대답·근거를 만들었습니다. 워크스테이션 실행에는 생성 답변 295건과 정상 접근 차단 5건이 있습니다. 25문항의 팀원 검수는 접수됐지만 최종 사람 승인과 학습용 내보내기는 아직 완료되지 않았습니다.

## 10. 권한 필터는 검색 전에 문서 후보를 제한한다

viewer는 L1만, bid analyst는 해당 회사의 L2까지, cost analyst와 bid approver는 허용된 시나리오의 L3까지 접근합니다. 로그인 상태, 멤버십, tenant, 회사, 역할, 시나리오를 함께 검사합니다. 전역 검색 후 결과를 숨기는 것이 아니라, 허용된 문서만 남긴 뒤 검색 점수를 계산합니다. 다만 이것은 파일럿 정책 구현이며 운영용 인증·인가 시스템과의 연결은 후속 과제입니다.

## 11. 정확한 용어와 의미가 비슷한 표현을 함께 찾는다

키워드 검색은 한국어 2글자 부분어와 영문·숫자 토큰을 이용해 코드, 금액, 날짜에 대응합니다. 벡터 검색은 multilingual-e5-small로 표현이 달라도 의미가 가까운 청크를 찾습니다. 두 검색 순위는 RRF, k 60으로 결합하고 상위 부모 청크를 최대 6개 선정합니다. 생성에는 우선 최대 4개 근거를 사용합니다. 현재 구현은 권한형 하이브리드 RAG이며 별도 그래프 DB 기반 GraphRAG로 부르지 않습니다.

## 12. 생성 모델에는 실제 선택 근거만 전달한다

로컬 생성 모델 입력에는 시스템 정책, 사용자 질문, 인용 가능한 근거 원문, 회사·공고·시나리오 정보가 들어갑니다. Qwen3-4B Q4_K_M GGUF를 로컬 GPU에서 실행했고 외부 API는 사용하지 않았습니다. 정본 실행 결과는 295건이며 권한상 허용되지 않은 5건은 모델 호출 전에 정상 차단했습니다. 생성 결과 중 잘림 4건과 인용 번호 오류 1건은 품질 문제로 따로 기록했습니다.

## 13. 환각 탐지는 답변과 실제 생성 근거를 직접 비교한다

답변은 먼저 근거가 지지하는 구간과 그렇지 않은 구간을 구분할 수 있도록 window와 토큰으로 정렬합니다. KLUE, XLM-R, BGE-M3 후보를 같은 입력 계약으로 비교하는 구조를 만들었고, 금액·부가세·날짜·자격·FTE 같은 항목은 규칙으로 직접 대조합니다. 출력은 문자 오프셋으로 의심 구절을 표시합니다. 모델이 의심 구절을 표시하는 것과 사람이 최종 오류로 승인하는 것은 별개입니다.

## 14. 나라장터 도메인 모델 비교는 평가 진행 중

세 후보 모두 입력·출력 파이프라인은 연결됐지만, 295답변 전체의 비교 평가는 아직 완료되지 않았습니다. 따라서 이 발표에서는 정밀도, 재현율, F1을 만들지 않습니다. 체크포인트, 실제 생성 근거, 사람 승인 라벨을 고정한 뒤 같은 분할과 threshold에서 비교해야 합니다. 성능 수치가 확정되기 전까지 세 모델의 우열은 미확정입니다.

## 15. 오류는 결론, 근거, 인용 위치에서 각각 발생한다

첫 사례는 근거가 서울·경기, 인천 포함이라고 했는데 답변이 인천을 제외해도 된다고 말한 모순입니다. 두 번째는 다른 인력 값을 재사용해 잔여 FTE가 0이라고 단정한 근거 없음 사례입니다. 세 번째는 실제 프롬프트에 [1], [2]만 있는데 [3]을 인용한 오류입니다. 이 사례들은 25문항 검수에서 나온 에이전트 조정안이며 최종 사람 승인은 아직 pending입니다.

## 16. 통합 평가는 검색, 생성, 탐지를 따로 보고한다

검색은 223문서와 3,275청크의 권한·해시·재현성을 확인했습니다. 생성은 295답변과 정상 차단 5건을 보존했습니다. 사람 라벨은 25문항 검수를 접수했지만 최종 승인이 남아 있습니다. 환각 탐지는 세 모델, 295답변, 885슬롯의 실행 구조를 갖췄고 평가는 진행 중입니다. 자동 검사 통과와 사람 승인 완료, 탐지 성능 확정은 서로 다른 상태로 보고합니다.

## 17. 라이브 데모는 실행 모드를 먼저 밝힌다

데모에서는 지도에서 공고를 선택하고 자연어 질문을 입력한 뒤, 답변·출처·근거를 확인합니다. 마지막으로 환각 의심 구절을 함께 봅니다. 저장 예제 모드는 재현성을 위한 화면이고, L1 테스트는 실제 생성 서버를 사용합니다. L2·L3 자유 질문은 아직 Live DB와 완전히 연결되지 않았으므로 화면에서 모드를 구분해 설명합니다.

## 18. 구현 자산은 남았고, 성능 검증은 계속된다

저희는 3개월 수집·파싱·변환 파이프라인, 51건 표본과 가상 기업 5곳, 223문서·3,275청크 색인, 평가 300문항과 생성 295답변을 남겼습니다. 남은 과제는 295답변 전체 탐지 평가, 사람 승인 라벨 고정, 운영 인증·인가 연결, L2·L3 자유 질문과 Live DB 연결입니다. 결론은 AI가 대신 확정하는 시스템보다, 사람이 근거를 더 빨리 확인하는 시스템을 만들었다는 것입니다.
