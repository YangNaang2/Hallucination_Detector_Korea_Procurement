# ASTRA 최종발표 내용 확장 초안 v2 · 발표 메모 초안

- 본문 30장 + 부록 3장
- 팀에서 발표 순서·문구·시간에 맞게 수정하기 위한 슬라이드별 핵심 설명 초안

## 1. 표지

ASTRA는 입찰 여부를 대신 확정하는 시스템이 아니라, 담당자가 권한에 맞는 자료에서 근거를 찾고 답변의 오류 가능성을 빠르게 확인하도록 돕는 시스템입니다. 데이터 수집부터 평가용 질문, 검색, 로컬 생성, 환각 검증까지 실제 구축한 범위와 아직 검증 중인 범위를 나눠 설명하겠습니다.

- 근거: project-docs/PPT_최종발표_제작_인수인계_프롬프트.md
- 표현 제한: 탐지 성능 우수 또는 운영 완성을 주장하지 않음

## 2. 프로젝트 결과 요약

먼저 완료 범위를 숫자로 보겠습니다. 3개월 공고 137,745행과 첨부 285,252개를 처리했고, 51건 표본을 원문 대조했습니다. 검색용 자산은 223문서와 3,275청크, 평가용 자산은 300문항입니다. 실제 생성 답변은 295건이고 5건은 권한 정책에 따라 모델 호출 전에 차단했습니다. 탐지 성능은 아직 최종값으로 발표하지 않습니다.

- 근거: project-docs/데이터현황/3개월_통합현황.md; project-docs/RAG파일럿/workstation-275/index_manifest.json; project-docs/평가데이터/v2/validation/report.json; project-docs/RAG파일럿/workstation-275/evaluation/final_summary.json
- 표현 제한: 탐지 성능은 평가 진행 중

## 3. 발표 흐름

발표는 여섯 부분입니다. 먼저 조달 문서가 왜 단순 검색으로 끝나지 않는지 설명합니다. 이어 데이터 수집과 원문 검수, 평가 데이터 설계를 보고, 권한 필터와 하이브리드 RAG, 로컬 생성과 탐지 흐름을 설명합니다. 마지막에는 실제 화면과 남은 검증 과제를 보여드리겠습니다.

- 근거: project-docs/PPT_최종발표_제작_인수인계_프롬프트.md
- 표현 제한: 구조 안내

## 4. 조달 검토의 복잡성

조달 검토의 어려움은 문서 수만 많아서가 아닙니다. 정정공고로 조건이 바뀌고, 같은 사업에서도 공고문과 제안요청서의 범위가 다를 수 있습니다. 회사 실적과 인력 자료는 공개 공고와 접근 권한이 다르고, 모델은 근거를 받더라도 숫자나 예외를 잘못 바꿀 수 있습니다. ASTRA는 이 네 문제를 한 흐름에서 다룹니다.

- 근거: project-docs/나라장터_문제정의_1차리서치_팀원용.md; project-docs/표본_정보시스템/검수/재확인_원문대조_결과.md
- 표현 제한: 자동 적격 판정이나 분쟁 해결을 주장하지 않음

## 5. 공식 사례와 원문 충돌

왼쪽은 평가 방법을 더 명확히 제공하라는 공식 의결문 발췌입니다. 오른쪽은 팀의 원문대조 사례입니다. 경민대는 공고와 RFP의 1억 6천5백만원과 수집 메타데이터의 1억 8천1백5십만원을 분리했습니다. 동아보건대 마감과 천안 사업기간도 두 값이 실제 원문에 병존했습니다. 이 경우 ASTRA의 정답은 임의의 단일값이 아니라 출처별 값과 보류 사유입니다.

- 근거: presentations/week3/source/acrc_order_excerpt.png; project-docs/표본_정보시스템/검수/재확인_원문대조_결과.md

다섯 회사는 모두 다른 제약을 갖습니다. 한빛IT는 정보통신공사업 0036을 보유하지 않고, 해온시스템은 직접생산 인증 만료와 기술지원 확약서 부족이 있습니다. 인우블록은 실적 증빙, 누리클라우드는 서비스 CSAP와 공급권한, 새온에너지SW는 장비 견적이 부족합니다. 이런 제약을 유지해야 정상 통과 사례뿐 아니라 미충족과 자료부족도 평가할 수 있습니다.

- 근거: project-docs/가상기업/v1/company_master.json; project-docs/가상기업/v1/generated/C01/r1/README.md; project-docs/가상기업/v1/generated/C02-C05/r1/README.md

- 근거: project-docs/평가데이터/v2/validation/report.json

사용자는 공고와 회사를 선택하고 질문합니다. 서버는 세션의 tenant, 회사, 역할과 시나리오를 확인하고, 허용 문서 ID만 남깁니다. 그 안에서 키워드와 벡터 검색을 결합하고 최대 4개 근거로 로컬 답변을 생성합니다. 마지막으로 규칙과 탐지를 수행해 답변과 근거, 의심 구절을 표시합니다.

- 근거: procurement-pipeline/rag_pilot.py; project-docs/데모개선/2026-09-15/local-integration/README.md

## 17. 역할별 접근 정책

viewer는 공개 L1만, bid analyst는 자기 회사 L2까지, cost analyst와 bid approver는 허용된 L3까지 접근합니다. 역할만 확인하지 않고 로그인, 멤버십, tenant, 회사, 시나리오와 기준일을 함께 검사합니다. 평가 중 5건은 이 정책에 따라 모델 호출 전에 정상 차단했습니다.

## 18. 검색 전 ACL 강제

ACL은 검색 결과를 만든 후 숨기는 것이 아니라, 허용 문서 집합을 먼저 만든 뒤 그 안에서 점수를 계산합니다. 답변 인용과 문서 열람에도 같은 정책을 사용합니다. 가상기업 접근 규칙 20건, C01 메타데이터 규칙 189건을 검사했고, 데모 오류 주입에서도 타회사 문서와 L2 혼입을 거부했습니다. 다만 이는 실서비스 침투 테스트가 아닙니다.

- 근거: project-docs/가상기업/v1/validation_report.json; project-docs/가상기업/v1/generated/C01/r1/README.md; project-docs/데모개선/2026-09-14/README.md
- 표현 제한: 오프라인·파일럿 검사와 운영 보안 검증을 구분

## 19. 정본·청크·offset

색인은 문서 ID와 버전, SHA-256을 보존합니다. parent chunk는 최대 1,800자, overlap 240자이며, 문자 위치는 Unicode code point의 시작 포함·끝 제외 규칙입니다. 16개 문서는 사용할 수 있는 텍스트가 없어 제외 사유를 남겼습니다. 생성과 탐지에는 실제 생성 당시 선택된 동일 근거를 사용합니다.

- 근거: project-docs/RAG파일럿/workstation-275/index_manifest.json; project-docs/환각라벨링/detector-300-workstation-v1/README.md
- 표현 제한: 로컬 실험 색인, production index 아님

## 20. 임베딩 구축

3,275개 parent 청크를 460토큰 window와 420토큰 stride로 나눠 7,195개 임베딩을 만들었습니다. multilingual-e5-small 384차원 벡터를 L2 정규화하고, 같은 parent의 window 중 최대 유사도를 parent 점수로 사용합니다. 구축은 CPU float32, 배치 8, 스레드 4로 1,379.6초가 걸렸습니다.

- 근거: project-docs/RAG파일럿/workstation-275/embedding_config.json; project-docs/RAG파일럿/workstation-275/validation/vector_validation.json
- 표현 제한: 임베딩 구축 시간은 해당 워크스테이션 1회 기록

## 21. 하이브리드 검색

키워드 검색은 코드, 금액, 날짜처럼 정확한 표현에 강합니다. 벡터 검색은 같은 의미의 다른 표현을 보완합니다. 두 검색의 원점수를 직접 섞지 않고 RRF k 60으로 순위를 결합합니다. 상위 parent를 최대 6개 선정하고, 생성에는 우선 최대 4개를 전달합니다.

- 근거: procurement-pipeline/rag_pilot.py; project-docs/평가데이터/v2/retrieval_manifest.json
- 표현 제한: 별도 그래프 DB 기반 GraphRAG 아님

## 22. 로컬 GPU 생성

생성 모델은 Qwen3-4B GGUF Q4_K_M입니다. context 4,096, 최대 출력 768토큰, 근거 최대 4개를 사용했습니다. 워크스테이션에서는 Vulkan으로 RTX A5000에 37개 레이어를 모두 offload했고, 기록된 peak GPU memory는 5,588 MiB입니다. 외부 API는 사용하지 않았으며 모델 파일 해시와 프로필을 기록했습니다.

- 근거: project-docs/RAG파일럿/workstation-275/environment.json; project-docs/RAG파일럿/workstation-275/validation/runtime_tuning.json
- 표현 제한: GPU 수치는 해당 워크스테이션 실행 기록

## 24. 환각 탐지 설계

- 근거: project-docs/환각라벨링/detector-300-workstation-v1/README.md; procurement-pipeline/detector300*.py
