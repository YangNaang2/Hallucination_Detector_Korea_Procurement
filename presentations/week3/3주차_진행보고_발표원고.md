# B1조 3주차 진행 보고 — 나라장터 적용과 데이터 준비

작성: 2026-09-13. 별도 표지 없이 나라장터 선택 이유에서 시작하는 8장 PPT 원고다. 현재 진행 단계에 집중하고 2주차 연구·실험 설명, 비공개 공간 시연, 성능 지표표는 반복하지 않는다. 각 장의 아래 내용은 PPT 발표자 노트에도 포함한다.

사실 구분: 수집·분야·표본 수치는 저장소의 보고서·CSV를 재집계했다. 요건 CSV 제작, 질문·기대 정답·근거 300건 완료, 가상 기업 준비는 사용자의 최신 진행 현황 확인을 반영했다. 완성된 CSV·질문·기업 파일을 이번 작업에서 독립적으로 검수한 것은 아니다. 기업 수량·기업명·실적값은 제시하지 않는다. 가상 기업 구성 완료를 모든 L2/L3 상세 문서·실제 인가·서비스 통합 완료로 확대하지 않는다.

## 슬라이드 1. 환각 탐지의 적용 무대를 나라장터로 넓혔다

### 핵심 메시지

모델을 실제 입찰 검토에 적용하면서 공고 조건·회사 증빙·접근 권한을 함께 다룬다.

### 화면 본문

- 출발점: 문서를 보고도 틀리는 한국어 답변의 의심 구절 탐지
- 확장 업무: 공개 공고 조건과 회사 증빙 대조
- 선정 이유: 공개 자료 확보, 실적·인력·인증 비교, 비공개 자료 접근 통제
- 목표: 허용된 자료로 입찰 조건을 검토하고 의심 구간을 원문에서 확인

### 레이아웃

첫 페이지 자체가 주제 소개다. 기존 모델 개발을 왼쪽, 확장한 입찰 업무를 오른쪽에 배치한다. 하단에 이번 프로젝트 목표를 한 문장으로 강조한다. 별도 표지·MSDS 역사·선행연구 성능 차트를 추가하지 않는다.

### 발표 대본

이번 주에는 한국어 환각 탐지 모델의 적용 무대를 나라장터 입찰 검토로 넓혔습니다. 공고에는 실적과 인력, 인증 같은 조건이 있고, 회사에는 이를 대조할 증빙이 있습니다. 공개 공고를 확보할 수 있고 판단에 필요한 조건을 구조화하기에도 적합했습니다. 여기에 비공개 회사 자료가 들어오면서 어떤 자료를 볼 수 있는지까지 다뤄야 합니다. 저희는 허용된 자료로 답하고 의심 구간을 원문에서 확인하도록 돕는 입찰 검토 시스템을 목표로 삼았습니다.

### 근거·표현 범위

팀공유 문서의 정보시스템 구축·운영 분야 결정, 요건 추출 작성 요령, Live RAG 전환 설계. 프로젝트 목표는 입찰 검토 보조이며 자동 적격 판정·분쟁 예방 성과가 아니다.

## 슬라이드 2. 새로운 문제: 조건·버전·기밀을 함께 다뤄야 한다

### 핵심 메시지

조건을 요약하는 기능에 더해 버전 확인·자료 보호·답변 검증이 필요하다.

### 화면 본문

| 박스 | 짧은 내용 | 도출한 설계 과제 |
|---|---|---|
| 입찰 취소 분쟁 | 제출 조건·사실 관계를 검토해 권익위가 입찰 절차 진행을 시정권고 | 조건 대조 |
| 모호한 평가 기준 | 적격심사 방법을 구체적으로 제공하라는 권익위 의견표명 | 근거 확인 |
| 같은 공고도 바뀐다 | 참가 업종 1468에서 1469로 정정, 일정 변경 안내 | 버전 관리 |
| 외부 전송의 위험 | 내부 코드 입력 사고 이후 삼성전자 생성형 AI 사용 제한 보도 | 처리 경계 |
| 민감정보 보호 | 정부 AI보안 안내에서 기밀 유출 등 보안 위협 대응 강조 | 권한 통제 |
| 근거가 있어도 오답 | 다른 물질 질문에 제공된 자료를 적용한 이전 MSDS 사례 | 답변 검증 |

### 레이아웃

3열×2행, 6개 박스로 구성한다. 각 박스는 설계 과제 한 단어, 제목, 설명 두 줄, 짧은 출처만 담는다. 실제 조달 사례 세 개를 위쪽에, 외부 전송·보안·답변 문제를 아래쪽에 둔다. 일반적인 회사 사진 대신 읽을 수 있는 짧은 근거 설명을 우선한다. 이미지가 없어도 사례와 기능의 연결이 명확하도록 표제를 강조한다.

### 발표 대본

이 업무에서는 여러 종류의 문제가 함께 나타납니다. 실제 의결 사례에는 제출 조건과 제출 사실 때문에 입찰 취소를 다툰 경우가 있고, 평가 방법을 더 명확하게 알리라는 의견도 있습니다. 같은 공고의 참가 업종과 일정이 정정되기도 합니다. 회사 자료를 사용하면 외부 전송과 민감정보 보호 문제도 생깁니다. 그리고 문서를 제공한 답변에도 근거 사용 오류가 남을 수 있습니다. 저희는 이 문제들을 조건 대조, 버전 관리, 권한 통제와 답변 검증이라는 요구사항으로 정리했습니다.

## 슬라이드 3. 데이터 준비와 실제 서비스 연결을 하나의 흐름으로 설계

### 핵심 메시지

완료된 준비 작업을 실제 권한 검색·답변 생성·원문 검토로 연결하는 구조다.

### 화면 본문

- 데이터 준비: 공고 수집·파싱 → 표본·요건 CSV → 검수 질문·가상 기업
- 실제 서비스 연결 예정: 권한 검색 → 로컬 답변 생성 → 환각·규칙 검증 → ASTRA 원문 검토
- 검색 자료: 공고 원문 + 합성 기업 L2/L3
- 질문·정답표는 검색 DB와 분리
- L1 공개·L2 내부·L3 민감은 사내 문서 분류 예시

### 레이아웃

사용자 제공 전체 구조도의 데이터 준비·서비스 구역을 두 가로 흐름으로 간추려 편집 가능한 도형과 화살표로 재구성한다. 위쪽은 파란 배경으로 준비한 자료, 아래쪽은 밝은 배경으로 실제 연결 예정 기능을 표시한다. 원본 구조도의 성능 숫자와 상세 노드 이름은 생략한다.

### 발표 대본

새 파이프라인은 자료를 준비하는 흐름과 실제 질문을 처리하는 흐름으로 나눴습니다. 위쪽에서 공고를 수집하고 파싱한 뒤 표본과 요건 시트를 만들고, 이를 질문과 가상 기업 준비에 활용합니다. 아래쪽에서는 사용자의 권한을 확인한 자료를 검색하고 로컬 모델이 답변을 만든 뒤 환각과 수치 조건을 검토합니다. 지금은 위쪽의 데이터와 검수 자산 준비를 진행한 상태이고, 아래쪽의 실제 서비스 연결이 다음 단계입니다. 질문의 정답표를 검색 DB에 넣어 정답을 찾아오게 하지는 않습니다.

### 근거·기술 보충

팀공유 문서, 첨부 프로젝트 구조도, Live RAG 설계. 검색용 원본 BGE-M3와 학습한 환각 탐지기는 분리한다. 실제 인가는 회사·프로젝트·문서별 승인 조건을 서버에서 확인해야 하며 개인 등급 비교만으로 구현하지 않는다. L1~L3는 국가 비밀취급인가 등급이 아니다. 숫자 규칙은 탐지 모델의 판정에만 의존하는 후처리가 아니라 원문과 답변을 대조하는 별도 검증이다. GraphRAG 관계 검색은 후속 확장이다.

## 슬라이드 4. 4~6월 공고 수집·파싱·변환 단계를 마쳤다

### 핵심 메시지

세 달 공고를 모아 원본·파싱 텍스트·어댑터 입력·집계로 연결했다.

### 화면 본문

- 파싱 처리와 별개로 실패·품질 미달 자료 구분 관리

### 레이아웃

왼쪽에 수집 공고 행의 큰 숫자와 월별 표, 오른쪽에 최신 차수와 사용 가능 첨부 수를 배치한다. “100% 파싱 성공” 배지나 처리 단계별 분모가 다른 숫자를 하나의 성공률로 만든 그래프는 넣지 않는다.

### 발표 대본

우선 4월부터 6월까지 공고 수집과 파싱, 변환 단계를 마쳤습니다. 차수를 포함하면 137,745행이고 최신 차수 기준으로는 124,522건입니다. 수집한 원본과 파싱 텍스트를 보관하고, 어댑터를 통해 다음 파이프라인의 입력으로 변환했습니다. 사용 가능한 첨부는 집계 대상 285,252개 중 246,797개입니다. 파싱 단계의 처리를 마쳤다는 표현이 모든 문서가 정상이라는 뜻은 아니며, 실패하거나 품질 기준에 못 미친 자료는 구분해서 관리합니다.

### 출처·검증

## 슬라이드 5. 주요 분야는 정보시스템 구축·운영으로 선정

### 핵심 메시지

문서 가용성과 실제 조건 대조의 적합성을 함께 보고 타깃 분야를 결정했다.

### 화면 본문

| 타깃 분야 | 공고 | 완전 공고 |
|---|---:|---:|
| SW·시스템 개발 | 2,163 | 984 |
| 운영·유지관리 | 1,313 | 681 |
| 합계 | 3,476 | 1,665 |

- 실적·인력·인증을 비교하기 적합
- 기업의 충족·미충족 사례를 설계할 수 있음
- 팀의 IT·SW 이해를 활용해 검수 가능
- 완전 공고 = 공고문 + (RFP 또는 과업·규격서)

### 레이아웃

선정 분야를 큰 제목으로 강조하고 왼쪽에 분야 표, 오른쪽에 선정 이유를 배치한다. 모든 후보 분야를 나열하기보다 선택 결과와 판단 이유를 설명한다.

### 발표 대본

파싱된 자료를 분야별로 집계한 뒤 정보시스템 구축·운영을 주요 주제로 선정했습니다. 이 범위에는 SW·시스템 개발과 운영·유지관리가 포함됩니다. 두 분야의 공고는 3,476건이고, 공고문과 RFP 또는 과업·규격서를 함께 활용할 수 있는 완전 공고는 1,665건입니다. 단순히 완비율이 가장 높아서 고른 것은 아닙니다. 회사의 실적과 인력, 인증을 조건과 대조하기 좋고 팀에서도 문서를 이해하고 검수하기에 적합하다는 점을 고려했습니다.

## 슬라이드 6. 51건을 데모 표본으로 추출하고 요건 CSV를 제작

### 핵심 메시지

### 화면 본문

- SW·시스템 개발 32건 / 운영·유지관리 19건

- 청크는 원문 조각, CSV는 질문·기업 자료 설계에 사용할 기준

### 레이아웃

왼쪽에 51건과 월별·분야별 구성, 오른쪽에 CSV 항목을 용도별로 묶은 편집 가능한 표를 둔다. 실제 완성 CSV가 이번 작업에 제공되지 않았으므로 빈 배포용 CSV를 완성본 스크린샷처럼 쓰지 않는다. 표는 기록 항목과 용도를 설명하는 도식이다.

### 발표 대본

선정 분야에서 데모에 사용할 공고 51건을 따로 추출했습니다. 각 월에서 17건씩이고, 분야별로는 개발 32건과 운영·유지관리 19건입니다. 이 문서들을 원문과 파싱 텍스트로 확인하면서 참가 조건과 근거 위치를 요건 시트에 정리했습니다. CSV는 공고 전체를 다시 옮겨 적거나 원문 청크를 대신하는 파일이 아닙니다. 질문과 정답을 만들고 가상 기업 조건을 설계할 때 같은 기준을 사용하도록 준비한 것입니다. 날짜나 조건이 서로 다른 부분은 근거와 함께 검토 메모에 남깁니다.

## 슬라이드 7. 질문·정답·근거 300건과 입찰용 가상 기업을 준비

### 핵심 메시지

공고의 조건을 실제로 물어볼 질문과 대조할 회사 상황으로 연결했다.

### 화면 본문

- 질문·기대 정답·근거 300건 준비 완료
- 질문할 내용, 기대 답, 확인할 원문 근거 연결
- 입찰용 가상 기업 구성: 실적·인력·인증 등의 회사 조건 마련
- 충족·미충족·자료 부족 상황을 구분하는 검토 기반
- 다음: 실제 답변 생성 → 환각 구간 라벨링 → 교차 검수

### 레이아웃

왼쪽의 큰 300건과 오른쪽의 가상 기업 구성 설명을 같은 무게로 배치한다. 기업명·기업 수·실적값·권한별 질문 비율은 만들지 않는다. 하단에 다음 작업을 연결해 준비 완료와 실제 답변 라벨링 완료를 구분한다.

### 발표 대본

이를 바탕으로 질문과 기대 정답, 근거 300건을 준비했고 입찰에 참여할 가상 기업도 구성했습니다. 질문마다 무엇을 기대하고 어떤 원문으로 확인할지 기준을 마련한 것입니다. 기업은 공고의 실적과 인력, 인증 조건을 대조할 수 있는 상황을 만들기 위한 합성 자료입니다. 이 준비를 실제 답변 생성과 연결한 뒤, 생성된 답변의 환각 구간을 사람이 표시하고 교차 검수할 예정입니다. 따라서 질문 300건 준비 완료와 생성 답변의 구절 라벨링 완료는 서로 다른 단계입니다.

### 근거·표현 범위

질문·기대 정답·근거 완료는 사용자가 명시적으로 확인했다. 가상 기업 준비는 이번 사용자 요청의 최신 진행 현황을 따른다. 실제 질문·기업 파일의 품질이나 세부 구성은 이번 작업에서 독립 검수하지 않았다. 합성 기업의 모든 L2/L3 상세 문서와 서비스용 권한이 완성됐다고 설명하지 않는다. 기존 계획의 기업 5곳을 검증된 완료 수량으로 재사용하지 않는다.

## 슬라이드 8. 다음 단계는 준비한 자료로 실제 답변을 끝까지 연결하는 것

### 핵심 메시지

작은 시나리오부터 연결하고, 300건 실행과 검수로 범위를 넓힌다.

### 화면 본문

1. 자료·버전 연결: 공고·기업·질문 ID 고정, L2/L3 상세 증빙·권한 연결, 개발·평가 자료 분리
2. 답변 생성·검수: 허용 근거로 로컬 답변 생성, span 라벨링·교차 검수, 숫자·기간 대조
3. ASTRA 실연결: 검색·생성·탐지 API, 원문·의심 구간 표시, 승인 전후·타 회사 차단

첫 연결 기준: 실제 공고 1건 + 가상 기업 1곳 + 질문 5개를 사람이 확인

### 레이아웃

세 단계의 제목과 제출물을 가로로 배치한다. 새 확정 날짜를 추가하지 않고 작업 순서와 끝났다고 볼 조건에 집중한다. 하단에 첫 연결 범위를 강조한다. 평가지표표·FPS·F1·성능 목표 숫자 및 비공개 공간 시연은 넣지 않는다.

### 발표 대본

다음에는 준비한 자료를 실제 서비스로 연결하겠습니다. 먼저 공고와 기업, 질문의 ID와 버전을 맞추고 L2/L3 증빙과 권한을 연결합니다. 공고 한 건과 기업 한 곳, 질문 다섯 개부터 끝까지 실행해 사람이 확인한 뒤 범위를 넓히겠습니다. 이후 답변의 환각 구간을 라벨링하고 숫자 조건도 별도로 대조합니다. 마지막으로 ASTRA에서 질문부터 근거와 의심 구간 확인까지 이어지도록 연결하고, 승인 전후와 다른 회사 자료에 대한 접근 차단을 확인하겠습니다.
