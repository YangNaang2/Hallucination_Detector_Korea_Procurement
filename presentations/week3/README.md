## 현재 발표본: 3주차 진행 보고

- [8장 진행 보고 PPT](output/3주차_진행보고_progress-v1.pptx): 별도 표지 없이 나라장터 선택 이유, 6개 문제 박스, 새 파이프라인, 수집·파싱, 분야 선정, 51건·CSV, 질문 300건·가상 기업, 다음 계획 순서다.
- [발표 원고·출처](3주차_진행보고_발표원고.md): 장별 본문·레이아웃·대본과 출처·완료 범위. 같은 내용을 PPT 발표자 노트에 포함했다.
- 생성: 기존 환경변수 설정 후 `source/build_progress.mjs`를 실행한다. 슬라이드 내용은 `source/progress_slides.mjs`에 있다. `DECK_REVISION`은 기존 출력과 겹치지 않게 지정한다.
- 수집·표본 숫자는 원자료 집계 파일과 CSV를 재확인했다. 질문·CSV·가상 기업 준비는 사용자의 최신 완료 확인을 반영한다. 가상 기업 수나 세부 실적은 추정하지 않았다.
- 최종 PPT를 재가져와 8장 전체를 렌더링해 확인했다. 파일 구조·레이아웃 검사에서 오류와 경고가 없었다. 데스크톱 PowerPoint 자체의 렌더링 검증은 수행하지 않았다.

- `source/보안RAG_전체구조_글꼴윤곽.svg`: 한글 깨짐을 막기 위해 글꼴을 벡터 경로로 변환한 PPT 삽입본. 내용 수정은 위 편집 원본에서 한다.
- v4 PPT, 이전 원고, `source/astra_*.png`는 이전 버전 기록이다. 현재 v5에는 공간 시연 이미지와 평가지표 페이지가 없다. 발표에는 v5를 사용한다.

제목과 발표 흐름은 한국어 환각 탐지와 권한 기반 RAG를 중심으로 수정했다. 2페이지는 첨부 추진배경 MD, 3페이지는 수정 SVG, 4페이지는 데이터 왼쪽·모델 오른쪽 배치를 사용한다. 기존 5·6페이지를 제외하고 프로젝트 목표·비취인가와 사내 문서 접근의 구분, 실제 질의 처리 흐름을 보충했다. 마지막 페이지는 담당·기한·제출물·완료 조건을 구체화했다. 모든 변경은 팀공유 문서 7절에 따라 학습 완료와 서비스 통합 예정 상태를 구분한다.

공고 건수는 월별 `adapt_report.json`, 분야 수치는 워크스테이션 통합 `sector_report.csv`, 표본 수는 `표본_목록.csv`를 사용한다. 모델 성능값은 원본 실험 기록이 이 저장소에 없어 본문에 넣지 않았다. 상세 출처는 원고와 각 슬라이드의 발표자 노트에 있다.

Business Review의 밝은 배경·파란 제목·구분선·설명 열을 유지하고, 전체 구조도 페이지에는 사용자 SVG의 두 트랙 디자인을 적용했다. 한국어 텍스트는 맑은 고딕이다. 원본 템플릿과 첨부 파일은 수정하지 않았다.

## 다시 생성하기

Codex의 bundled workspace dependencies와 presentation skill이 있는 환경에서 다음 환경변수를 설정한 뒤 해당 런타임의 Node로 `source/build_week3.mjs`를 실행한다. SVG를 수정했다면 먼저 Windows PowerShell에서 `source/prepare_architecture.ps1`을 실행해 맑은 고딕 글자를 벡터 경로로 변환한다. 새 빌드는 기존 최종본과 겹치지 않는 `DECK_REVISION`을 지정한다.

| 변수 | 값 |
|---|---|
| `RUNTIME_NODE_MODULES` | bundled Node 패키지 디렉터리 |
| `RUNTIME_PYTHON` | bundled Python 실행 파일 |
| `PRESENTATION_SKILL` | presentations `SKILL.md`가 있는 디렉터리 |
| `BUSINESS_REVIEW_TEMPLATE` | 선택 템플릿의 `assets/reference.pptx` 절대 경로 |
| `DECK_REVISION` | 기존 최종본과 겹치지 않는 버전명 |

`.build/`는 렌더링·내부 검증용 임시 폴더로 Git에서 제외한다. 최종 PPTX, 원고와 필요한 생성 자료는 저장소에 커밋한다. 원천 공고 문서, 모델 가중치, 키는 포함하지 않는다.
