# ASTRA 생성 모델 비교 평가 · 담당자 1명

## 전달 내용과 현재 상태

51개 공고의 요건은 project-docs/표본_정보시스템/검수/요건추출시트_51건_통합.csv 한 파일에 51행으로 통합되어 있다. 51개 독립 CSV가 아니다.
질문·기대답·근거 300건은 project-docs/평가데이터/v2/evaluation/questions_300.jsonl이다. 질문 파일의 actual_answer=null은 실행 미실시라는 현재 상태 판정이 아니라 작성 당시 필드다. 실제 과거 결과는 baseline/에서 확인한다.
가상 회사 5곳의 공통 사실·L2/L3 문서·시나리오도 포함했다. 요건시트만으로 회사 비교 질문 300개를 모두 평가할 수 없다.

과거 실행: 답변 295건 + 시스템 차단 5건. 수정 재실행·검색 조건이 혼합되어 새 모델과의 공정한 통제 비교 결과가 아니다. 과거 정답 판정도 에이전트 검토이며 최종 사람 승인과 구분한다.

## 시작 순서

1. 함께 있는 담당자_AI프롬프트.md를 AI에 전달한다.
2. Python 3.10 이상에서 python validate_package.py 실행. 파일 해시·300문항·회사별60·51공고·기존 결과300·51행 검사.
3. metrics.md의 공통 기준과 experiment_plan.json을 읽고 실제 사용 가능한 모델·GPU·라이선스·런타임을 확인한다. 모델명은 후보군일 뿐 실행 가능 확인이 아니다.
4. 동일 검색 컨텍스트를 먼저 동결하고 모델마다 소수 연결 검사 후 전체 평가한다. 접근 차단 질문은 서버 차단으로 따로 보고한다.
5. 모델별 새 run_id 아래에 원본 답변·근거·설정·오류·채점을 저장하고 comparison 결과를 제출한다.

## 포함 / 별도 준비

포함: 300질문·기대답·짧은 근거 인용, 51행 요건시트와 재확인 기록, 합성 회사·시나리오·생성 문서, 기존 답변 참고본과 원 실행 레코드, 검수자4명의 25문항 통합 기록, 기존 RAG 코드, 새 평가 기준·기록 템플릿.
제외: 모델 가중치·원천 HWP/PDF·전체 파싱 캐시·색인 DB·키·가상환경.
실제 RAG 검색 재현은 기존 원천·색인을 별도로 받아야 한다. project-docs/RAG파일럿/v1/SOURCE_TRANSFER.md와 workstation-275/README.md를 참고하고 접근 권한이 없으면 통합 담당자에게 전달을 요청한다. 파일 경로와 해시를 확인하기 전 원천 준비 완료라고 하지 않는다.
원천이 없더라도 공통 채점 코드·결과 스키마·설정·테스트는 작성할 수 있다. 인용만 제공하는 실험은 curated-reference 트랙으로 구분하며 RAG 검색 평가로 부르지 않는다.

## 반환할 것

- 선택 모델의 정확한 ID/revision/양자화/라이선스/런타임과 하드웨어
- 동결 입력 manifest 및 SHA-256, 생성·검색·평가 설정 버전
- 모델별 원본 결과 JSONL, 판정과 근거가 포함된 검토표
- 모델별·유형별·회사별 비교표 및 속도·실패·잘림 통계
- 검증 코드·테스트·재개 절차·남은 문제

results_template.jsonl은 3개 후보군 × 300문항의 빈 실행 슬롯이며 실행 결과가 아니다. baseline은 재사용 참고용이고 새 결과 칸을 채우는 용도가 아니다.
Git을 쓰지 않으면 신규 결과·코드·보고서만 하위 폴더 구조를 유지해 ZIP으로 돌려보낸다. 원천·가중치·키·전체 프롬프트 캐시는 포함하지 않는다. Git 사용 시 별도 브랜치/PR, main 직접 병합 금지.
