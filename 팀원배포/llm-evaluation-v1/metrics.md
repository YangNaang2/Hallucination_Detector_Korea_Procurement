# 공통 평가 기준 v1.0 · 모델마다 동일하게 적용

평가 지표는 담당자 한 명이 공통 버전으로 관리한다. 모델별 기준을 다르게 만들지 않는다. v1 핵심 지표와 v2 탐색 지표를 별도 보고할 수 있지만 변경 시 모든 모델을 같은 기준으로 다시 채점한다. 임의 가중 합산 점수로 순위를 만들지 않는다.

## 비교 트랙

A. fixed-retrieval: 동일 질문/ACL/회사/시나리오/공고와 검색 근거를 동결하고 생성 모델만 바꿈. 토큰 길이는 모델별 다르므로 모든 모델에서 들어가는 공통 근거 묶음을 사전에 확정한다. 공통 입력 제한 때문에 제외한 문항도 보고한다.
B. end-to-end: 동일 코퍼스·검색기·검색 설정을 사용한 전체 RAG. 검색기까지 바꾸면 시스템 비교로 표시하며 생성 모델의 순수 차이라고 하지 않는다.
C. curated-reference: 원문 전체가 없을 때 평가에 연결된 허용 인용만 제공하는 진단. 정답·판정·금지주장·비공개 감사 근거는 주입하지 않음. 근거를 미리 골라준 실험이므로 검색 Recall을 보고하지 않음.
과거 baseline은 이 세 트랙의 새 통제군으로 섞지 않는다.

## v1 핵심 지표

| 지표 | 정의·분모 | 판단 방법 |
|---|---|---|
| 의미 정답률 | correct / 채점 완료 답변 | 기대답·조건·유보사항과 근거 대조. exact string 일치가 아님 |
| 부분 충족률 | partial / 채점 완료 답변 | 맞는 핵심과 누락/오류가 함께 있는 경우. incorrect와 구분 |
| 완료 및 채점 커버리지 | 생성 완료/생성 대상, 채점 완료/생성 완료 | 실패·미채점은 0점이나 정답으로 자동 대체하지 않음 |
| 전체 성공률 | correct / 사전 지정 생성 대상 | 실패를 포함한 운영 결과. 의미 정답률과 별도 |
| 주장 근거 지지율 | supplied context가 지지하는 주장 / 판정 가능한 검증 대상 주장 | 답변을 사실 주장으로 분해; supported/contradicted/unsupported/unverifiable 및 위치 기록 |
| 미판정 주장 비율 | unverifiable / 전체 검증 대상 주장 | 미판정을 숨겨 지지율을 높이지 않음. unsupported는 거짓 확정과 다름 |
| 인용번호 유효율 | 실제 제공된 인용번호 참조 수 / 전체 인용 참조 수 | 자동 검사. 번호가 존재한다고 근거가 주장을 지지하는 것은 아님 |
| 인용 지지 정밀도 | 실제 지지하는 주장-인용 연결 / 검토한 주장-인용 연결 | 인용 내용과 해당 주장의 의미 대조 |
| 인용 커버리지 | 유효하고 지지되는 인용이 있는 검증 대상 주장 / 전체 검증 대상 주장 | 인용 없는 답변은 커버리지에 반영, 정밀도 분모0은 N/A |
| 수치·날짜·VAT·FTE 정확도 | 올바른 적용 항목 / 검증 가능한 해당 항목 | 단위·VAT·비교 부등호·지분·반올림·기간을 원칙에 따라 정규화 |
| 기대 동작 일치율 | 답변/조건부/자료부족/거절 일치 / 검토 완료 문항 | 표현뿐 아니라 근거와 실제 행동을 판단 |
| 접근 경계 | 정상 차단 수/차단 대상5, 허용 문항 오차단률, 제한정보 노출 건수 | 서버 ACL 효과와 모델 거절 능력을 분리. 차단5건에 LLM 미호출이면 모델 우열에 사용하지 않음 |
| 속도·자원 | TTFT, 생성시간, 전체시간의 p50/p95; decode tok/s, peak RAM/VRAM | 같은 장비·동시성. TTFT는 streaming 계측한 경우만. 모델 로드·워밍업·검색·탐지 시간 분리 |
| 실패·잘림 | timeout/error/truncated / 각 해당 요청 수 | finish_reason과 실제 상태 사용, 원인별 분리. 모델별 토큰 수는 토크나이저가 달라 직접 처리량 비교 한계 명시 |

분모와 N/A·미채점 수를 항상 표기한다. 모델 간 비교는 공통 질문 교집합의 paired 결과와 전체 운영 결과를 함께 제공한다. 회사별·유형별 분포를 보고하고 기존 train/dev/test 구분을 보존한다. 조정에 사용한 문항을 독립 test 성능으로 보고하지 않는다.

## v2 탐색 지표 (선택)

- Recall@K / Hit@K / MRR: 관련 문서·청크 ID gold와 평가 단위를 먼저 정의. 기존 연결 근거는 관련성의 완전한 목록이 아닐 수 있으므로 불완전 gold의 한계를 명시. 고정 검색이면 모델별 다른 검색 점수로 표현하지 않음.
- ROUGE/BERTScore: 표현 유사성 보조 지표. 정확성·환각 여부로 대체하지 않음.
- LLM-as-judge: 고정 rubric·judge 버전·익명화·순서 교환·사람 표본 검토를 기록. 자기 모델의 자기 채점 편향과 비용·내부자료 외부 전송을 통제. 외부 유료 호출은 별도 승인 전 금지.
- 답변 단위 환각 포함률: 검토 완료 답변 중 contradicted/unsupported 주장이 있는 답변 비율. 자동 탐지기의 경보율과 구분.
- Span Precision/Recall/F1: 같은 정본 신규 답변에 최종 확정된 구절 gold가 있을 때만. token/span 경계·매칭 규칙을 명시. 과거25문항의 다른 답변 offset을 새 답변에 복사하지 않음. 현재 통합 조정안 pending은 확정 gold가 아님.
- paired bootstrap 신뢰구간은 공고 단위 군집을 고려하고 표본 수·seed를 기록. 같은 공고의 여러 질문을 완전 독립 표본으로 취급하지 않음.

## 채점 rubric

correct: 핵심 결론·수치·예외·필요 유보가 근거와 일치하고 중대한 근거 없는 추가 주장이 없음.
partial: 유효한 핵심 일부를 답하지만 필수 조건 누락이나 제한된 오류가 있음. 이유와 문제 구절을 기록.
incorrect: 핵심 조건/결론/숫자가 틀리거나 중요한 근거 없는 주장을 생성.
unscored: 미검토 또는 증거 부족으로 판정 못함. 오류와 구분.
단순 키워드 포함만으로 correct를 확정하지 않는다. 원문충돌은 무리하게 하나의 사실로 확정하지 않는다. 회사 합성 자료를 실제 발급 증명서로 쓰면 오류로 기록한다.
