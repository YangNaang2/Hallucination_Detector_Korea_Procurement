# 팀원4 · 반응형·접근성·통합 QA

브랜치: ui/team4-qa. 배포 README의 clone/실행 절차를 먼저 따른다.

- 주 담당 파일: demo-ui/spatial-poc/dist/rag-observatory.css; 별도 QA 기록·테스트 파일
- 목표: 모바일·노트북·포커스·명암·긴 문서 오버플로·재현 가능한 버그 보고
- 확인 항목: 390px/1366px·Tab/Escape·모션 줄이기·모델 미연결·레이아웃
- 기본 실행: python demo-ui/spatial-poc/integrated_server.py --generator disconnected --port 8769
- 내부 검수가 필요하면 Windows start_integrated.ps1 -Review, 또는 env 파일의 로컬 ASTRA_REVIEW_KEY를 사용한다.
- 필수 테스트: test-rag-http.mjs / test-rag-ux.mjs / test-detection-http.mjs. 서버를 수정했다면 test_l1_server.py와 test_integration.py도 실행한다.

완료 기준: 담당 화면의 전후 스크린샷, 실행 방법, 테스트 결과, 미해결 사항을 PR에 적는다. 키·모델·색인·원천 문서·개인 경로를 커밋하지 않는다. 실제 모델이 없으면 저장 재생/테스트 검증이라고 명시한다.

팀원 간 공통 파일 충돌이 예상되면 변경 범위를 먼저 기록하고 작은 PR로 나눈다. 다른 담당자의 파일은 임의로 일괄 포맷하지 않는다. API·보안·정본 offset 규칙은 통합 담당자 검토 없이 바꾸지 않는다. UI 수정으로 저장 답변의 오답을 고치거나 승인 상태를 바꾸지 않는다.

원본 25문항·300문항·회사 마스터·조정안 JSONL은 읽기 전용이다. 새 제안은 별도 메모로 제출한다. 검수 키는 로컬 개발 접근 장치이며 회사 RBAC가 아니다. 공개 dist에 L2/L3나 정답을 추가하지 않는다.
