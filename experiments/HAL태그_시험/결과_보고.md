# `<HAL>` 태그 번역 생존 시험 — 결과 보고

**날짜** 2026-09-01 · **판정: 통과.** 프로젝트 전제가 성립한다.

---

## 1. 이 시험이 무엇인가

우리 프로젝트는 **한국어 구간 라벨을 사람이 만들지 않는다.** 영어 데이터(RAGTruth)의 환각 구간을
`<HAL>...</HAL>` 태그로 감싼 뒤 통째로 번역해서, **라벨이 번역을 따라오게 만든다.**
터키어 팀(Turk-LettuceDetect)이 쓴 트릭이다.

문제는 한국어가 터키어와 다르다는 점이었다. 어순이 달라 구간이 문장 안에서 이동하고,
교착어라 조사·어미가 구간 경계에 달라붙는다. **터키어에서 됐다고 한국어에서 된다는 보장이 없다.**
이 전제가 깨지면 프로젝트 전체를 다시 짜야 하므로, 10건으로 먼저 확인했다.

### 절차
1. RAGTruth 원본을 GitHub에서 직접 받았다 (17,790건).
2. 라벨이 있고 길이가 적당한 응답 중 **QA 4 / Data2txt 3 / Summary 3 = 10건**을 무작위 추출.
3. 환각 구간을 `<HAL>` 태그로 감싸고, "태그 개수를 정확히 유지하라"는 지시와 함께 한국어로 번역.
4. 자동 검사기로 태그 개수·짝·중첩·조사 경계·구간 이동량을 측정.

## 3. 발견한 문제 세 가지 (전부 해결 가능)

### (1) 조사가 구간 밖으로 밀린다 — 유일한 실질 문제

```
영어 : from 11:00 AM to <HAL>10:00 PM</HAL> every day
한국어: 매일 오전 11시부터 <HAL>오후 10시</HAL>까지 영업합니다
                                        ^^^^ 조사가 태그 밖
영어 : offers a <HAL>pleasant atmosphere,</HAL> good service
한국어: <HAL>쾌적한 분위기</HAL>와 좋은 서비스
                            ^ 원문의 쉼표가 조사 '와'로 바뀌며 태그 밖
```

라벨 자체는 틀리지 않았다. 다만 **"어디까지가 환각 구간인가"의 정답이 하나가 아니게 된다.**
`오후 10시`인가 `오후 10시까지`인가. 토큰 단위 학습에서는 이 한 토큰이 곧 손실 계산 대상이다.

> **대응** — 이것을 결함으로 처리하지 말고 **연구 항목으로 승격한다.**
> 세션 24에서 이미 다루기로 한 "한국어 구간 경계 문제(형태소 단위 vs 어절 단위)"가 바로 이것이며,
> **10건 중 1건에서 실제로 재현되었다.** 발표에서 쓸 수 있는 근거가 생겼다.
> 실무적으로는 **어절 단위로 경계를 확장하는 정규화**를 기본값으로 두고, 형태소 단위와 성능을 비교한다.

### (2) 어순이 뒤집혀도 태그는 따라간다 — 걱정했던 것이 문제가 아니었다

```
영어 : the migrants were trying to escape Libya and reach Europe
       <HAL>when they were caught in a storm at sea.</HAL>   ← 문장 끝
한국어: 이주민들은 <HAL>바다에서 폭풍을 만났을 때</HAL> 리비아를 탈출해...  ← 문장 앞
```

구간이 문장 끝에서 앞으로 **완전히 이동했는데도 태그가 내용과 함께 움직였다.**
토큰 라벨링은 절대 위치가 아니라 "이 토큰이 환각인가"만 보므로 **이동은 문제가 되지 않는다.**
로그에 적힌 최대 우려가 해소되었다.

### (3) 원본에 겹치는 구간이 있다 — 번역 전에 병합해야 한다

RAGTruth에는 `607-646`과 `636-653`처럼 **서로 겹치는 라벨**이 존재한다.
그대로 태그를 삽입하면 `<HAL>...<HAL>...</HAL>...</HAL>` 같은 깨진 중첩이 만들어진다.

**전체 데이터 기준 겹침 발생 = 라벨 보유 응답 7,664건 중 115건 (1.5%).**
전처리에서 병합하면 끝난다. 본 시험의 `01_추출.py`에 병합 함수가 이미 들어 있다.

## 4. 파이프라인 설계에 확정된 숫자

| 항목 | 값 |
|---|---|
| 전체 응답 | 17,790건 (train 15,090 / test 2,700) |
| 환각 라벨 보유 | 7,664건 (43.1%) — 나머지는 정상 응답(음성 샘플) |
| task_type | Summary 5,658 / Data2txt 6,198 / QA 5,934 — 고르다 |
| 응답당 구간 수 | 평균 1.86, 최대 14 |
| 응답 길이 | 중앙값 758자, 최대 4,007자 |
| 겹침 병합 필요 | 115건 (1.5%) |

터키어 논문의 학습 17,790 / 테스트 2,700 규모와 정확히 일치한다. **우리도 같은 규모로 간다.**

## 5. 이 시험의 한계 (정직하게)

- **번역기가 다르다.** 이번 시험은 Claude가 번역했고, 실제 파이프라인은 터키어 논문과 같이
  **`gemma-3-27b-it` + vLLM 배치**로 17,790건을 돌린다. 큰 모델은 지시를 잘 따르므로
  **소형·오픈 모델에서 태그 보존율이 떨어질 가능성이 남아 있다.**
- **10건은 작다.** 태그 보존율 100%가 곧 17,790건에서 100%라는 뜻은 아니다.
- 구간이 4개 이상인 긴 응답, 표 형태 Data2txt는 이번 표본에 없었다.

> **다음 검증 (B 파트 1주차)** — 실제 번역 모델로 **200건 배치**를 돌려 태그 보존율을 다시 잰다.
> 여기서 95% 이상이면 그대로 전량 번역, 미만이면 실패 건만 재시도하는 루프를 붙인다.
> **태그가 깨진 건은 버리면 되므로(전체의 소수), 이 방식은 실패해도 프로젝트를 무너뜨리지 않는다.**

## 6. 결론

**전제는 성립한다. 한국어 구간 라벨을 사람이 손으로 만들 필요가 없다.**
프로젝트 최대 리스크였던 라벨링 공수가 제거되었고, 덤으로 **조사 경계 문제라는 연구 소재가
실제 데이터에서 확인**되었다 — 터키어 논문이 다루지 않은 한국어 고유의 문제이므로 그대로 기여가 된다.
