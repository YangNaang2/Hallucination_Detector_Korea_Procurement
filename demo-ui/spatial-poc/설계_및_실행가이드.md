# ORBIT Spatial Procurement — 가상 입찰공고 3D POC

## 먼저 실행하기

Windows에서는 이 폴더의 `실행.bat`를 더블클릭한다. Python 3이 설치되어 있으면 로컬 서버가 켜지고 브라우저가 열린다. 추가 Python 패키지는 없다. 터미널에서 실행하려면:

```powershell
python run_demo.py
```

브라우저 주소를 출력하며, 서버는 `127.0.0.1`의 사용 가능한 포트에만 바인딩한다. 종료는 터미널에서 Ctrl+C. 파일을 바로 여는 것보다 이 실행 방식을 권장한다.

**인터넷과 WebGL이 필요하다.** MapLibre 코드·CSS와 지도·고도 타일은 외부에서 로드한다. 이전 ORBIT HTML과 달리 오프라인 완결 데모가 아니며 폐쇄망 구현물이 아니다. 실패 시 안내를 표시하고 공고·그래프 UI는 남겨 둔다.

### 권장 시연 순서

1. `판교`를 검색하거나 지역 버튼을 누른다.
2. 카메라가 광역 뷰에서 회전하며 위치로 접근하는 것을 본다.
3. 화성·구미로 전환해 위치와 공고·근거 패널이 함께 갱신되는 것을 본다.
4. 오른쪽 `참가 자격`의 분홍 구절을 클릭해 원문을 확인한다.
5. `제출 기한` 정상 예시, `내부 전략`과 L1~L3 전환을 확인한다.
6. `광역 뷰`, `이동 중지`, `3D 지형`, `카메라 연출`을 사용한다.

검색은 내장된 가상 공고 3건의 지역·기관·사업명·ID를 대상으로 한다. 임의의 실제 기업 주소를 지오코딩하는 검색은 아니다.

## 1. 채용공고에서 입찰공고로 바뀐 정보 구조

| 원래 프롬프트 | 입찰공고 POC |
|---|---|
| 채용 기업 | 발주기관, 입찰 참여 회사는 별도로 관리 |
| 근무지 | 사업 수행 위치 또는 납품 장소 |
| 직무·채용 조건 | 과업 범위·참가 자격·평가 조건 |
| 연봉 등 | 사업 예산·기간·제출 기한 |
| 회사–직무–기술 | 발주기관–공고–위치–근거 청크–요구 기술 |

**기관 주소와 사업 수행 위치는 같다고 가정하지 않는다.** 여러 사업장, 전국 범위, 위치 미정 사업은 각각 복수 지점·범위·미확인 상태로 표현해야 한다.

이번 `bids.js`의 판교·화성·구미 좌표는 지형 위의 시연 앵커다. 주소 확인·지오코딩으로 특정 사업장을 검증한 좌표가 아니다. 공고 ID도 실제 나라장터 번호와 구분되는 `DEMO-...` 형식이다.

## 2. 추천 스택과 비교

**이번 POC: MapLibre GL JS 6.9.0 + 기본 HTML/CSS/JavaScript.**

선정 이유는 공개 DEM 지형, 지도 카메라, 웹 UI를 한 화면에서 빠르게 결합할 수 있기 때문이다. 다음 비교는 공식 기능을 바탕으로 한 이 프로젝트 관점의 판단이며, FPS·개발시간을 실제 비교 측정한 결과는 아니다.

| 스택 | 강점 | 추가 고려 | 이 프로젝트에서의 선택 |
|---|---|---|---|
| MapLibre GL JS | 위경도, DEM 지형, 지도 카메라, 웹 HUD 결합 | 건물·고해상도 영상은 별도 데이터. 지형 품질은 DEM 해상도에 좌우됨 | **현재 POC 선택** |
| CesiumJS + 웹 HUD | 지구 규모 좌표계와 지형·3D Tiles, 카메라 제어 | 사용할 지형·영상 공급원과 인증·이용조건 결정 필요 | 실제 시설·건물 3D Tiles까지 확장할 때 우선 검토 |
| Three.js / React Three Fiber | 네온·입자·블룸·자유로운 카메라 연출 | 실제 지형 타일, 좌표계, LOD 등을 직접 연결하거나 지도 엔진과 결합해야 함 | 지도 엔진 위 특수효과·시설 모델에 보조 사용 |
| Unity Web | 게임 수준의 장면·이펙트 제작과 에디터 작업 | 지형 데이터 연동, 웹 빌드·메모리, 웹 패널 브리지 고려 | 기존 Unity 자산·팀 역량이 있을 때 검토 |
| Mapbox GL JS | 웹 지도·지형·카메라·서비스 통합 | 토큰과 이용량·서비스 약관 확인 필요 | 상용 지도 서비스 운영을 선택할 경우 후보 |

React는 장면 연출의 필수 조건이 아니다. 실제 백엔드 연동과 화면 상태가 커질 때 React + TypeScript로 옮겨도 된다. UE5 기반 원격 스트리밍은 별도 서버·GPU·전송 인프라가 필요하므로 이번 빠른 브라우저 POC의 우선순위는 낮다.

공식 참고: [MapLibre 3D Terrain](https://maplibre.org/maplibre-gl-js/docs/examples/3d-terrain/), [Cesium Camera](https://cesium.com/learn/cesiumjs-learn/cesiumjs-camera/), [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html), [Unity Web 브라우저 호환성](https://docs.unity3d.com/6000.0/Documentation/Manual/webgl-browsercompatibility.html), [Mapbox terrain](https://docs.mapbox.com/mapbox-gl-js/example/add-terrain/).

## 3. 실제 지형과 연출을 구분

- 배경 지도: OpenStreetMap raster tiles.
- 지형: AWS 공개 Terrain Tiles의 Terrarium 고도 타일.
- 고도 배율: 1배. 평지가 극적인 산맥처럼 보이도록 높이를 임의로 과장하지 않음.
- 마커: 지도 레이어의 220m 높이 기둥과 지표 X, 위치 라벨. 기둥 높이는 연출값이며 실제 시설 높이가 아님.
- HUD 고도: 로드된 DEM에서 읽은 추정 지표 높이. 실제 측량값·건물 높이·카메라 높이가 아님.
- 야간·붉은 수평선·별빛: 스타일 연출. 현재 시각·실제 날씨와 무관.

판교·화성·구미가 첨부 이미지처럼 거대한 산악 협곡으로 보일 것이라고 보장할 수 없다. **실제 지형 정확성과 판타지 산악 연출은 구분해야 한다.** 해당 장면은 위성사진이나 건물 메시가 아니라 지도 표면과 DEM이다.

지도 저작자 표시는 우측 하단에 유지한다. 공개 타일 서버를 대량 수집하거나 무제한 운영 서비스처럼 사용하지 않는다. 운영 단계에서는 타일 공급자·라이선스·트래픽 조건을 결정한다. [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/), [AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/), [고도 데이터 출처](https://github.com/tilezen/joerd/blob/master/docs/attribution.md).

## 4. 카메라 궤적 구현

`app.js`의 `fly()`와 `leg()`가 담당한다.

**1단계: 광역 이동 → 2단계: 위치 접근·회전**

```javascript
// 개념 예시. 실제 POC에는 중단·재검색 토큰과 이벤트 해제가 포함되어 있다.
await leg({
  center: midpoint,
  zoom: 8.2,
  pitch: 36,
  bearing: targetBearing - 65,
  duration: 1900,
  curve: 1.6
}, token);

await leg({
  center: [lng, lat],
  zoom: 13.8,
  pitch: 68,
  bearing: targetBearing,
  duration: 3100,
  curve: 1.35
}, token);
```

`flyTo`의 비행 경로와 줌 전환에 pitch·bearing을 결합한다. 정확한 미터 단위 물리 궤적이나 3D 베지어 경로를 직접 계산한 구현은 아니다. 가까운 지점은 과도한 줌아웃을 줄인다.

연속 검색 시 이전 이동 이벤트를 해제하고 새 시퀀스를 시작한다. 이동 중지와 지도 드래그를 지원한다. 모션 감소 설정을 감지하면 연출 없이 이동한다. 고도 타일 로딩은 카메라 애니메이션 종료와 별개이므로 로딩 중에는 고도를 확정 표시하지 않는다.

Cesium으로 확장할 경우 `Cartesian3.fromDegrees`로 좌표를 바꾸고 `camera.flyTo`, `flyToBoundingSphere`, `HeadingPitchRange` 또는 지역 ENU 좌표계 기반 사용자 정의 궤적을 검토한다. 지표 샘플링 후 마커를 고정하고, 지역별 경사와 카메라의 지형 충돌을 확인해야 한다.

## 5. 데이터 바인딩과 RAG 연결 구조

```text
공고 파일 + 메타데이터
  → 공고 ID / 차수 / 유효 버전 확정
  → 사업 위치 추출 → 주소 확인 → 위경도 확인
  → 청크 + 문서 위치 + 접근 권한 저장
  → 사용자에게 허용된 공고 검색
  → 공고 선택 이벤트
       ├─ 확인된 사업 위치 → 카메라·앵커
       ├─ 공고 메타 → 좌측 HUD
       └─ 관련 청크·관계 → 우측 그래프
  → 질문 → 허용 문서 검색 → 생성 → 탐지
  → answer span ↔ evidence chunk 연결
```

### 실제 연동 시 권장 레코드

```json
{
  "bidId": "DEMO-PG-001",
  "revision": "demo-01",
  "agencyId": "fictional-agency-01",
  "locations": [{
    "locationId": "site-pg",
    "type": "demo_regional_anchor",
    "coordinates": {"lng": 127.1112, "lat": 37.3947, "alt": null},
    "accuracy": "illustrative",
    "sourceChunkId": null,
    "verified": false
  }],
  "chunks": [{
    "id": "DEMO-PG-001-C01",
    "documentId": "rfp-demo-pg",
    "section": "제4조 참가 자격",
    "page": null,
    "securityLevel": 1,
    "text": "최근 3년 이내 유사 사업 단일 계약 실적 10억 원 이상…"
  }],
  "graph": {
    "nodes": [
      {"id": "DEMO-PG-001", "type": "bid"},
      {"id": "site-pg", "type": "site"},
      {"id": "DEMO-PG-001-C01", "type": "chunk"}
    ],
    "edges": [
      {"from": "DEMO-PG-001", "to": "site-pg", "relation": "demo_location", "verified": false},
      {"from": "DEMO-PG-001", "to": "DEMO-PG-001-C01", "relation": "has_chunk"}
    ]
  }
}
```

실제 문서에서 확인한 위치는 `type: execution_site`처럼 구분하고 출처 청크를 연결한다. 발주기관 주소는 `agency_address`, 납품지는 `delivery_site`로 분리한다. 위치가 없으면 지도 이동을 하지 않고 ‘위치 미확인’을 보여준다. 복수 위치이면 목록 선택 또는 범위 표시를 사용한다.

실제 검색 API는 `GET /bids?q=...`, 문서 상세는 `GET /bids/{id}`, 답변은 `POST /review` 같은 인터페이스로 분리할 수 있다. 이는 설계 예시이며 구현된 서버가 아니다.

답변 응답에는 `answer`, `spans[{start,end,score,evidenceChunkIds}]`, `retrievedChunkIds`, `modelVersion`을 포함한다. 구절 오프셋은 Unicode 코드포인트인지 JavaScript UTF-16 인덱스인지 명시하고 UI에서 변환한다. 신뢰 점수는 보정하지 않았다면 사실일 확률로 설명하지 않는다.

**그래프의 소속 관계와 의미 관계, 답변 지지 관계는 다르다.** `has_chunk`는 문서 소속, `mentions`는 언급, `supports`는 별도 검증이 필요한 관계다. 임베딩이 가깝다는 이유만으로 `supports`를 만들면 안 된다.

이번 POC는 사전 작성된 관계와 답변만 사용한다. 가상 회사는 발주기관과 구분하며, 프런트엔드 등급 전환은 인증이 아니다. 실제 서비스에서는 노드·엣지·원문·검색 결과 모두 서버에서 사용자 권한으로 제한해야 한다.

### 팀원 작업 제안

1. 데이터 담당: 5월 공고 10건에 사업 위치·기관 주소 구분, 원문 근거 추가.
2. 검색 담당: 공고 ID·차수 필터와 접근 권한을 포함해 검색 API 연결.
3. 모델 담당: 생성 답변·검색 문맥을 탐지기로 전달하고 오프셋 반환.
4. UI 담당: POC의 합성 데이터·답변을 API 응답으로 교체하고 연속 검색·지형 로딩 실패·모바일 상태 점검.

완료 기준은 ‘멋진 지도로 움직인다’뿐 아니라 **선택 공고·지도 위치·근거 문서·답변이 같은 대상을 가리키는지**다.
